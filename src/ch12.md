# 第12章 数値計算プログラム

第II部までで、Piet のすべての命令と、白と黒による流れの制御、条件分岐、繰り返し、スタック操作の技法を学びました。第III部では、それらを組み合わせて「ちゃんと役に立つ」プログラムを書いていきます。最初の題材は数値計算です。階乗、フィボナッチ数、最大公約数、べき乗、素数判定といった定番の問題は、どの言語の入門書でも繰り返しの練習に使われます。Piet でも同じです。ただし Piet には変数がないので、**スタックのどこに何を置くか**という設計がプログラムの中心になります。

!!! abstract "この章で学ぶこと"
    - 本書のアセンブラ pasm を使って、制御構造のあるプログラムを効率よく作る方法
    - 擬似コードからスタックの配置計画を立て、Piet の命令列に落とし込む手順
    - 階乗・フィボナッチ数・最大公約数・べき乗・素数判定・桁の和・コラッツ問題の実装
    - 複数の入力でプログラムをテストする方法
    - npiet の整数の扱いと、桁あふれの落とし穴

## 12.1 この部の進め方

### 手で描くか、アセンブラで生成するか

第II部では、ループや分岐を含むプログラムも手で描きました。手で描くと、小さく美しいプログラムになりますが、命令が 30 個を超えるあたりから、色の計算とブロックの配置を誤りなく行うのは大変になります。ほかの言語でいえば、機械語を手で書くのとアセンブリ言語で書くのとの違いに近いものがあります。

そこで第III部では、主に本書付属のアセンブラ **pasm.py**（第2章で紹介しました）を使います。pasm には命令の列とラベル、ジャンプを書きます。画像の配置（色の選び方、ブロックの大きさ、白い通路と黒い曲がり角）はアセンブラが自動で決めてくれます。手で描く技法は第14章と第15章で再び取り上げます。pasm がどのように画像を組み立てるのかは、第17章で詳しく解説します。

### pasm の文法のおさらい

pasm のソースは 1 行に 1 命令を書き、`;` 以降はコメントです。この章で使う命令を表にまとめます。

| pasm の命令 | 意味 |
|---|---|
| `push N` | 整数 N を積む。0、負数、大きな数は自動で計算式に展開される |
| `pop` `add` `sub` `mul` `div` `mod` `not` `gt` `dup` `roll` | 同名の Piet 命令（`gt` は `greater`、`sub` は `subtract`） |
| `inn` `inc` `outn` `outc` | `in(number)` `in(char)` `out(number)` `out(char)` |
| `label:` | ラベル（ジャンプ先の名前） |
| `jmp L` | ラベル L へ無条件にジャンプ |
| `jz L` / `jnz L` | 先頭を取り出し、0 なら / 0 以外なら L へジャンプ |
| `halt` | 停止（プログラムの末尾では省略可） |
| `prints "..."` | 文字列を出力する |
| `swap` | 上の 2 つを入れ替える |
| `pick D` | 深さ D（先頭が 0）の値を複製して先頭に積む |
| `bury D` | 先頭の値を深さ D まで沈める |

`swap`・`pick`・`bury` は**マクロ**で、アセンブラが Piet の命令列に展開します。第11章で学んだ `roll` の使い方そのものです。

| マクロ | 展開後の命令列 |
|---|---|
| `swap` | `push 2` `push 1` `roll` |
| `bury D` | `push D+1` `push 1` `roll` |
| `pick D` | `push D+1` `push D` `roll` `dup` `push D+2` `push 1` `roll` |

たとえば `pick 1` は、`[a b]` を `[a b a]` にします。`push 2` `push 1` `roll` で `a` を先頭に持ってきて（`[b a]`）、`dup` で複製し（`[b a a]`）、`push 3` `push 1` `roll` で 1 つめの `a` を深さ 2 まで沈めます（`[a b a]`）。

条件ジャンプの `jz` と `jnz` も展開されます。`jz L` は `not` `push 3` `mul` `pointer` になります。値が 0 なら `not` で 1、3 倍して 3 になり、`pointer` が DP を時計回りに 3 回（反時計回りに 1 回）回します。右向きに進んでいた流れは上に曲がり、L へ向かう白い通路に入ります。値が 0 以外なら `not` で 0 になり、DP は変わらずに右へ進み続けます。第9章で学んだ「`pointer` による分岐」をアセンブラが自動で組み込んでいるわけです。

### スタックの配置計画

この章のプログラムは、どれも次の手順で作ります。

1. 擬似コードで計算の手順を書く
2. ループの入口でスタックにどの値がどの順で並んでいるかを決める（**スタックの配置計画**）
3. 各命令の後のスタックの状態をコメントに書きながら、pasm のソースを書く
4. 複数の入力でテストする

2 と 3 が Piet らしい部分です。本書では、スタックを `[a b c]`（左が底、右が先頭）と書きます。pasm のソースでは、各行の右側にその命令を実行した**後**のスタックをコメントで書いておきます。ループの入口と出口でスタックの形がそろっていることを確認するのが、バグを防ぐいちばんの近道です。

## 12.2 階乗

最初は階乗です。入力された n について n! = 1 × 2 × … × n を計算します。

### 擬似コードとスタックの配置

```text
n を読む
acc = 1
while n != 0:
    acc = acc * n
    n = n - 1
acc を出力
```

変数は `n` と `acc` の 2 つです。これをスタックに `[n acc]` の順で置くことにします。ループの入口では、いつもこの形になっていなければなりません。

ループの中でやることは次のとおりです。

- 条件判定に `n` を使う。`n` は深さ 1 にあるので `pick 1` で複製してから `jz` で判定する（判定で消費されるのは複製のほう）
- `acc * n` を計算する。もう一度 `pick 1` で `n` を複製して `mul` すると `[n acc*n]` になる
- `n` を 1 減らす。`swap` で `n` を先頭に出し、`push 1` `sub` で減らし、もう一度 `swap` で元の順に戻す

### pasm のソース

```pasm
; 階乗 n! を計算して出力する
        inn             ; [n]
        push 1          ; [n acc]
loop:
        pick 1          ; [n acc n]
        jz done         ; [n acc]        n = 0 なら終わり
        pick 1          ; [n acc n]
        mul             ; [n acc*n]
        swap            ; [acc n]
        push 1
        sub             ; [acc n-1]
        swap            ; [n-1 acc]
        jmp loop
done:
        outn            ; [n]
        push 10
        outc            ; 改行
```

コメントのスタックを上から追ってみてください。`loop:` に来るときは、最初も、`jmp loop` で戻ってきたときも `[n acc]` の形になっています。`done:` では `[n acc]` から `acc` を出力し、最後に改行（文字コード 10）を出力します。

これを pasm で変換したものが次の図です。入力欄に 5 を入れて実行すると、120 が出力されます。

@piet ch12/factorial caption="階乗を計算するプログラム（pasm で生成、44×27 コーデル）" input="5\n"

pasm が生成する画像には共通の形があります。左上の 1 コーデルから実行が始まり、命令の列は**基本ブロック**（途中にジャンプもラベルもない命令の並び）ごとに 1 行ずつ、左から右へ並びます。行の左右にある縦の白い通路と、下のほうにある横の白い通路が、ジャンプのための「配線」です。黒いコーデルは、白い通路を進む流れを曲がらせる角の役目をしています。

### テスト

入力を変えて何度か実行し、期待どおりの出力になるかを確かめます。

| 入力 | 期待される出力 | 確認すること |
|---|---|---|
| 5 | 120 | 普通の場合 |
| 0 | 1 | ループを 1 回も回らない場合（0! = 1） |
| 12 | 479001600 | 大きめの値 |

0 のように「ループを 1 回も回らない」入力は、ループの入口の条件判定が正しく書けているかを確かめるのに役立ちます。本書のサンプルは、どれもこのような複数の入力で、本書の piet.py と npiet の両方の出力が期待値と一致することを確認してあります。

!!! column "コラム: npiet の整数の大きさ"
    Piet の仕様では、スタックに積める整数の大きさに上限はありません（実装が上限を設けてもよく、そのときのあふれは実行時エラーとされています）。本書の piet.py は Python の整数を使っているので、20! = 2432902008176640000 も正しく計算できます。

    一方、npiet 1.3h はスタックの値を C 言語の `long` 型で持っています。本書の環境（64 ビットの Linux）では `long` は 64 ビットなので、2⁶⁴ を超える計算は桁あふれします。さらに注意が必要なのは `roll` です。npiet の `roll` は、動かす値を一時的に `int` 型（32 ビット）の変数に入れるため、**先頭の値が 32 ビットに収まらないと、`roll` で動かしたときに値が壊れます**。上の階乗のプログラムでは `swap`（中身は `roll`）で `acc` を動かしているので、npiet で 13 を入力すると、正しい 6227020800 ではなく 1932053504（6227020800 を 2³² で割った余り）が出力されます。12! = 479001600 は 32 ビットに収まるので正しく計算できます。

    このように、大きな数を扱うプログラムは処理系によって結果が変わることがあります。処理系ごとの違いは付録C にまとめています。

## 12.3 フィボナッチ数

次は、入力された上限 lim **未満**のフィボナッチ数を順に出力するプログラムです。フィボナッチ数は 0, 1, 1, 2, 3, 5, 8, … と、前の 2 つの和が次の数になる数列です。

```text
lim を読む
a = 0, b = 1
while lim > a:
    a を出力
    (a, b) = (b, a + b)
```

スタックの配置は `[lim a b]` とします。上限 `lim` は深さ 2 に置いたまま、ループのあいだずっと使います。

`(a, b) = (b, a + b)` の部分が、スタックでやると少し面白いところです。`[lim a b]` から始めて、

1. `dup` で `[lim a b b]`
2. `bury 2` で先頭の `b` を深さ 2 に沈めて `[lim b a b]`
3. `add` で `[lim b a+b]`

となり、3 命令（展開すると 6 命令）で新しい `[lim a b]` ができあがります。一時変数を使わずに 2 つの値を同時に更新できるのは、スタックマシンならではの書き方です。

```pasm
; limit 未満のフィボナッチ数を順に出力する
        inn             ; [lim]
        push 0          ; [lim a]
        push 1          ; [lim a b]
loop:
        pick 2          ; [lim a b lim]
        pick 2          ; [lim a b lim a]
        gt              ; [lim a b (lim>a)]
        jz done         ; [lim a b]
        pick 1          ; [lim a b a]
        outn            ; [lim a b]
        push 10
        outc
        dup             ; [lim a b b]
        bury 2          ; [lim b a b]
        add             ; [lim b a+b]
        jmp loop
done:
        halt
```

条件 `lim > a` を作るところに注意してください。`pick 2` を 2 回続けています。1 回目は深さ 2 の `lim` を複製し、その結果スタックが 1 つ深くなるので、2 回目の `pick 2` は元の `a` を複製します。`gt`（`greater`）は「2 番目 > 先頭」なら 1 を積むので、`[… lim a]` に対して `lim > a` が得られます。

@piet ch12/fib caption="上限未満のフィボナッチ数を出力するプログラム" input="100\n"

入力 100 では 0 から 89 までの 12 個が、入力 1 では 0 だけが出力されます。

## 12.4 ユークリッドの互除法

2 つの数の最大公約数（GCD）を求めるユークリッドの互除法は、とても短いループで書けます。

```text
a, b を読む
while b != 0:
    (a, b) = (b, a mod b)
a を出力
```

スタックは `[a b]` の 2 つだけです。`(a, b) = (b, a mod b)` は、フィボナッチ数のときと同じく `dup` と `bury 2` で書けます。`[a b]` → `dup` → `[a b b]` → `bury 2` → `[b a b]` → `mod` → `[b a%b]` です。

```pasm
; ユークリッドの互除法で最大公約数を求める
        inn             ; [a]
        inn             ; [a b]
loop:
        dup             ; [a b b]
        jz done         ; [a b]          b = 0 なら a が答え
        dup             ; [a b b]
        bury 2          ; [b a b]
        mod             ; [b a%b]
        jmp loop
done:
        pop             ; [a]
        outn
        push 10
        outc
```

@piet ch12/gcd caption="ユークリッドの互除法（34×27 コーデル）" input="1071 1029\n"

入力は空白か改行で区切った 2 つの数です。`in(number)` は数字の前の空白や改行を読み飛ばすので、`12 18` のように 1 行に書いても、2 行に分けてもかまいません。1071 と 1029 の最大公約数は 21 です。`0 9` を入力すると、1 回目の `mod` で `[9 0]` になり、9 が出力されます。

このプログラムは命令が少ないので、手で描けばもっと小さくできます。第14章では、これを 17×6 コーデルまで縮めます。

!!! note "メモ"
    `mod` の結果の符号は、仕様では「除数と同じ符号」（床関数による剰余）ですが、npiet は C 言語の `%` をそのまま使っているため「被除数と同じ符号」になります。負の数を入力すると処理系によって結果が変わるので、本書のプログラムは `mod` と `divide` に負の数を渡さないように書いています。詳しくは付録C を参照してください。

## 12.5 べき乗

a の b 乗を、b 回の掛け算で求めます。

```text
a, b を読む
r = 1
while b != 0:
    r = r * a
    b = b - 1
r を出力
```

スタックは `[a b r]` です。階乗とほとんど同じ形で、違いは掛ける数が毎回 `a`（深さ 2）であることだけです。

```pasm
; a の b 乗を計算する
        inn             ; [a]
        inn             ; [a b]
        push 1          ; [a b r]
loop:
        pick 1          ; [a b r b]
        jz done         ; [a b r]
        pick 2          ; [a b r a]
        mul             ; [a b r*a]
        swap            ; [a r b]
        push 1
        sub             ; [a r b-1]
        swap            ; [a b-1 r]
        jmp loop
done:
        outn
        push 10
        outc
```

@piet ch12/power caption="べき乗を計算するプログラム" input="2 10\n"

`2 10` で 1024、`7 3` で 343、`3 0` で 1 が出力されます。b が大きいとステップ数は b に比例して増えます。2 の 10 乗の計算には 313 ステップかかりました。

!!! tip "ヒント"
    「繰り返し二乗法」（b を 2 で割りながら a を 2 乗していく方法）を使うと、掛け算の回数を b 回から log₂ b 回程度に減らせます。`b mod 2` で分岐し、`b div 2` で b を半分にするループになります。腕試しにぜひ書いてみてください。

## 12.6 素数判定

入力された n が素数かどうかを判定し、素数なら `prime`、そうでなければ `not prime` と出力します。方法は単純な**試し割り**です。2 から順に d で割ってみて、割り切れたら素数ではありません。d × d が n を超えるまで割り切れなければ素数です。

```text
n を読む
if n < 2: "not prime" を出力して終了
d = 2
loop:
    if d * d > n: "prime" を出力して終了
    if n mod d == 0: "not prime" を出力して終了
    d = d + 1
```

この章で初めて、ループの**途中から**2 方向に抜け出すプログラムです。スタックは `[n d]` とします。

```pasm
; n が素数かどうかを判定する（試し割り）
        inn             ; [n]
        push 2
        pick 1          ; [n 2 n]
        gt              ; [n (2>n)]
        jnz notprime    ; [n]            n < 2 は素数ではない
        push 2          ; [n d]
loop:
        dup             ; [n d d]
        dup             ; [n d d d]
        mul             ; [n d d*d]
        pick 2          ; [n d d*d n]
        gt              ; [n d (d*d>n)]
        jnz isprime     ; [n d]          d*d > n まで割り切れなかった
        pick 1          ; [n d n]
        pick 1          ; [n d n d]
        mod             ; [n d n%d]
        jz notprime     ; [n d]          割り切れた
        push 1
        add             ; [n d+1]
        jmp loop
isprime:
        prints "prime\n"
        halt
notprime:
        prints "not prime\n"
        halt
```

`n < 2` の判定は、`push 2` `pick 1` で `[n 2 n]` を作ってから `gt` で `2 > n` を求めています。`greater` は「2 番目 > 先頭」なので、比べたい順に値を並べるのがこつです。

`d * d` は `dup` を 2 回続けて `[n d d d]` にし、`mul` で上の 2 つを掛けて作ります。`d` を変数に保存しておく必要はなく、スタックに必要な数だけ複製すればよいのです。

@piet ch12/prime caption="試し割りによる素数判定（99×69 コーデル）" input="7919\n"

文字列の出力（`prints`）があるので、画像はこれまでより大きくなりました。文字列を出力する部分の大きさについては第13章で考えます。

テストには、境界にあたる値を必ず含めます。

| 入力 | 期待される出力 | 確認すること |
|---|---|---|
| 17 | prime | 普通の素数 |
| 91 | not prime | 7 × 13。小さな約数で見つかる合成数 |
| 2 | prime | いちばん小さな素数（ループを 1 回も回らずに d×d > n になる） |
| 1 | not prime | 2 未満の特別扱い |
| 7919 | prime | 1000 番目の素数。d が 89 まで進む（3560 ステップ） |

## 12.7 各桁の和

10 進数の各桁を取り出すには、「10 で割った余りが一の位、10 で割った商が残りの桁」という性質を使います。

```text
n を読む
s = 0
while n != 0:
    s = s + n mod 10
    n = n div 10
s を出力
```

```pasm
; 各桁の数字の和を求める
        inn             ; [n]
        push 0          ; [n s]
loop:
        pick 1          ; [n s n]
        jz done         ; [n s]
        pick 1          ; [n s n]
        push 10
        mod             ; [n s d]        d = n % 10
        add             ; [n s+d]
        swap            ; [s n]
        push 10
        div             ; [s n/10]
        swap            ; [n/10 s]
        jmp loop
done:
        outn
        push 10
        outc
```

`push 10` は、pasm が `push 2` `push 5` `multiply` に展開します。pasm は 12 以下の数を基本的にブロックの大きさでそのまま表しますが、10 のように掛け算を使ったほうがコーデルが少なくて済む場合はそちらを選びます（大きさ 10 のブロックより、2 + 5 + 1 = 8 コーデルの命令列のほうが小さい）。12345 を入力すると 15、9999 では 36、0 では 0 が出力されます。

@piet ch12/digitsum caption="各桁の和を求めるプログラム" input="12345\n"

「10 で割った余りと商で桁を取り出す」技法は、数を 2 進数や 8 進数で出力するプログラム（第13章）でもそのまま使います。

## 12.8 コラッツ問題

最後は、ループの中に `if`〜`else` があるプログラムです。コラッツ問題とは、「n が偶数なら 2 で割り、奇数なら 3 倍して 1 を足す」という操作を繰り返すと、どんな正の整数から始めてもいずれ 1 になるだろう、という未解決の予想です。ここでは、n から 1 になるまでの操作の回数（手数）を数えます。

```text
n を読む
c = 0
while n != 1:
    c = c + 1
    if n が偶数: n = n / 2
    else:        n = 3n + 1
c を出力
```

スタックは `[n c]` です。偶数・奇数の判定と、それぞれの計算の間は `[c n]` の順に入れ替えておくと、`n` を先頭で扱えて楽になります。ループの最後に `swap` で `[n c]` に戻すのを忘れないようにします。

```pasm
; コラッツ数列が 1 に達するまでの手数を数える
        inn             ; [n]
        push 0          ; [n c]
loop:
        pick 1          ; [n c n]
        push 1
        sub             ; [n c n-1]
        jz done         ; [n c]          n = 1 なら終わり
        push 1
        add             ; [n c+1]
        swap            ; [c n]
        dup             ; [c n n]
        push 2
        mod             ; [c n n%2]
        jz even         ; [c n]
        push 3
        mul
        push 1
        add             ; [c 3n+1]
        swap            ; [3n+1 c]
        jmp loop
even:
        push 2
        div             ; [c n/2]
        swap            ; [n/2 c]
        jmp loop
done:
        outn
        push 10
        outc
```

「n が 1 か」の判定には、`n - 1` を計算して `jz` を使っています。Piet には「等しい」を調べる命令がないので、**引き算して 0 かどうかを見る**のが定石です。

`if`〜`else` の 2 つの枝（奇数の枝と `even:` の枝）は、どちらも最後に `jmp loop` でループの先頭に戻ります。2 つの枝の終わりでスタックが同じ `[n c]` の形になっていることを、コメントで確かめてください。

@piet ch12/collatz caption="コラッツ問題の手数を数えるプログラム" input="27\n"

6 を入力すると 6 → 3 → 10 → 5 → 16 → 8 → 4 → 2 → 1 の 8 手なので 8 が出力されます。27 は手数が多いことで知られる数で、111 手かかります（3770 ステップ）。1 を入力すると 0 です。

## まとめ

- 制御構造のある大きめのプログラムは、アセンブラ pasm で書くと効率がよい。`swap`・`pick`・`bury` は `roll` を使うマクロ、`jz`・`jnz` は `not` と `pointer` を使う分岐に展開される
- プログラムは「擬似コード → スタックの配置計画 → 命令ごとのスタックの状態を書いたソース → 複数入力でのテスト」の順に作る
- ループの入口と出口、`if` の各枝の終わりで、スタックの形がそろっていることを確認する
- 2 つの値の同時更新 `(a, b) = (b, f(a, b))` は `dup` `bury 2` と演算で書ける
- 「等しいか」は引き算して `jz`、「小さいか」は値の並べ方を工夫して `greater` で調べる
- npiet は値を 64 ビット（`roll` で動かす値は 32 ビット）で扱うので、大きな数では結果が仕様と変わることがある
