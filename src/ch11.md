# 第11章 スタックを使いこなす

第10章までで、計算・入出力・分岐・ループという、プログラムを書くための道具はひととおりそろいました。しかし、実際に少し複雑なプログラムを書こうとすると、すぐに壁に当たります。「さっき読んだ値をもう一度使いたいのに、スタックの奥に埋もれている」という壁です。

Piet には変数がありません。値を取り出せるのはスタックの先頭だけです。この章では、スタックの奥の値を自在に扱うための命令 `roll` を詳しく学び、それを組み合わせた定番の操作（イディオム）を身につけます。そして、スタックを「変数の並び」として使うプログラムの設計方法を考えます。

!!! abstract "この章で学ぶこと"
    - `duplicate` と `roll` の正確な定義
    - `roll` の深さと回数、負の回数、何も起きない場合
    - swap・over・rot・pick・bury など、`roll` から作るイディオムとそのコスト
    - スタックの決まった深さに値を置き、変数のように使う方法
    - スタックの形をコメントで書きながらプログラムを設計する方法

## 11.1 duplicate

`duplicate` は、先頭の値の複製を積みます。色相の変化 4、明度の変化 0 の命令です。`[a]` が `[a a]` になります。

これまでにも何度も使ってきたとおり、Piet の命令の多くは値を「消費」します。`out(number)` で出力した値も、`greater` で比較した値も、スタックから消えてしまいます。後でもう一度使う値は、消費する命令の前に `duplicate` しておくのが基本です。

`duplicate` が複製できるのは先頭の値だけです。2 番目以降の値を複製するには、次に説明する `roll` で先頭に持ってくる必要があります。

## 11.2 roll

### 定義

`roll` は、色相の変化 4、明度の変化 1 の命令です。仕様の定義は次のとおりです。

> roll: Pops the top two values off the stack and "rolls" the remaining stack entries to a depth equal to the second value popped, by a number of rolls equal to the first value popped. A single roll to depth n is defined as burying the top value on the stack n deep and bringing all values above it up by 1 place. A negative number of rolls rolls in the opposite direction. A negative depth is an error and the command is ignored.

整理すると、次のようになります。

1. スタックから 2 つの値を取り出す。先頭が**回数** n、2 番目が**深さ** d。
2. 残ったスタックの上から d 個の値を対象にする。
3. 「先頭の値を d 個の一番下に沈め、その上にあった値を 1 つずつ持ち上げる」操作（1 回のロール）を n 回行う。
4. n が負なら逆向き（一番下の値を先頭に持ち上げる）に |n| 回行う。

`roll` に渡す 2 つの値は、**深さ、回数の順に積む**ことに注意してください。

### 例

`[1 2 3 4]` に対して深さ 3、回数 1 の `roll` を行うと、上から 3 つの `2 3 4` が対象になり、先頭の 4 が 3 つ目の位置に沈みます。

```text
[1 2 3 4]   push 3, push 1   →   [1 2 3 4 3 1]
            roll             →   [1 4 2 3]
```

@piet ch11/roll1 caption="[1 2 3 4] を深さ 3・回数 1 でロールし、4 つの値を出力する（出力 3241）"

@trace ch11/roll1

`roll` のあとのスタックは `[1 4 2 3]` で、先頭から順に出力すると `3241` になります。`roll` の動きは頭の中だけで追うと混乱しがちです。Piet スタジオでこのプログラムを描き、1 ステップずつ実行してスタック表示の変化を確かめてみましょう。深さや回数のブロックの大きさを変えて試すと、すぐに感覚がつかめます。

回数を 2 にすると、沈める操作が 2 回行われ、`[1 3 4 2]` になります。

@piet ch11/roll2 caption="深さ 3・回数 2 のロール（出力 2431）"

### 負の回数

回数が負のときは逆向きに回ります。1 回の逆向きのロールは、対象のうち**一番下の値を先頭に持ち上げる**操作です。深さ 3 なら、逆向きに 1 回回すことと、順方向に 2 回回すことは同じ結果になります。

@piet ch11/rollneg caption="深さ 3・回数 −1 のロール。回数 2 と同じ結果になる（出力 2431）"

−1 は `push 1, push 2, subtract` で作っています。一般に、深さ d のロールは d 回で元に戻るので、回数 −k は回数 d − k と同じです。負の数を作るには余分な命令が要るので、実際には正の回数で書くほうが短く済みます。

### 何も起きないロール

次の場合、`roll` は値を 2 つ取り出すだけで、スタックの残りは変わりません。

- 深さが 0 または 1（対象が 0 個か 1 個なので、回しても同じ）
- 回数が 0、または深さの倍数

### 実行できないロール

深さが負の場合と、深さがスタックに残っている値の数より大きい場合は、実行できない命令として扱われます。仕様では「命令を無視する」とされているので、piet.py とブラウザ版ビューアは、取り出した深さと回数も含めてスタックを元のまま残します。

@piet ch11/rollfail caption="[1 2] に対して深さ 3 のロールを試みる。値が足りないので無視される"

このプログラムは `[1 2]` に 3 と 5 を積んで `roll` を実行します。取り出したあとに残るのは 2 つだけなので、深さ 3 のロールはできません。仕様どおりならスタックは `[1 2 3 5]` のまま残り、3 回の `out(number)` で `532` が出力されます。

npiet はここでも動作が異なり、深さと回数の 2 つを取り出したうえで何もしません。スタックは `[1 2]` になり、出力は `21` です。どちらの動作でも困らないように、深さはスタックの値の数を超えないように使いましょう。

## 11.3 roll から作るイディオム

`roll` は万能ですが、深さと回数を毎回考えるのは大変です。よく使う操作には名前を付けておくと、プログラムを考えやすくなります。ここでは、Forth という言語の用語にならった名前を使います。

### swap ― 上 2 つを入れ替える

```text
[a b]  push 2, push 1, roll  →  [b a]
```

深さ 2 で 1 回ロールすると、先頭が 1 つ下に沈み、上 2 つが入れ替わります。

@piet ch11/swap caption="swap: [1 2] を [2 1] にして出力する（出力 12）"

### rot と -rot ― 上 3 つを回す

```text
rot:   [a b c]  push 3, push 2, roll  →  [b c a]    3 番目を先頭へ
-rot:  [a b c]  push 3, push 1, roll  →  [c a b]    先頭を 3 番目へ
```

@piet ch11/rot caption="rot: [1 2 3] を [2 3 1] にする（出力 132）"

@piet ch11/mrot caption="-rot: [1 2 3] を [3 1 2] にする（出力 213）"

### over ― 2 番目を複製する

```text
[a b]  swap       →  [b a]
       duplicate  →  [b a a]
       -rot       →  [a b a]
```

@piet ch11/over caption="over: [1 2] を [1 2 1] にする（出力 121）"

### nip ― 2 番目を捨てる

```text
[a b]  swap, pop  →  [b]
```

@piet ch11/nip caption="nip: [1 2] から 1 を捨てる（出力 2）"

### pick と bury ― 任意の深さ

深さを一般化した操作も用意しておきましょう。以下、深さは**先頭を 0** と数えます。`[x a1 … ad]` のとき、x の深さは d です。

| 名前 | 動作 | 命令列 |
|---|---|---|
| dig d | 深さ d の値を先頭に持ってくる | `push d+1, push d, roll` |
| bury d | 先頭の値を深さ d に沈める | `push d+1, push 1, roll` |
| pick d | 深さ d の値の複製を先頭に積む | dig d, `duplicate`, bury d+1 |

pick は「掘り出して、複製して、片方を元の位置に戻す」という 3 段階の操作です。dig d で x を先頭に持ってくると `[a1 … ad x]`、`duplicate` で `[a1 … ad x x]`、そして先頭の x を深さ d + 1 に沈めると `[x a1 … ad x]` になります。

本書の pasm には、`swap`、`pick D`、`bury D` がマクロとして組み込まれています。

```pasm
; pick と bury の動作を確かめる
  push 1
  push 2
  push 3
  push 4         ; [1 2 3 4]
  pick 2         ; [1 2 3 4 2]
  outn           ; 2 を出力 → [1 2 3 4]
  push 9         ; [1 2 3 4 9]
  bury 2         ; [1 2 9 3 4]
  outn
  outn
  outn
  outn
  outn           ; 4 3 9 2 1
```

@piet ch11/pick caption="pick と bury（出力 243921）"

### イディオムのコスト

`push n` のブロックは n コーデル、それ以外の命令のブロックは 1 コーデルと数えると、各イディオムのおおよそのコスト（コーデル数）は次のようになります。

| イディオム | 動作 | コスト |
|---|---|---|
| `duplicate` | `[a]` → `[a a]` | 1 |
| swap | `[a b]` → `[b a]` | 4 |
| rot | `[a b c]` → `[b c a]` | 6 |
| -rot | `[a b c]` → `[c a b]` | 5 |
| over（= pick 1） | `[a b]` → `[a b a]` | 10 |
| nip | `[a b]` → `[b]` | 5 |
| dig d | | 2d + 2 |
| bury d | | d + 3 |
| pick d | | 3d + 7 |

深い位置の値を扱うほどコストは大きくなります。とくに pick は深さの 3 倍で増えていくので、**よく使う値はスタックの浅いところに置く**のが、小さな Piet プログラムを書くためのこつです。

!!! tip "ヒント"
    同じ深さの数を何度も積むときは、push の値のブロックを大きな長方形にまとめると絵が引き締まります。一方、深さ 1 や 2 の小さな数は 1〜2 コーデルで済むので、浅い位置の操作はほとんどコストがかかりません。

## 11.4 スタックを変数として使う

### スタックの形を決める

変数のない Piet でも、スタックの**決まった位置に決まった値を置く**と決めれば、それを変数のように扱えます。たとえば「スタックの底から順に i、s、p を置く」と決めたら、ループの先頭では常に `[i s p]` という形になるようにプログラムを書きます。

プログラムを書くときは、各命令の右に実行後のスタックの形をコメントで書いていきます。

```pasm
loop:
  pick 2         ; [i s p i]
  jz done        ; [i s p]
```

これは Forth のプログラマが「スタック効果コメント」と呼ぶ習慣と同じものです。Piet ではスタックの中身が目に見えないので、このコメントがなければ、数行先で何が起きているのかすぐにわからなくなります。

### 例: 和と積を同時に求める

1 から n までの和 s と積 p を同時に求めるプログラムを書いてみます。i を n から 1 まで数え下げ、s に i を足し、p に i を掛けていきます。

```pasm
; 1..n の和と積を同時に求める。スタックを [i s p] の「変数」として使う
  inn            ; [i]        i = n から 1 まで数え下げる
  push 0         ; [i s]
  push 1         ; [i s p]
loop:
  pick 2         ; [i s p i]
  jz done        ; [i s p]
  pick 2         ; [i s p i]
  mul            ; [i s p*i]
  push 3
  push 2
  roll           ; [s p i]     rot: i を先頭へ
  dup            ; [s p i i]
  push 4
  push 3
  roll           ; [p i i s]   s を先頭へ（roll 4 3 = 4 段の rot）
  add            ; [p i s+i]
  push 3
  push 1
  roll           ; [s p i]     -rot
  push 1
  sub            ; [s p i-1]
  push 3
  push 1
  roll           ; [i-1 s p]
  jmp loop
done:
  push 2
  push 1
  roll           ; [i p s]
  outn           ; s
  push 32
  outc
  outn           ; p
  push 10
  outc
```

@piet ch11/sumprod caption="1 から n までの和と積（入力 5 → 出力 15 120）" input="5\n"

ループの中では、値を使う直前にその値を先頭に持ってきて（rot や `push 4, push 3, roll`）、計算が終わったら元の並びに戻しています（-rot）。ループの先頭と末尾でスタックの形が `[i s p]` にそろっていることを、コメントで確かめてください。

### 変数に書き込む

決まった深さの値を、新しい値で**置き換える**こともできます。深さ d の値 x を v で置き換えるには、次のようにします。

```text
[x a1 … ad]      push v              →  [x a1 … ad v]
                 bury d+1            →  [v x a1 … ad]
                 dig d               →  [v a1 … ad x]
                 pop                 →  [v a1 … ad]
```

新しい値を x の下に潜り込ませてから、古い値 x を掘り出して捨てる、という手順です。次の例は `[1 2 3]` の 1 を 9 に置き換えます。

@piet ch11/store caption="[1 2 3] の底の値を 9 に置き換える（出力 329）"

@trace ch11/store

!!! column "コラム: スタックの深さを浅く保つ"
    スタックを変数の置き場として使うと、変数が増えるほど深い位置の値を扱うことになり、pick や roll のコストが増えていきます。小さな Piet プログラムを書く人は、「次に使う値が先頭に来るように」計算の順序を工夫します。たとえば和と積の例では、ループの中で i を何度も使うので、i を先頭近くに置いた並び `[s p i]` でループを回せば、rot と -rot の回数を減らせます。どの値をどの順で置くかは、Piet のプログラミングで最も頭を使うところであり、最もパズルらしい部分でもあります。

## まとめ

- `duplicate` は先頭を複製する。値を消費する命令の前に複製しておくのが基本。
- `roll` は先頭（回数）と 2 番目（深さ）を取り出し、上から深さ分の値を回転させる。1 回のロールは先頭を深さの位置に沈める。負の回数は逆向き。
- 深さが負、またはスタックの値の数より大きいロールは無視される（npiet は 2 つの値を取り出してしまう）。
- swap・rot・-rot・over・nip、そして任意の深さの dig・bury・pick は `roll` の組み合わせで作れる。深い位置ほどコストが大きい。
- スタックの決まった位置に値を置けば変数のように使える。各命令の後のスタックの形をコメントで書いて設計する。

## 練習問題

1. スタックが `[1 2 3 4 5]` のとき、`push 4, push 1, roll` を実行するとどうなりますか。`push 4, push 3, roll` ならどうなりますか。
2. `[a b]` を `[b a b]` にする操作（Forth では tuck と呼ぶ）を、`duplicate` と `roll` で作り、`[1 2]` に適用して結果を出力するプログラムを描いてください。
3. 上 3 つの順序を逆にする操作 `[a b c]` → `[c b a]` を、この章のイディオムを組み合わせて作ってください。
4. 3 つの整数 a、b、c を読み、ab + bc + ca を出力するプログラムを pasm で書いてください。
5. 深さ d、回数 d の `roll` が何も変化を起こさない理由を説明してください。
