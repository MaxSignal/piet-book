# 第17章 Piet アセンブラを作る

前章では Piet の画像を実行するインタプリタを作りました。本章では逆向きの道具、つまり **命令の並びから Piet の画像を作る** アセンブラを作ります。

第III部までに見てきたとおり、数十個の命令からなるプログラムでも、色を 1 つずつ計算しながら手で塗るのは大変な作業です。ループや分岐が入ると、白と黒で通り道を作る設計まで必要になります。アセンブラがあれば、私たちは `push 72`、`outc`、`jz done` といった命令を書くだけで済み、色の計算、ブロックの大きさ、通り道の配線はすべて機械に任せられます。本書の後半のサンプルの多くも、本章で紹介する `tools/pasm.py` で作っています。

!!! abstract "この章で学ぶこと"
    - 本書のアセンブリ言語 pasm の文法と、マクロ（`prints`・`swap`・`pick`・`bury`）の展開
    - 大きな数を少ないコーデルで積むための動的計画法
    - 命令列を「基本ブロック」に分け、1 行の色の並びに変換する方法
    - 白い通り道（配線）で任意のジャンプを実現するレイアウトと、時計回りにしか曲がれない制約の克服
    - 条件分岐と停止のしかけの作り方

## 17.1 アセンブラの全体像

pasm.py は、次の順に処理を進めます。

1. **構文解析**（`parse`）: ソースを 1 行ずつ読み、命令・ラベル・引数に分ける。
2. **マクロ展開**（`expand`）: `push 1000` や `prints "Hi"` のような便利な命令を、Piet の基本命令だけの列に直す。
3. **基本ブロックへの分割**（`basic_blocks`）: ラベルとジャンプの位置で命令列を区切る。
4. **レイアウト**（`layout_linear` / `layout_general`）: 各基本ブロックを 1 行の色の並びにし、行どうしを白い配線でつなぐ。
5. **出力**: 画像（PNG）として保存する。

コマンドラインからは次のように使います。

```sh
python3 tools/pasm.py prog.pasm -o prog.png        # 画像を作る
python3 tools/pasm.py prog.pasm --text             # テキスト格子で表示する
```

## 17.2 アセンブリ言語 pasm

pasm は 1 行に 1 命令を書く単純な言語です。`;` から行末まではコメントです。

| 書き方 | 意味 |
|---|---|
| `label:` | ラベル（ジャンプ先の名前） |
| `push N` | 整数 N を積む。0・負の数・大きな数も書ける |
| `pop` `add` `sub` `mul` `div` `mod` `not` `gt` | Piet の同名の命令（`gt` は `greater`） |
| `dp` `cc` `dup` `roll` | `pointer` `switch` `duplicate` `roll` |
| `inn` `inc` `outn` `outc` | `in(number)` `in(char)` `out(number)` `out(char)` |
| `jmp L` | ラベル L へ無条件にジャンプ |
| `jz L` / `jnz L` | 先頭の値を取り出し、0 なら（0 以外なら）L へジャンプ |
| `halt` | 停止 |
| `prints "文字列"` | 文字列を出力（`\n` などのエスケープが使える） |
| `swap` | 上の 2 つを入れ替える |
| `pick D` | 深さ D（先頭が 0）の値の複製を積む |
| `bury D` | 先頭の値を深さ D の位置へ沈める |

たとえば、3, 2, 1 と数えるプログラムは次のように書けます。

```pasm
; 3, 2, 1 と数える
  push 3
loop:
  dup
  outn
  push 1
  sub
  dup
  jnz loop
  pop
  halt
```

`jmp`・`jz`・`jnz`・`halt` は、Piet には存在しない命令です。これらをどう実現するかが、本章の後半の主題になります。

## 17.3 マクロの展開

`expand()` は、便利な命令を Piet の命令列に置き換えます。いくつか例を見ましょう。

```text
swap    => push 2  push 1  roll
pick 2  => push 3  push 2  roll  duplicate  push 4  push 1  roll
bury 2  => push 3  push 1  roll
```

`swap` は「深さ 2 の roll を 1 回」です。`[a b]` に対して先頭の b を深さ 2 に沈めると `[b a]` になります。

`pick D` は少し複雑です。スタックが `[x a1 … aD]`（x が深さ D）のとき、次の 3 段階で x の複製を先頭に作ります。

1. `push D+1`、`push D`、`roll` ― 深さ D+1 の区間を D 回回転させる。これは「x を先頭へ引き上げる」ことと同じで、`[a1 … aD x]` になる。
2. `duplicate` ― `[a1 … aD x x]`
3. `push D+2`、`push 1`、`roll` ― 先頭の x を深さ D+2 の区間の底へ沈め、`[x a1 … aD x]` にする。

roll の回数に −1 を使えば手順 1 は「−1 回」と書けますが、−1 を積むには `push 1`、`push 2`、`subtract` のように手間がかかります。深さ D+1 の区間では D 回の回転と −1 回の回転が同じなので、正の数で済ませています。

`prints "Hi"` は、文字ごとに「文字コードを積む → `out(char)`」を繰り返す列に展開されます。

## 17.4 数を少ないコーデルで積む

Piet で数 n を積むには、n コーデルのブロックから `push` で出る必要があります。つまり `push 1000` を素直に実現すると 1000 コーデルのブロックが必要です。これでは画像が巨大になるので、[第6章](ch06.html)で学んだように、小さな数の積や和で組み立てます。

問題は「どう組み立てるのが最も安いか」です。pasm.py はこれを **動的計画法** で解きます。数 n のコスト（おおよそのコーデル数）を次の候補の最小値として定義します。

- n が 12 以下なら、そのまま push する: コスト n + 1
- n = a × a なら、a を作って `duplicate`、`multiply`: コスト(a) + 2
- n = a × b なら、a と b を作って `multiply`: コスト(a) + コスト(b) + 1
- n = m + k（k は 12 以下）なら、m を作って k を push し `add`: コスト(m) + k + 2

```python
@functools.lru_cache(maxsize=None)
def number_plan(n):
    """正の整数 n を積むための (コスト, 命令列)。コスト ≒ 使うコーデル数"""
    assert n >= 1
    best = (n + 1, [("push", n)]) if n <= DIRECT_MAX else (10 ** 9, None)
    # 平方 a*a = a dup mul
    r = int(n ** 0.5)
    if r * r == n and r >= 2:
        c, s = number_plan(r)
        cand = (c + 2, s + [("duplicate",), ("multiply",)])
        if cand[0] < best[0]:
            best = cand
    # 積 a*b
    for a in range(2, r + 1):
        if n % a == 0:
            ca, sa = number_plan(a)
            cb, sb = number_plan(n // a)
            cand = (ca + cb + 1, sa + sb + [("multiply",)])
            if cand[0] < best[0]:
                best = cand
    # 和 m + k（k は小さい数）
    if n > DIRECT_MAX:
        for k in range(1, DIRECT_MAX + 1):
            cm, sm = number_plan(n - k)
            cand = (cm + k + 2, sm + [("push", k), ("add",)])
            if cand[0] < best[0]:
                best = cand
    return best
```

`functools.lru_cache` は、一度計算した結果を覚えておく仕組み（メモ化）です。これによって同じ n の計算を繰り返さず、再帰で書いたまま動的計画法になります。いくつかの数について、得られる命令列を示します。

| n | コスト | 命令列 |
|---|---|---|
| 5 | 6 | `push 5` |
| 12 | 10 | `push 3` `push 4` `multiply` |
| 13 | 12 | `push 3` `duplicate` `multiply` `push 4` `add` |
| 72（`H`） | 13 | `push 2` `push 6` `duplicate` `multiply` `multiply` |
| 100 | 12 | `push 2` `push 5` `multiply` `duplicate` `multiply` |
| 1000 | 23 | `push 2` `push 5` `push 2` `push 5` `multiply` `duplicate` `multiply` `multiply` `multiply` |

100 は「2 × 5 = 10 を作って 2 乗」、72 は「6 の 2 乗に 2 を掛ける」と、人間が思いつく工夫を自動で見つけています。

0 と負の数は特別に扱います。0 は `push 1`、`not` で作り、負の数 −n は `1 − (n + 1)` として作ります。

!!! note "再帰の深さに注意"
    `number_plan(n)` は `n - k` を再帰的に呼ぶので、大きな n をいきなり計算すると Python の再帰の深さの上限（既定で 1000 程度）を超えることがあります。pasm.py の `push_seq()` は、大きな n のときに 300 刻みの小さい値から順に `number_plan` を呼んでキャッシュを温めておき、この問題を避けています。結果は変わりません。

    さらに n が 20000 を超えると、表を下から埋めるやり方では時間がかかりすぎます。そこで `push_seq()` は、そのような n には別の関数 `big_plan(n)` を使います。`big_plan` は 2〜12 の k について n = (n ÷ k) × k + 余り と分解し、商を同じ方法で再帰的に作ります。再帰は log n 段で済むので、4294967301 のような数でも一瞬で命令列が得られます（最短である保証はありません）。

このコスト関数は完全ではありません。`n = a × b − k` のような引き算の形や、すでにスタックにある値の再利用は考えていません。改良の余地については本章の最後で触れます。

## 17.5 基本ブロックに分ける

次に、命令列をジャンプの単位で区切ります。途中にジャンプもジャンプ先もない、ひとつながりの命令列を **基本ブロック**（basic block）と呼びます。コンパイラの教科書でおなじみの概念です。

`basic_blocks()` は、命令列を先頭から読みながら次のように区切ります。

- **ラベル**が来たら、そこで新しいブロックを始める。直前のブロックは「そのラベルへジャンプ」で終わったことにする（実行がそのまま次へ流れ落ちる「フォールスルー」も、ジャンプとして扱う）。
- **`jmp L`** が来たら、ブロックを「L へジャンプ」で終える。次のラベルまでの命令は実行されることがないので捨てる。
- **`jz L` / `jnz L`** が来たら、ブロックを「条件が成り立てば L、成り立たなければ次のブロック」という分岐で終える。次のブロックには自動で名前（`__L1` など）を付ける。
- **`halt`** が来たら、ブロックを停止で終える。

結果は `(ラベル, 命令列, 終わり方)` の組のリストです。終わり方は `("jmp", L)`、`("br", "jz", L, 次)`、`("halt",)` のいずれかです。

また、1 つの基本ブロックが長すぎると画像が横に長くなりすぎるので、`split_long()` が幅 48 コーデルを目安に分割し、分割点を `jmp` でつなぎます。

## 17.6 1 行に色を並べる

1 つの基本ブロックの命令列は、左から右へ 1 行に並んだ色ブロックの列になります。この変換は驚くほど簡単です。

```python
def row_colors(cmds, start=START_COLOR):
    """命令列 → [(色, 幅)] 。push N の直前のブロックは幅 N"""
    blocks = []
    c = start
    for k, cmd in enumerate(cmds):
        width = cmd[1] if cmd[0] == "push" else 1
        blocks.append([c, width])
        c = next_color(c, cmd[0])
    blocks.append([c, 1])
    return blocks
```

最初のブロックは淡赤（`START_COLOR`）です。命令を 1 つ処理するたびに、`next_color()`（[第4章](ch04.html)の命令表を逆に引く関数）で次の色を決めます。ブロックの幅は 1 コーデルですが、次の命令が `push N` のときだけ、そのブロックを N コーデルにします。push が積むのは「出ていくブロック」の大きさだからです。

高さ 1 の行では、DP が右向きである限り、出口のコーデルはブロックの右端の 1 つに決まり、CC がどちらを向いていても結果は変わりません。この性質のおかげで、行の中では CC のことを一切考えずに済みます。

ジャンプのない短いプログラムは、この 1 行だけで完成です。次の図は `prints "Hi\n"` を変換したものです。

## 17.7 停止のしかけ

プログラムの最後では、インタプリタが 8 回の試行すべてに失敗するよう、ブロックを黒で囲む必要があります。pasm.py の `_place_trap()` は、最後のブロック P の右に 3 コーデルの L 字形のブロック T を置き、その周りを黒で囲みます（1 行だけのレイアウトでは、L 字は下向きになります）。

```text
  P T #        P : 最後のブロック
# T T #        T : 終端ブロック（3 コーデル）
  # #          # : 黒
```

T の四方の縁を調べてみましょう。

- 右の縁（T の右の列）: 2 つのコーデルとも右隣は黒。
- 下の縁（T の下の行）: 2 つのコーデルとも下は黒。
- 左の縁（T の左の列）: 左隣は黒。P の真下にある T のコーデルの、さらに左にも黒を置いているからです。
- 上の縁（T の上の行）: 画像の外。

どの DP、どの CC でも外へ出られないので、ここで必ず停止します。P は T に接していますが、T のどの縁の出口コーデルからも P へは進めない形になっているのがポイントです。P から T への最後の遷移は「無害な `push`」になるよう、T の色を P の色から決めています。

## 17.8 行と行を白い配線でつなぐ

いよいよ本章の山場です。ジャンプを含むプログラムでは、基本ブロックの行を縦に並べ、行の終わりから飛び先の行の始まりまで、白い通り道（配線）を引きます。

### 白の中では時計回りにしか曲がれない

[第8章](ch08.html)で学んだとおり、白の中を滑っていて黒にぶつかると、CC が切り替わり DP が **時計回り** に 1 つ回ります。つまり、黒を 1 つ置くだけで「右へ進んでいたものを下へ」「下へ進んでいたものを左へ」と曲げられます。しかし反時計回り（右から上へ）には、黒 1 つでは曲げられません。

そこで pasm.py は、すべてのジャンプを次の形の経路で実現します。

```text
右へ → 下へ → 左へ → 上へ → 右へ（飛び先の行に入る）
```

4 回とも時計回りなので、それぞれの角に黒を 1 つ置くだけで済みます。しかも、この経路は飛び先が上にあっても下にあっても同じ形で使えます。いったん画像のいちばん下まで降りてから、左端を上がって戻ってくるからです。

### 画像の区画

画像は次の区画に分かれます。n は行（基本ブロック）の数です。

| 区画 | 位置 | 役割 |
|---|---|---|
| 開始コーデル | (0, 0) | 実行の出発点。淡赤の 1 コーデル |
| 左レーン | x = 1, 3, 5, …（行ごとに 1 本） | 下から上へ登って、飛び先の行に入る |
| コード領域 | 左レーンの右 | 各行の命令。行 i は y = 3 + 4i |
| 右レーン | コード領域の右（行ごとに 1 本） | 右から来た配線を下へ降ろす |
| 下部チャネル | 最後の行の下（行ごとに 1 本） | 右レーンの下端から左レーンの下端へ |

飛び先が行 t のジャンプは、次のように進みます。

1. 行の終わりから右へ滑り、右レーン t の 1 つ右に置かれた黒にぶつかって下へ曲がる。
2. 右レーン t を下へ滑り、下部チャネル t の 1 つ下に置かれた黒にぶつかって左へ曲がる。
3. 下部チャネル t を左へ滑り、左レーン t の 1 つ左の黒にぶつかって上へ曲がる。
4. 左レーン t を上へ滑り、行 t の 1 つ上の黒にぶつかって右へ曲がる。
5. 右へ滑って、行 t の最初の色ブロックに入る。白からの移動なので命令は実行されない。

コードで書くと、黒を置く 4 種類の場所の指定だけです。

```python
for y, t in targets_from:                         # 各ジャンプの出発行 y
    cv.put(xr(t) + 1, y, BLACK, f"turn-down {t}")
for t in used:                                    # 飛び先 t ごとに 1 組
    cv.put(xr(t), yb(t) + 1, BLACK, f"turn-left {t}")
    cv.put(xl(t) - 1, yb(t), BLACK, f"turn-up {t}")
    cv.put(xl(t), Y(t) - 1, BLACK, f"turn-right {t}")
```

実行の開始も、(0, 0) の淡赤のコーデルから「行 0 へのジャンプ」として同じ経路で行 0 に入ります。遠回りですが、白の中の移動は何ステップ分でも命令を実行しないので、プログラムの意味には影響しません。

### 配線が交差しても大丈夫な理由

右レーンは縦に、下部チャネルは横に走るので、配線どうしはあちこちで交差します。Piet の白の滑走は、黒や色にぶつかるまでまっすぐ進むので、白どうしの交差点は素通りでき、問題になりません。

問題になるのは、曲がるための黒が、別の配線の通り道に置かれてしまう場合だけです。pasm.py は次のように場所を分けて、これが起きないようにしています。

- レーンは 2 列おきに置き、曲がるための黒はレーンとレーンの間の列に置く。黒の列には縦の配線が通らない。
- 下部チャネルも 2 行おきに置き、曲がるための黒はチャネルの間の行に置く。黒の行には横の配線が通らない。
- 各行で右へ向かう配線は、その行の高さ（偽の分岐は y、真の分岐は y − 1）にしかない。

さらに安全装置として、キャンバスの `put()` は、同じ場所に違う色を置こうとすると例外を投げます。設計の誤りで黒と色がぶつかれば、画像を出力する前に気づけます。

## 17.9 条件分岐

`jz L` と `jnz L` は、Piet の `pointer` 命令で実現します。`pointer` は値を 1 つ取り出し、その回数だけ DP を時計回りに回すのでした。

基本ブロックの最後に、次の命令を付け加えます。

| 元の命令 | 付け加える命令列 | スタック先頭の値 → pointer の回数 |
|---|---|---|
| `jz L` | `not` `push 3` `multiply` `pointer` | 0 → 3、0 以外 → 0 |
| `jnz L` | `not` `not` `push 3` `multiply` `pointer` | 0 → 0、0 以外 → 3 |

`not` は 0 を 1 に、0 以外を 0 にします。`jnz` で `not` を 2 回重ねるのは、任意の値を 0 か 1 に「正規化」するためです。その値に 3 を掛けて `pointer` に渡すと、条件が成り立たないときは 0 回（右向きのまま）、成り立つときは 3 回、つまり反時計回りに 1 回で **上向き** になります。

- **成り立たない（偽）**: DP は右のまま。行の右端から白へ出て、右へ滑る。次の基本ブロックへのジャンプと同じ経路をたどる。
- **成り立つ（真）**: DP は上向き。最後のブロックの真上の白に出て、さらにその上に置いた黒にぶつかり、時計回りに曲がって右へ滑る。こうして 1 つ上の行（y − 1）を通って、飛び先 L の右レーンへ向かう。

なぜ「下向き」（`pointer` 1 回）にしないのでしょうか。下へ出ると、次に右へ向かうには「下から右」という反時計回りの曲がりが必要になり、黒 1 つでは実現できないからです。上向きに出れば「上から右」は時計回りなので、黒 1 つで曲がれます。3 を掛ける手間（`push 3` と `multiply` で数コーデル）は、この制約を回避するための費用です。

次の図は、数を 1 つ読んで偶数か奇数かを表示するプログラムです。

```pasm
  inn
  push 2
  mod
  jz even
  prints "odd\n"
  halt
even:
  prints "even\n"
```

@piet ch17/parity caption="偶数なら even、奇数なら odd と出力する。分岐の真の経路は上へ出る" input="7\n" zoom=10

最初の行（y = 3）の右端を見ると、最後のブロックの 2 つ上（y = 1）に黒があり、そこで真の経路が右へ曲がっていることが分かります。y = 7 の行は `odd` を出力して停止する行で、その右端の上にある黒に囲まれた形が停止のしかけです。

## 17.10 できあがりと限界

pasm.py は、次のような意味で「必ず動く」画像を作ります。

- 行の中は高さ 1 なので、CC の状態に左右されない。
- 配線は白と黒だけで作られ、命令を実行しない。
- 停止のしかけは 8 回の試行すべてを失敗させる。

一方で、画像の美しさや小ささは二の次です。改良の余地はたくさんあります。

- **フォールスルーの最適化**: 次の行へ流れ落ちるだけのジャンプも、いったん画像の下まで降りて戻ってきます。次の行の始まりへ直接つなげば、配線が減ります。
- **レーンの節約**: 今はすべての行にレーンを 1 本ずつ用意していますが、ジャンプの飛び先になる行の分だけで足ります。
- **行の高さを使う**: ブロックを複数行にまたがる長方形にすれば、大きな push の幅を減らせます。ただし、出口コーデルが CC に依存するようになるので注意が必要です。
- **数の作り方の改善**: 引き算や、`duplicate` による値の再利用を候補に加えると、さらに短くなる数があります。
- **見た目**: 開始色を変える、空いた場所を装飾する、など。[第15章](ch15.html)の技法と組み合わせる余地があります。

npiet に付属する npiet-foogol や、Sergei Lewis の Piet アセンブラなど、ほかの「Piet を生成する道具」も、それぞれ異なるレイアウトの工夫をしています（[第18章](ch18.html)、[第20章](ch20.html)）。

## まとめ

- アセンブラは、構文解析 → マクロ展開 → 基本ブロックへの分割 → レイアウト、の順に処理する。
- `push N` は「直前のブロックを N コーデルにする」ことで実現する。大きな数は、動的計画法で積と和の組み合わせを探して安く作る。
- 基本ブロックは高さ 1 の行に並べる。行の中では CC を考えずに済む。
- 白の中は時計回りにしか曲がれないので、ジャンプはすべて「右 → 下 → 左 → 上 → 右」の経路で実現する。
- 条件分岐は「0/1 に正規化 → 3 を掛ける → `pointer`」で、真のときだけ上へ出す。
- 終端は L 字形のブロックを黒で囲んで作る。
