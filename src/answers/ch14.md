## 第14章 総合演習

### 問題 14-1

3 つの戻り先 `ret1`・`ret2`・`ret3` の文字列から先頭の ` of beer` を取り除き、かわりにサブルーチンの中で、本数の言い方を出力した直後に ` of beer` を出力します。`b0` と `b1` の枝も、最後に共通の `ofbeer:` へ合流させます。変更した部分だけを示します。


```pasm
ret1:
        prints " on the wall, "
        ...
ret2:
        prints ".\nTake one down and pass it around, "
        ...
ret3:
        prints " on the wall.\n\n"
        ...
bottles:
        swap                    ; [r m]
        dup
        jz b0                   ; m = 0
        dup
        push 1
        sub
        jz b1                   ; m = 1
        outn
        prints " bottles"
        jmp ofbeer
b0:
        pop
        prints "no more bottles"
        jmp ofbeer
b1:
        outn
        prints " bottle"
ofbeer:
        prints " of beer"       ; 3 か所で共通の部分をここにまとめた
return:                         ; [r]
        ...
```

@piet ch14/ex1 caption="練習問題 1 の解答。共通部分をサブルーチンに移した 99 Bottles of Beer（387×501 コーデル）" zoom=2

出力は元のプログラムとまったく同じです（期待出力のファイルを共有してテストしました）。画像は 403×525 から 387×501 コーデルへ、面積で 1 割ほど小さくなりました。` of beer` の 8 文字ぶんの命令を 3 か所から 1 か所にまとめたので、そのぶん命令は減りますが、`jmp ofbeer` が増えて基本ブロックの数は変わらないため、配線を含めた画像全体の縮み方は控えめです。

### 問題 14-2

「何か出力したか」を数える `k` をスタックに積んでおき、`Fizz` や `Buzz` を出力するたびに 1 足します。最後に `k` が 0 のときだけ数を出力します。


```pasm
; FizzBuzz 別解: Fizz と Buzz を別々に判定し、どちらも出なければ数を出す
        push 1          ; [i]
loop:
        push 0          ; [i k]          k = 何か出力したか
        pick 1
        push 3
        mod
        jnz nofizz
        prints "Fizz"
        push 1
        add             ; k = k + 1
nofizz:
        pick 1
        push 5
        mod
        jnz nobuzz
        prints "Buzz"
        push 1
        add
nobuzz:
        jnz next        ; k ≠ 0 なら数は出さない
        dup
        outn
next:
        push 10
        outc
        push 1
        add
        dup
        push 101
        sub
        jnz loop
```

@piet ch14/ex2 caption="練習問題 2 の解答。FizzBuzz の別解（99×69 コーデル）" zoom=4

15 の倍数では `Fizz` と `Buzz` が続けて出力されるので、`FizzBuzz` という文字列は不要になりました。画像は 111×87 から 99×69 コーデルに小さくなりましたが、毎回 `k` を積んで調べるぶん、実行ステップ数は 6029 から 7653 に増えています。大きさと速さはしばしばトレードオフになります。

### 問題 14-3

演算子の判定に `^`（94）を加え、累乗の枝 `power:` では第12章のべき乗のループを使います。ループが終わった時点のスタックは `[a b r]` なので、`bury 2` `pop` `pop` で `[r]` にしてから合流点 `print:` へ進みます。


```pasm
        dup
        push 94         ; '^'
        sub
        jz power
        prints "?\n"    ; 知らない演算子
        halt
        ...
modulo:
        pop
        mod
        jmp print
power:
        pop             ; [a b]
        push 1          ; [a b r]
ploop:
        pick 1
        jz pdone        ; b = 0 なら終わり
        pick 2
        mul             ; [a b r*a]
        swap
        push 1
        sub
        swap            ; [a b-1 r]
        jmp ploop
pdone:
        bury 2
        pop
        pop             ; [r]
print:
        outn
        push 10
        outc
```

@piet ch14/ex3 caption="練習問題 3 の解答。累乗を加えた電卓" input="2^10\n" zoom=4

`2^10` で 1024、`5^0` で 1 が出力され、ほかの演算子もこれまでどおり動きます。

### 問題 14-4

命令は 4 つなので、1 行に 5 つのブロックを並べ、最後のブロックを L 字形のわなにします。淡青から始めると、`in(number)`（色相 +4、明度 +2）で濃緑、もう一度 `in(number)` で赤、`add`（色相 +1）で黄、`out(number)`（色相 +5、明度 +1）で濃赤になります。


@grid ch14/ex4

@piet ch14/ex4 caption="練習問題 4 の解答。2 つの数の和（6×3 コーデル）" input="3 4\n" zoom=40

濃赤のブロックは、黄から右に入る 1 行目の (4,0) と、その下の 2 行目の 2 コーデルからなる L 字形です。右・下・左は黒、上は画像の端なので、どの方向にも出られず停止します。2 行目の左側の黒 (2,1) は、L 字の左端 (3,1) から左へ出られないようにするためのものです。

### 問題 14-5

`out(number)` の後に、大きさ 10 のブロック・`push`・`out(char)` を追加します。出口は下向きに進んでいるので、大きさ 10 のブロックを縦長（2×5）にして下へ並べ、その下に `push` 用の 1 コーデルのブロック、最後に `out(char)` の結果を受ける横棒を置きます。


@grid ch14/ex5

@piet ch14/ex5 caption="練習問題 5 の解答。改行も出力する手描きの互除法（17×12 コーデル）" input="1071 1029\n" zoom=28

いくつか注意する点があります。

- 大きさ 10 のブロック（淡黄、2×5）から下へ出るとき、出口になるのは下端の 2 コーデルのうち CC で選ばれるほうです。このとき CC は左（ループの白い通路で 4 回切り替わって元に戻っている）なので、下向きに進むときの「左」、つまり**東側**（右の列）のコーデルが選ばれます。そこで `push` 用の黄のブロックは右の列 (8,9) に置きます。
- 最後の淡赤のブロックは、横に 3 つ並んだ横棒で、真ん中 (8,10) から入ります。横棒の上端・下端の辺から出ようとすると、CC が選ぶのは両端のコーデルなので、真ん中の入口へ戻ることはありません。両端の上下左右を黒で囲めば、どの方向にも出られなくなります。入口がブロックの辺の「端」にならないようにするのが、わなを作るこつです（第15章でも使います）。
