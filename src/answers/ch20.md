## 第20章 Piet の世界

### 問題 20-1

自由解答です。比べるときは、npiet に必ず `-q` を付けます（付けないと入力のたびに `? ` が出力に混ざります）。出力が食い違った場合は、[付録C](appC.html)の表で、その作品が処理系依存の命令（負の数の `mod`、0 による除算、255 を超える文字コードなど）を使っていないかを調べましょう。入力が必要な作品は、トレースで最初の `in(number)` や `in(char)` がどこで実行されるかを探し、その直後にスタックの値がどう使われるか（比較される相手の数、出力のされ方）から、期待されている入力の種類を推測できます。


### 問題 20-2

`loop_fix` の制御フローは「9 を積む → ループ本体（出力、2 を引く、0 より大きければ先頭へ）→ 捨てて停止」です。Piet のブロックとスタックの動きをそのまま Python に写すと、たとえば次のようになります。


```python
stack = []
stack.append(9)                      # push 9
while True:                          # loop:
    stack.append(stack[-1])          #   dup
    print(stack.pop())               #   outn と outc 10
    stack.append(2)                  #   push 2
    b = stack.pop(); a = stack.pop()
    stack.append(a - b)              #   sub
    stack.append(stack[-1])          #   dup
    stack.append(0)                  #   push 0
    b = stack.pop(); a = stack.pop()
    stack.append(1 if a > b else 0)  #   gt
    if stack.pop() == 0:             #   jnz loop（0 なら抜ける）
        break
stack.pop()                          # pop
```

repiet や PietCC のようなコンパイラは、これを機械的に行い、さらにスタック操作を変数に置き換えるなどの最適化をします。上のプログラムなら、最終的には `n = 9; while True: print(n); n -= 2; if not n > 0: break` と同じ意味になります。

### 問題 20-3

本書の形式は 20 色に 20 文字（`r y g c b m`、`R Y G C B M`、`1`〜`6`、`.`、`#`）を割り当てています。別の形式に変換するには、両方の形式について「文字 → (色相, 明度) または白・黒」の対応表を作り、本書の文字 → 色 → 相手の文字、と 2 段階で引けば十分です。piet.py の `CHARS` 辞書が本書側の対応表です。相手の形式に、改行やコメントの扱い、行の長さをそろえる必要があるかどうかなどの約束があれば、それも合わせます。


### 問題 20-4

解答例: 「画面にグラフィックスを描く」「ファイルを開いて読み書きする」「ネットワークで通信する」などは、Piet ではできません。Piet が持つ入出力は標準入力と標準出力だけだからです。また、「実行時間やメモリを現実的な範囲に抑えながら大きなプログラムを書く」ことも非常に難しいでしょう。


これらはチューリング完全性と矛盾しません。チューリング完全性は「計算できる関数の範囲」についての性質で、どんな計算も（時間とメモリを無制限に使ってよければ）原理的に実行できる、という意味にすぎないからです。外部の装置とのやりとり（入出力の種類）や、効率、書きやすさは、チューリング完全性とは別の問題です。
