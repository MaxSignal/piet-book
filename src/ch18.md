# 第18章 小さな言語から Piet へ ― コンパイラを作る

前章のアセンブラで、ラベルとジャンプを使ったプログラムを Piet の画像にできるようになりました。それでも pasm で書くのは楽ではありません。値がスタックのどこにあるかを常に頭の中で追いかけ、`pick 3` や `bury 2` の数字を間違えないように書かなければならないからです。

本章では、もう一段高い水準の言語を設計し、それを pasm に翻訳する **コンパイラ** を作ります。変数、四則演算、比較、`if` と `while` を備えた、ごく小さな言語です。これを「Mini」と呼ぶことにします。コンパイラ `tools/minic.py` は約 400 行の Python プログラムで、FizzBuzz や素数の列挙を Piet の画像に変換できます。

!!! abstract "この章で学ぶこと"
    - 小さな言語 Mini の仕様と、コンパイラの構成（字句解析 → 構文解析 → コード生成）
    - 変数をスタックの底に固定して置き、コンパイル時に「深さ」を追跡する方法
    - 式・条件・`if`・`while` を pasm の命令列に翻訳する方法
    - 入力の終わり（EOF）を番兵で検出する工夫
    - npiet に付属するコンパイラ npiet-foogol との比較

## 18.1 Mini 言語

まず、Mini で書いたプログラムを見てください。

```c
// FizzBuzz（1 から 30 まで）
i = 1;
while (i <= 30) {
  if (i % 15 == 0) { prints "FizzBuzz"; }
  else if (i % 3 == 0) { prints "Fizz"; }
  else if (i % 5 == 0) { prints "Buzz"; }
  else { print i; }
  putc '\n';
  i = i + 1;
}
```

C 言語や JavaScript を知っている人なら、説明なしで読めるでしょう。Mini の仕様は次のとおりです。

| 種類 | 書き方 | 意味 |
|---|---|---|
| 代入 | `x = 式;` | 変数 x に式の値を入れる |
| 数の出力 | `print 式;` | `out(number)` で出力 |
| 文字の出力 | `putc 式;` | `out(char)` で出力 |
| 文字列の出力 | `prints "文字列";` | 文字列を出力（`\n` などのエスケープ可） |
| 数の入力 | `read x;` | `in(number)` で読む。読めなければ −1 |
| 文字の入力 | `getc x;` | `in(char)` で読む。読めなければ −1 |
| 条件分岐 | `if (式) 文 else 文` | `else` は省略可 |
| 繰り返し | `while (式) 文` | |
| ブロック | `{ 文 … }` | |

式には、整数、文字（`'a'` は 97）、変数、かっこ、そして次の演算子が使えます。上ほど優先順位が高くなります。

| 優先順位 | 演算子 |
|---|---|
| 1（高） | 単項の `-` |
| 2 | `*` `/` `%` |
| 3 | `+` `-` |
| 4 | `<` `>` `<=` `>=` `==` `!=` |
| 5 | `not` `!` |
| 6 | `and` `&&` |
| 7（低） | `or` `||` |

変数はすべて整数で、宣言は要りません。プログラム中に現れた変数はすべてプログラム全体で共有され、初期値は 0 です。関数や配列はありません。真偽値も整数で表し、0 が偽、0 以外が真です。

## 18.2 コンパイラの構成

minic.py は、教科書どおりの 3 段構成です。

1. **字句解析**（`tokenize`）: 文字の列を、数・名前・演算子などの「トークン」の列にする。
2. **構文解析**（`Parser`）: トークンの列から、プログラムの構造を表す木（抽象構文木、AST）を作る。
3. **コード生成**（`CodeGen`）: 木をたどりながら pasm のソースを出力する。

最後に pasm.py（前章）が画像を作ります。Mini → pasm → Piet と、2 段階で翻訳するわけです。中間に pasm をはさむことで、コンパイラはスタックの操作とジャンプのことだけを考えればよく、色や配線のことは一切気にせずに済みます。

```sh
python3 tools/minic.py fizzbuzz.mini              # pasm を表示
python3 tools/minic.py fizzbuzz.mini -o fb.png    # 画像まで作る
```

## 18.3 字句解析

字句解析には正規表現を使います。トークンの種類ごとに名前付きのグループを書き、先頭から順に照合していきます。

```python
TOKEN_RE = re.compile(r"""
    (?P<ws>\s+|//[^\n]*|\#[^\n]*)
  | (?P<num>\d+)
  | (?P<chr>'(?:\\.|[^'\\])')
  | (?P<str>"(?:\\.|[^"\\])*")
  | (?P<id>[A-Za-z_]\w*)
  | (?P<op><=|>=|==|!=|&&|\|\||[-+*/%<>=!(){};])
""", re.VERBOSE)
```

空白とコメント（`ws`）は読み飛ばします。文字リテラル `'a'` は、この段階で数（97）に変えてしまいます。演算子のうち `<=` のような 2 文字のものを 1 文字のものより先に書いているのは、`<=` を `<` と `=` に分けて読んでしまわないためです。名前のうち `print` や `while` などは予約語として区別します。

## 18.4 構文解析

構文解析は **再帰下降法** で書きます。文法の規則 1 つにつき関数を 1 つ用意し、規則の中に別の規則が現れるところで、その関数を呼び出します。優先順位の低い演算子から順に関数を作るのが定石です。

```python
def add(self):
    e = self.mul()
    while self.peek()[1] in ("+", "-"):
        op = self.take()[1]
        e = (op, e, self.mul())
    return e

def mul(self):
    e = self.unary()
    while self.peek()[1] in ("*", "/", "%"):
        op = self.take()[1]
        e = (op, e, self.unary())
    return e
```

`add()` は「`mul()` で読める式を、`+` か `-` でつないだもの」を読みます。`while` で左から順に組み立てていくので、`10 - 3 - 2` は `((10 - 3) - 2)` と、正しく左結合になります。

抽象構文木は Python のタプルで表しました。たとえば `i % 15 == 0` は次のようになります。

```python
("==", ("%", ("var", "i"), ("num", 15)), ("num", 0))
```

文も同じくタプルです。`while (c) body` は `("while", 条件, 本体)`、`if` は `("if", 条件, then, else)` です。

## 18.5 変数をどこに置くか

ここがこのコンパイラの設計の中心です。Piet には「メモリ」がなく、データを置ける場所はスタックだけです。そこで、次のように決めます。

- プログラムで使う変数を全部数え、実行開始時にその個数だけ 0 を積む。**スタックの底の部分を変数の置き場にする**。
- 式の計算に使う一時的な値は、変数の上に積む。

```text
底                                  先頭
[ a  b  t | 一時的な値 … ]
  変数の置き場
```

変数の位置は、底からは固定です。しかし Piet の命令（`roll` など）は、すべて **先頭からの深さ** で位置を指定します。先頭からの深さは、変数の上に一時的な値がいくつ積まれているかによって変わります。

そこでコンパイラは、コードを生成しながら「今、変数の上に一時的な値がいくつあるか」を数え続けます。これを `temps` と呼びます。値を 1 つ積む命令を出力したら `temps` を 1 増やし、2 つ取り出して 1 つ積む `add` なら 1 減らす、という具合です。

```python
def emit(self, line, delta=0):
    self.out.append("  " + line)
    self.temps += delta

def depth(self, name):
    """変数 name の、現在のスタック先頭からの深さ（0 = 先頭）"""
    i = self.vars.index(name)
    return (len(self.vars) - 1 - i) + self.temps
```

変数が 3 つ（a, b, t）で一時的な値が 2 つあるとき、a の深さは (3 − 1 − 0) + 2 = 4 です。これで、変数の読み出しは pasm の `pick` 1 つで書けます。

```python
elif k == "var":
    self.emit(f"pick {self.depth(e[1])}     ; {e[1]}", +1)
```

書き込みは少し工夫が要ります。新しい値はスタックの先頭にあり、それを深さ d の変数の位置に入れ、古い値を捨てなければなりません。

```python
def store(self, name):
    """スタック先頭の値を変数 name に書き込み、先頭から取り除く"""
    d = self.depth(name)          # 先頭の値を含めた深さ
    if d == 1:
        self.emit("swap")
        self.emit("pop", -1)
    else:
        self.emit(f"bury {d}")      # 新しい値を変数の位置へ。古い値は深さ d-1 に上がる
        self.emit(f"push {d}")
        self.emit(f"push {d - 1}")
        self.emit("roll")           # 古い値を先頭へ
        self.emit("pop", -1)        # 捨てる
```

変数が a, b の 2 つで、a に 42 を書き込む場合を追ってみましょう。

| 命令 | スタック（左が底） | 説明 |
|---|---|---|
| | `[a b 42]` | 新しい値 42 が先頭にある。a の深さは 2 |
| `bury 2` | `[42 a b]` | 42 を深さ 2 へ沈める。a と b が 1 つずつ上がる |
| `push 2` `push 1` `roll` | `[42 b a]` | 深さ 2 の区間を 1 回転させ、古い a を先頭へ |
| `pop` | `[42 b]` | 古い a を捨てる。a の位置に 42 が入った |

実際に、次の小さなプログラムをコンパイルしてみます。

```c
// 変数の読み書き
a = 6 * 7;
b = a - 2;
print b;
putc '\n';
```

minic.py の出力（pasm）は次のとおりです。

```pasm
; 変数: a, b
  push 0     ; a
  push 0     ; b
; a = ...
  push 42
  bury 2
  push 2
  push 1
  roll
  pop     ; → a
; b = ...
  pick 1     ; a
  push 2
  sub
  swap
  pop     ; → b
  pick 0     ; b
  outn
  push 10
  outc
  halt
```

`6 * 7` が `push 42` になっているのは、後で説明する定数畳み込みのおかげです。b への書き込みでは、b の深さが 1 なので `swap` と `pop` だけで済んでいます。ジャンプがないので、この程度のプログラムは 1 行の画像になります。

## 18.6 式のコード生成

式は、スタックマシンの定石どおり **後置記法**（逆ポーランド記法）の順に命令を出します。`a - 2` なら「a を積む → 2 を積む → `sub`」です。

```python
elif k in ("+", "-", "*", "/", "%"):
    self.expr(e[1]); self.expr(e[2])
    self.emit({"+": "add", "-": "sub", "*": "mul", "/": "div", "%": "mod"}[k], -1)
```

左の式、右の式の順に計算して積み、最後に演算を 1 つ出力します。演算は 2 つ取り出して 1 つ積むので、`temps` は 1 減ります。

Piet の比較命令は `greater`（2 番目が先頭より大きければ 1）しかありません。ほかの比較は組み合わせで作ります。

| Mini | 命令列 | 考え方 |
|---|---|---|
| `a > b` | a, b, `gt` | そのまま |
| `a < b` | b, a, `gt` | 「b > a」と同じ |
| `a <= b` | a, b, `gt`, `not` | 「a > b ではない」 |
| `a >= b` | b, a, `gt`, `not` | 「b > a ではない」 |
| `a == b` | a, b, `sub`, `not` | 差が 0 なら 1 |
| `a != b` | a, b, `sub`, `not`, `not` | 差が 0 でなければ 1 |

論理演算 `and` と `or` は、まず両辺を 0 か 1 にそろえて（`not` を 2 回）から、`and` は掛け算、`or` は足し算をしてもう一度 0/1 にそろえます。比較や `not` の結果は最初から 0 か 1 なので、そろえる命令は省きます。

```python
elif k == "and":                     # 両方を 0/1 にしてから掛ける
    self.bool(e[1]); self.bool(e[2]); self.emit("mul", -1)
elif k == "or":                      # 0/1 にして足し、もう一度 0/1 に
    self.bool(e[1]); self.bool(e[2]); self.emit("add", -1); self.emit("not"); self.emit("not")
```

Mini の `and` と `or` は、C 言語の `&&` や `||` と違って **短絡評価をしません**。両辺を必ず計算します。Mini の式には副作用（入力や代入）がないので、結果は変わりません。

## 18.7 文のコード生成

`if` と `while` は、ラベルと条件ジャンプに翻訳します。

```python
elif k == "while":
    l_top, l_end = self.label("while"), self.label("wend")
    self.out.append(f"{l_top}:")
    self.expr(fold(s[1]))
    self.emit(f"jz {l_end}", -1)
    self.stmt(s[2])
    self.emit(f"jmp {l_top}")
    self.out.append(f"{l_end}:")
```

`while (条件) 本体` は、次の pasm になります。

```pasm
while1:
  （条件を計算）
  jz wend2        ; 偽なら抜ける
  （本体）
  jmp while1
wend2:
```

`if` も同様に、条件が偽なら `else` 側のラベルへ飛び、`then` 側の最後で `jmp` によって `else` 側を飛び越します。

ここで大切な約束があります。**1 つの文の実行が終わったとき、`temps` は必ず 0 に戻っている** ことです。もし `if` の片方の枝だけが値を 1 つ残すと、合流した後の変数の深さが、どちらの枝を通ったかによって変わってしまい、コンパイル時に深さを決められなくなります。minic.py は、文を 1 つ生成するたびに `assert self.temps == 0` で確かめています。

## 18.8 入力の終わりを見分ける

Piet の `in` 命令は、入力がなければ「無視」されます。何も積まれないので、スタックの深さが 1 つずれてしまい、以降の変数の読み書きがすべて狂います。しかも、Piet にはスタックの深さを調べる命令がありません。

minic.py は **番兵** を使ってこれを解決しています。読む前に −1 を積んでおき、読んだ後の先頭を調べます。

```pasm
  push -1         ; 番兵
  inc             ; 読めれば [-1 c]、読めなければ [-1]
  dup
  push -1
  gt              ; 先頭 > -1 なら 1（読めた）
  jz in_done1     ; 読めなかった: [-1] のまま
  swap
  pop             ; 読めた: 番兵を捨てて [c]
in_done1:
  （先頭を変数に書き込む）
```

文字コードは 0 以上なので、先頭が −1 より大きければ「読めた」、そうでなければ「番兵がそのまま残っている」と判定できます。どちらの経路でも、最後にはスタックに値がちょうど 1 つ残ります。これで、`getc c;` は入力が尽きると c に −1 を入れる、という分かりやすい動作になります。

```c
// 入力をそのまま出力する（大文字は小文字に変換）
getc c;
while (c != -1) {
  if (c >= 'A' and c <= 'Z') { c = c + 32; }
  putc c;
  getc c;
}
```

@piet ch18/cat caption="入力の大文字を小文字にして出力する。入力が尽きると停止する" input="Hello, PIET World!\n" zoom=5

!!! warning "read の制限"
    `read x;` も同じ方法で −1 を番兵にしています。そのため、入力された数が −1 以下だと、読めなかった場合と区別できず、スタックがずれてしまいます。Mini の `read` は 0 以上の整数の入力を前提としています。

## 18.9 定数畳み込み

`6 * 7` のように、コンパイル時に値が決まる式は、その場で計算してしまいます。これを **定数畳み込み**（constant folding）と呼びます。

```python
def fold(e):
    if e[0] in ("num", "var"):
        return e
    ...
    op, a, b = e[0], fold(e[1]), fold(e[2])
    if a[0] == "num" and b[0] == "num":
        （a[1] と b[1] で演算して ("num", 結果) を返す）
    return (op, a, b)
```

Piet では数を積むこと自体にコーデルがかかるので、`push 6`、`push 7`、`mul` より `push 42` のほうが小さくなります（42 は pasm.py が `push 6` `push 7` `mul` 相当の安い作り方を自動で選びます）。効果は小さいですが、コンパイラの最適化の第一歩として実装しておきました。

## 18.11 npiet-foogol と比べる

Piet を生成するコンパイラは、本書が初めてではありません。npiet の作者 Erik Schoenfelder は、npiet と一緒に **npiet-foogol** というコンパイラを配布しています。foogol は Per Lindberg が mod.sources に投稿した、ALGOL 風の小さな言語です。npiet-foogol はそのソースを読んで、Piet の画像を出力します。

foogol で同じ「階乗の表」を書くと、次のようになります。

```text
begin
  integer n, f;
  n := 1; f := 1;
  while 8 > n do begin
    f := f * n;
    printn (n); prints ("! = "); printn (f); print;
    n := n + 1
  end
end
```

変数は `integer` で宣言し、代入は `:=`、数の出力は `printn`、文字列は `prints`、改行は `print` です。比較演算子は `=`・`#`（等しくない）・`>`・`<` の 4 つです。npiet をビルドしたディレクトリで、次のように変換します。

```sh
$ ./npiet-foogol -o foogol_fact.png foogol_fact.foo
output saved to foogol_fact.png
$ ./npiet -q foogol_fact.png
1! = 1
2! = 2
...
7! = 5040
```

@piet ch18/foogol_fact caption="npiet-foogol が生成した階乗の表（117×9 コーデル）" zoom=6

同じ内容を Mini で書いてコンパイルしたものと比べてみましょう。

```c
n = 1;
f = 1;
while (n < 8) {
  f = f * n;
  print n; prints "! = "; print f; putc '\n';
  n = n + 1;
}
```

@piet ch18/fact_small caption="同じ処理を minic.py でコンパイルしたもの（79×39 コーデル）" zoom=6

| | npiet-foogol | minic.py + pasm.py |
|---|---|---|
| 画像の大きさ | 117 × 9 = 1,053 コーデル | 79 × 39 = 3,081 コーデル |
| 実行ステップ数（piet.py で計測） | 1,222 | 650 |

npiet-foogol の画像は横長で、面積は約 3 分の 1 です。マニュアルによると、npiet-foogol はコードを左から右へ生成し、折り返し幅（`-w` オプション）に達すると左向きに折り返します。ループや条件分岐の部分は、仮想的な左端を設けて重ならないように配置しています。数を作るときは、`-b` オプションで指定した基数（既定は 7）で数を分解します。

一方、本書の pasm.py は、ジャンプのたびに画像の下端を回り込む単純な配線を使うので、空白が多く面積が大きくなります。そのかわり実行ステップ数は少なくなっています。白の中の滑走は何コーデル進んでも 1 ステップと数えられるからです。どちらが優れているというより、「画像を小さくする」と「仕組みを単純にする」のどちらを重視したかの違いです。

## 18.12 さらに先へ

Mini には、関数も配列もありません。これらを加えるには、何が必要でしょうか。

- **配列**: `roll` の深さはスタックから取り出す値なので、実行時に計算した深さを使えます。つまり「i 番目の要素」をスタック上の位置で表し、計算した深さで `roll` すれば、添字による読み書きができます。
- **関数**: 呼び出し元へ戻るには「戻り先」を覚えておく必要がありますが、Piet には「任意の場所へのジャンプ」がありません。戻り先の番号をスタックに積み、関数の終わりで番号ごとに分岐する（ジャンプ表を作る）という方法が考えられます。再帰呼び出しでは、局所変数もスタックに積み重ねることになります。

実際に、Sergei Lewis は Piet のアセンブラと、それを出力先とする C 風の言語のコンパイラを公開しています。このコンパイラは `if`・`for`・`while` に加えて再帰的な関数を扱えます（[第20章](ch20.html)）。

## まとめ

- Mini → pasm → Piet と 2 段階で翻訳すると、コンパイラはスタックとジャンプのことだけを考えればよい。
- 変数はスタックの底に固定して置き、変数の上の一時的な値の数（`temps`）をコンパイル時に追跡して、読み出しは `pick`、書き込みは `bury` と `roll` で行う。
- 文の実行の前後で `temps` を 0 に保つことが、分岐や繰り返しを正しく翻訳するための約束である。
- 比較は `greater`・`not`・`subtract` の組み合わせで、論理演算は 0/1 にそろえてからの掛け算・足し算で作る。
- 入力の終わりは、番兵の −1 を先に積んでおくことで検出できる。
- npiet-foogol は画像を小さくする配置を、pasm.py は単純な配線を選んでおり、設計の重点が違う。
