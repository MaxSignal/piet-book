# 第5章 プログラムの流れ ― DP と CC

第4章までで、色ブロックから色ブロックへ移るときに命令が実行されることを学びました。では、インタプリタは**どの**隣のブロックへ移るのでしょうか。一つの色ブロックの周りには、たいてい複数のブロックが接しています。どこへ進むかを決めるのが、この章で学ぶ **DP**（方向ポインタ）と **CC**（コーデルチューザ）という 2 つの「向き」です。DP と CC の規則、進めないときの再試行の手順、そしてプログラムを確実に終了させる方法を学ぶと、Piet のプログラムの動きを完全に追えるようになります。

!!! abstract "この章で学ぶこと"
    - 実行の開始位置と、DP・CC の初期値
    - ブロックの出口となるコーデルの選び方（DP と CC の 8 通りの組み合わせ）
    - 黒いブロックや画像の端で進めないときの再試行の手順
    - 8 回失敗するとプログラムが終了すること
    - 確実に終了させる「わな」の設計

## 5.1 実行の開始

仕様によれば、Piet のプログラムは**左上のコーデルを含む色ブロック**から実行を始めます。左上のコーデルだけでなく、そのコーデルを含むブロック全体が最初の「いまいるブロック」です。たとえば次のプログラムでは、左上の赤いブロックは左端の列に沿って縦に長く伸びた、大きさ 12 のブロックです。

@piet ch05/exit caption="大きさ 12 の赤いブロックから始まるプログラム。12 を出力する" zoom=32

インタプリタは、実行のあいだ次の状態を持っています。

- **いまいる色ブロック**（最初は左上のコーデルを含むブロック）
- **DP**（Direction Pointer、方向ポインタ）: 右・下・左・上のいずれか。最初は**右**。
- **CC**（Codel Chooser、コーデルチューザ）: 左・右のいずれか。最初は**左**。
- **スタック**（最初は空）

DP はインタプリタが進もうとしている向きです。CC は、DP の向きに進むときに「進行方向に向かって左寄りのコーデルから出るか、右寄りのコーデルから出るか」を決めます。

## 5.2 出口のコーデルを選ぶ

インタプリタは、いまいる色ブロックから次のブロックへ移るとき、仕様に従って次の手順で出口のコーデルを選びます。

1. ブロックの中で、**DP の向きに最も遠い辺**を求める。DP が右なら、ブロックの最も右の列に属するコーデルの集まりです。
2. その辺のコーデルの中から、**CC の向きに最も遠いコーデル**を選ぶ。CC の向きは、DP の向きに顔を向けて立ったときの左手・右手の方向です。
3. そのコーデルから、DP の向きに 1 コーデル進んだ先のコーデルに移る。

CC の「左」「右」は、画面の左右ではなく、**DP の向きを基準にした左右**である点に注意してください。DP が右向きのとき、進行方向に向かって左手は画面の上です。DP が下向きのときは、左手は画面の右になります。DP と CC の 8 通りの組み合わせで、選ばれるコーデルは次のとおりです。

| DP | CC | 選ばれるコーデル |
|---|---|---|
| 右 | 左 | 右端の列のうち、最も**上**のコーデル |
| 右 | 右 | 右端の列のうち、最も**下**のコーデル |
| 下 | 左 | 下端の行のうち、最も**右**のコーデル |
| 下 | 右 | 下端の行のうち、最も**左**のコーデル |
| 左 | 左 | 左端の列のうち、最も**下**のコーデル |
| 左 | 右 | 左端の列のうち、最も**上**のコーデル |
| 上 | 左 | 上端の行のうち、最も**左**のコーデル |
| 上 | 右 | 上端の行のうち、最も**右**のコーデル |

具体的なブロックで確かめてみましょう。次の図の `X` が一つの色ブロックで、A〜H が各組み合わせで選ばれる出口のコーデルです（本書付属のインタプリタの出口選択の関数で計算したものです。DP が右の 2 通りはどちらも C になるので、F は使っていません）。

```text
       x=0 1 2 3 4
  y=0    . A X B .      A: DP 上・CC 左    B: DP 上・CC 右
  y=1    H X X X C      C: DP 右・CC 左、DP 右・CC 右（同じ）
  y=2    G X X X .      D: DP 下・CC 左    E: DP 下・CC 右
  y=3    . E D . .      G: DP 左・CC 左    H: DP 左・CC 右
```

- DP が右のとき、最も右の列（x = 4）にあるコーデルは (4,1) だけです。辺が 1 コーデルしかないので、CC が左でも右でも同じ C が選ばれます。
- DP が下のとき、最も下の行（y = 3）は (1,3) と (2,3) です。DP 下に向かって左手は画面の右なので、CC 左では右側の D (2,3)、CC 右では左側の E (1,3) が選ばれます。
- DP が左のとき、最も左の列（x = 0）は (0,1) と (0,2) です。左を向いたときの左手は画面の下なので、CC 左では下の G (0,2)、CC 右では上の H (0,1) です。
- DP が上のとき、最も上の行（y = 0）は (1,0)〜(3,0) です。上を向いたときの左手は画面の左なので、CC 左では A (1,0)、CC 右では B (3,0) です。

出口のコーデルは、ブロックの形と DP・CC だけで決まり、**直前にどこからブロックに入ってきたかには関係しません**。この性質は、あとでプログラムを終了させる仕組みを考えるときに重要になります。

下の道（濃赤・淡赤・淡黄）は `push 12`、`push 1`、`add`、`out(number)` を実行して 13 を出力するように作ってありますが、CC が左である限り使われません。

## 5.3 進めないとき

DP の向きに進んだ先が**黒いコーデル**か**画像の外**だった場合、インタプリタはそちらへ進めません。仕様はこのとき、次のように再試行すると定めています。

1. まず **CC を切り替え**（左なら右に、右なら左に）、同じブロックから出直してみる。
2. それでも進めなければ、**DP を時計回りに 1 つ回し**（右 → 下 → 左 → 上 → 右）、出直してみる。
3. 以後、CC の切り替えと DP の回転を交互に繰り返す。
4. **8 回試しても進めなければ、プログラムは終了する。**

DP が右・CC が左の状態から 8 回とも失敗した場合、試す組み合わせは次の順になります。

| 試行 | DP | CC | 失敗したあとに変えるもの |
|---|---|---|---|
| 1 | 右 | 左 | CC を切り替える |
| 2 | 右 | 右 | DP を回す |
| 3 | 下 | 右 | CC を切り替える |
| 4 | 下 | 左 | DP を回す |
| 5 | 左 | 左 | CC を切り替える |
| 6 | 左 | 右 | DP を回す |
| 7 | 上 | 右 | CC を切り替える |
| 8 | 上 | 左 | （終了） |

8 回の試行で、DP の 4 つの向きと CC の 2 つの向きのすべての組み合わせが一度ずつ試されます。つまり「8 回失敗して終了する」とは、「どの向きのどの出口からも出られない」ということです。

**途中で進めた場合、変更した DP と CC はそのまま残ります。** 元の向きに戻ることはありません。これが、Piet のプログラムの流れが向きを変える基本的な仕組みです。

### 黒で道をふさぐ

5.2 節のプログラムで、上の道の入り口を黒でふさいでみましょう。

@piet ch05/blocked caption="上の道を黒でふさいだもの。13 を出力する" zoom=32

@grid ch05/blocked

(3,0) が黒になったため、DP 右・CC 左で選ばれる出口 (2,0) からは右へ進めません。インタプリタは CC を右に切り替えて出直します。DP 右・CC 右では右端の列の最も下のコーデル (2,4) が選ばれ、その右隣の濃赤 (3,4) に進めます。こうして下の道が実行され、13 が出力されます。

npiet のトレースを見ると、CC が切り替わったことがわかります。

```text
trace: step 0  (0,0/r,l nR -> 3,4/r,r dR):
action: push, value 12
trace: step 1  (3,4/r,r dR -> 4,4/r,r lR):
action: push, value 1
trace: step 2  (4,4/r,r lR -> 5,4/r,r lY):
action: add
trace: step 3  (5,4/r,r lY -> 6,4/r,r nR):
action: out(number)
```

1 行目の移動元は `r,l`（DP 右・CC 左）ですが、移動先は `r,r`（DP 右・CC 右）になっています。切り替わった CC は、その後もずっと右のままです。

## 5.4 角を曲がる

進めないときの再試行の規則を使うと、命令を使わずに流れの向きを変えられます。次のプログラムは、上の行を右へ、右の列を下へ、下の行を左へと、画像の縁に沿って 1 コーデルずつ進みながら、1 から 4 までの数を出力します。

@piet ch05/corner caption="画像の端で向きを変えながら 1234 を出力する" zoom=40

@grid ch05/corner

各ブロックは大きさ 1 で、移動するたびに `push`（1 を積む）、`duplicate`、`out(number)`、`add` などの命令が実行されます。注目してほしいのは角の部分です。npiet のトレースから、向きが変わる前後を抜き出します。

```text
trace: step 4  (4,0/r,l nC -> 5,0/r,l nB):
action: add
trace: step 5  (5,0/r,l nB -> 5,1/d,r nG):
action: duplicate
  ……
trace: step 8  (5,3/d,r lY -> 5,4/d,r lG):
action: add
trace: step 9  (5,4/d,r lG -> 4,4/l,l lR):
action: duplicate
```

右上の角の青 (5,0) では、右が画像の端なので進めません。CC を右に切り替えても進めず、DP を下に回すと、真下の緑 (5,1) に進めます。トレースの `5,1/d,r` は、DP が下（`d`）、CC が右（`r`）になったことを示しています。右下の角の淡緑 (5,4) では、下が画像の端なので、CC を左に戻し、それでも進めないので DP を左に回して、左隣の淡赤 (4,4) へ進みます。

このように、**画像の端や黒いコーデルに突き当たると、流れは時計回りに曲がります**。プログラムを渦巻き状や「コ」の字形に配置できるのはこのためです。

最後の淡マゼンタのブロックは左下の角にある L 字形のブロックで、ここで 4 が出力され、プログラムは終了します。終了の仕組みは次の節で説明します。

!!! note "メモ"
    再試行の規則で曲がれるのは時計回りだけです（DP を時計回りに回すため）。反時計回りに曲がりたいときは、`pointer` 命令で DP を直接回します（第9章）。白い領域を使って流れを導く方法は第8章で学びます。

## 5.5 プログラムを終了させる

Piet には「停止」という命令はありません。プログラムが終了するのは、5.3 節で見たように、**いまいるブロックからどの向きにも出られなくなったとき**だけです。したがって、プログラムの最後には、入ったら二度と出られないブロックを用意する必要があります。本書ではこれを**わな**と呼ぶことにします。

### 素朴なわなは失敗する

最後のブロックを黒で囲めばよい、と考えるのが自然です。次のプログラムは、5 を出力したあと、最後の淡マゼンタのコーデルの右と下を黒でふさいでいます（上は画像の端です）。

@piet ch05/naive caption="素朴なわな。終了せず 5 を出力し続ける" zoom=40

@grid ch05/naive

ところが、このプログラムは終了しません。トレースを見てみましょう（12 ステップで打ち切っています）。

@trace ch05/naive steps=12

淡マゼンタのブロックで、右（端ではなく黒）、下（黒）と試して失敗したあと、DP が左を向いた時点で、来た道である濃赤のブロックに戻れてしまうのです。左への移動でも命令は実行されます（淡マゼンタ → 濃赤は `multiply`、濃赤 → 赤は `pop` ですが、スタックが空なので何も起きません）。赤のブロックの左端は画像の端なので、ここでまた向きが変わって右に戻り、再び `push 5` と `out(number)` が実行されます。結果として、5 を延々と出力し続けます。

ブロックに入ってきた入り口は、逆向きに進もうとしたときの出口の候補になりえます。わなを作るには、**入り口のコーデルがどの向きの出口にも選ばれない**ようにしなければなりません。

### L 字形のわな

本書のサンプルで使っている、L 字形のわなを見てみましょう。第1章の最初のプログラムの最後の部分です。

@grid ch01/five

濃赤 (5,0) から右へ進むと、淡マゼンタの L 字形のブロック (6,0)・(5,1)・(6,1) に入ります。このブロックの 8 通りの出口を調べると、次のようになります。

| DP | 辺のコーデル | 出口（CC 左 / CC 右） | 進んだ先 |
|---|---|---|---|
| 右 | (6,0)・(6,1) | (6,0) / (6,1) | (7,0) 黒 / (7,1) 黒 |
| 下 | (5,1)・(6,1) | (6,1) / (5,1) | (6,2) 黒 / (5,2) 黒 |
| 左 | (5,1) | (5,1) / (5,1) | (4,1) 黒 |
| 上 | (6,0) | (6,0) / (6,0) | 画像の外 |

入り口の (6,0) の左隣は濃赤 (5,0) ですが、DP が左のとき、このブロックの最も左の列は x = 5 で、そこには (5,1) しかありません。(6,0) は左向きの出口に選ばれないのです。(5,1) の左は黒なので、左にも出られません。こうして 8 回の試行がすべて失敗し、プログラムは終了します。

このわなは 3 つのコーデルでできていて、最後の命令（この場合は `out(number)`）をわなへの移動そのもので実行できるので、無駄がありません。同じ考え方で、上向きに折れた L 字形のわなも作れます。

@piet ch05/trap_up caption="上向きの L 字形のわな" zoom=40

@grid ch05/trap_up

濃赤 (4,1) から入る淡マゼンタのブロックは (4,0)・(5,0)・(5,1) の L 字形で、入り口の (5,1) は、DP が左のときには最も左の列（x = 4）に入っていないため出口に選ばれません。

!!! tip "ヒント"
    わなを設計したら、8 通りの DP と CC の組み合わせについて出口と行き先を表にして確かめましょう。手作業が面倒なら、トレースで「8 回失敗して終了した」ことを確認するのが確実です。本書付属の piet.py のトレースでは、最後に「から出られない（8 回失敗）」と表示されます。

## 5.6 流れを追う手順のまとめ

ここまでの規則をまとめると、インタプリタの 1 ステップは次のようになります（白いブロックの扱いは第8章で補います）。

1. いまいるブロックについて、DP と CC から出口のコーデルを選ぶ。
2. 出口から DP の向きに 1 つ進んだ先を調べる。
3. 進んだ先が色ブロックなら、そのブロックに移り、色の変化に応じた命令を実行する。ステップ終了。
4. 進んだ先が黒か画像の外なら、CC の切り替えと DP の時計回りの回転を交互に行って 1 に戻る。8 回失敗したらプログラムを終了する。

この手順を紙の上で追えるようになれば、どんな Piet のプログラムでも動きを読み解けます。第16章では、この手順をそのまま Python のプログラムにしてインタプリタを作ります。

## まとめ

- 実行は左上のコーデルを含む色ブロックから始まる。DP の初期値は右、CC の初期値は左。
- 出口のコーデルは、DP の向きに最も遠い辺の中で、CC の向き（DP を向いたときの左手・右手）に最も遠いコーデル。
- 進んだ先が黒か画像の外なら、CC の切り替えと DP の時計回りの回転を交互に行って再試行する。変更した DP と CC はそのまま残る。
- 8 回とも失敗するとプログラムは終了する。終了させるには、入り口が出口に選ばれない形のブロック（L 字形のわななど）を黒で囲む。
- 端や黒に突き当たると、流れは時計回りに曲がる。
