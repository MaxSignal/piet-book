# 第8章 白と黒 ― 流れを導く

20 色のうち、白と黒の 2 色は特別です。どちらも命令を表す色ではありませんが、プログラムの流れを形づくるうえで欠かせない役割を持っています。白は命令を実行せずに通り抜けられる「通路」、黒は進入できない「壁」です。

この章では白と黒の規則を詳しく学び、それを使ってプログラムの流れを思いどおりに導く方法を身につけます。最後に、長い命令列を小さな正方形に折りたたむ「渦巻き」のプログラムを描きます。

!!! abstract "この章で学ぶこと"
    - 白ブロックの「滑走」の規則と、命令が実行されないこと
    - 白を通路として使い、命令の色をリセットする方法
    - 白の中で曲がる方法（黒と画像の端による時計回りの転回）
    - 2008 年の仕様の明確化と、npiet との違い
    - 黒と画像の端を使って、色ブロックの中で向きを変える方法

## 8.1 白ブロック ― 命令を実行しない通路

### 滑走の規則

DP が指す先が白いコーデルだった場合、インタプリタは白の中を DP の方向にまっすぐ進み続けます。これを**滑走**（slide）と呼びます。滑走は白でないコーデルに出会うまで続き、色のあるコーデルに着いたらそのブロックに移ります。

仕様の言葉では、白い色ブロックは「インタプリタが妨げられずに通り抜けられる自由な領域」です。そして重要なのは次の規則です。

> If the transition between colour blocks occurs via a slide across a white block, no command is executed.
> （白ブロックを滑って色ブロック間を移動した場合、命令は実行されない）

つまり白を挟むと、両側のブロックの色の差は意味を持たなくなります。

### 白が命令を「消す」ことを確かめる

次の 2 つのプログラムを比べてみましょう。1 つ目は 3 と 2 を積んで足し、和を出力します。

@piet ch08/nogap caption="3 と 2 を積んで足す（出力 5）"

2 つ目は、最初の淡赤のブロック（3 コーデル）と次の赤のブロックの間に 3 コーデルの白を挟んだものです。

@piet ch08/gap caption="間に白を挟む。push 3 が実行されず、出力は 2"

@trace ch08/gap

1 つ目では淡赤 → 赤の遷移で `push` が実行され 3 が積まれますが、2 つ目では白を滑って赤に着くため何も実行されません。そのあと赤（2 コーデル）から濃赤への `push` で 2 が積まれ、`add` はスタックに値が 1 つしかないので無視され、出力は 2 になります。

### 白は「色のリセット」

白を通り抜けた先のブロックは、どんな色でもかまいません。この性質は、プログラムを組み立てるうえで非常に便利です。

- **命令列の区切り**: 2 つの命令列を白でつなげば、前の列の最後の色と次の列の最初の色の関係を気にせずに済みます。
- **分岐した流れの合流**: 異なる経路から同じブロックに入るとき、経路ごとに直前の色が違っていても、白を通って入れば命令は実行されません（第9章）。
- **最初の push のための準備**: 前の命令の到着先ブロックは、次の `push` の値を決めてしまいます。白を挟めば、新しい列を好きな大きさのブロックから始められます。

第7章で見た pasm 製の Hello, World! は、命令の行を白い通路でつないでいました。各行の先頭のブロックはすべて淡赤から始まっていて、行と行の間では命令が実行されません。

## 8.2 白の中で曲がる

### 黒と端で止まると時計回りに曲がる

白の中を滑っている途中で、行く手に黒いコーデルか画像の端が現れた場合を考えます。2008 年 1 月 25 日に仕様に追加された「白ブロックの振る舞いの明確化」によると、このときインタプリタは次のように動きます。

1. CC を切り替え、DP を時計回りに 1 段階回す。
2. 新しい DP の方向に、再び白の中を滑る。
3. 色ブロックに着くまで、行き止まりのたびに 1. と 2. を繰り返す。
4. 白の中で自分の通った道をそのままたどり始めたら、抜け出す方法がないので停止する。

色ブロックの中で行き止まりになったときは、CC の切り替えと DP の回転を**交互に**試しました（第5章）。白の中では、行き止まりのたびに CC の切り替えと DP の回転を**両方同時に**行う点が異なります。その結果、白の中では行き止まりにぶつかるたびに必ず**時計回りに 90 度**曲がります。

### 曲がり角を作る

この規則を使えば、白い通路の好きな場所で流れを曲げられます。曲げたい場所の 1 つ先に黒を 1 つ置くだけです。Piet スタジオで白い通路と黒を描き、1 ステップずつ実行して DP の向きが変わる様子を確かめてみましょう。

@piet ch08/corner caption="白い通路を黒で曲げる。右に進んできた流れが下に曲がり、青のブロックに入る"

@grid ch08/corner

@trace ch08/corner

淡赤（5 コーデル）から赤への `push` で 5 を積んだあと、流れは赤の右の白に出て右へ滑ります。右上の黒にぶつかると DP が右から下に変わり、そのまま下へ滑って青のブロックに入ります。白を通って入ったので、ここでは命令は実行されません。最後に青 → 濃シアンの `out(number)` で 5 が出力されます。

### 時計回りしかできない

白の中の曲がり角は常に時計回りです。右に進んでいれば下へ、下に進んでいれば左へ、左なら上へ、上なら右へ曲がります。反時計回りに曲がりたいときは、次のどちらかの方法を使います。

- 黒を 3 つ使って時計回りに 3 回曲がる（右 → 下 → 左 → 上で、結果として右から上に曲がる）。
- `pointer` 命令で DP を直接回す（第9章）。

時計回りの曲がり角を 4 回続けると、流れは元の向きに戻ります。右 → 下 → 左 → 上 → 右という長方形の経路は、第10章で学ぶループの基本形になります。

!!! tip "ヒント"
    白い通路どうしは交差させてもかまいません。滑走はまっすぐ進むだけなので、横向きの通路を進む流れは、縦向きの通路を横切ってそのまま進みます。曲がる原因になるのは黒と画像の端だけです。交差点の近くに曲がり角用の黒を置かないようにすれば、通路を立体交差のように重ねられます。pasm はこの性質を使って、多数のジャンプを白い通路で配線しています（第17章）。

## 8.3 白の中での停止と、処理系の違い

### 白い袋小路

白の中で曲がり続けても色ブロックにたどり着けない場合、仕様は「自分の経路をたどり直し始めたら停止する」と定めています。次のプログラムは、3 を出力したあと白い袋小路に入り込みます。

@piet ch08/whitetrap caption="3 を出力したあと、白い袋小路に入る"

@grid ch08/whitetrap

濃マゼンタのブロックを出た流れは、白い通路を右へ滑り、黒にぶつかって下へ曲がります。下の端の黒で左へ曲がろうとしますが左も黒なので、さらに時計回りに回って上へ滑り、上の端で右へ、右の黒で下へ……と、縦の通路を往復し続けます。2 往復目に入ったところで「同じ位置・同じ DP・同じ CC」の状態が再び現れるため、仕様に従う処理系はここで停止します。

@trace ch08/whitetrap

### npiet の場合

npiet 1.3h の既定の動作は、仕様の明確化とは少し異なります。npiet は白の中で行き止まりにぶつかると、いったん「最後の白いコーデルにいる」状態でステップを終えます。次のステップでは、その白いコーデルから DP の方向を調べ、行き止まりなら CC と DP を同時に変えて最大 8 回まで試します。曲がる方向は仕様と同じなので、通常のプログラムでは同じように動きますが、**白の中の経路のたどり直しを検出しません**。

そのため、上のプログラムを npiet で実行すると、3 を出力したあと縦の通路を永遠に往復し続けます。

```text
$ npiet -q -e 1000 whitetrap.png
3error: configured execution steps exceeded (1000 steps)
```

`-e` は実行ステップ数の上限を指定するオプションです。npiet には古いバージョン 1.1 の動作を再現する `-v11` オプションがあり、こちらは経路のたどり直しを検出して停止します。

!!! warning "注意"
    白の中で停止させる書き方は、処理系によって結果が変わります。プログラムを止めるときは、白ではなく**色ブロックを黒で囲む**方法（第5章）を使いましょう。本書のプログラムもすべてこの方法で停止させています。

## 8.4 黒 ― 壁として使う

### 黒は進入できない

黒いコーデルは、画像の端と同じく「進めない場所」として扱われます。DP の先が黒なら、インタプリタはそこへは移らず、CC の切り替えと DP の回転を試します（第5章）。黒どうしがつながって大きな黒ブロックになっていても、意味は変わりません。

黒の主な使い道は次の 3 つです。

1. **停止**: 最後のブロックをすべての方向で黒（または端）に囲み、8 回の試行をすべて失敗させる。
2. **白の中での曲がり角**: 8.2 節のとおり。
3. **色ブロックの中での曲がり角**: 次に説明します。

### 色ブロックの中で曲がる

色ブロックの中で行き止まりになったときも、DP は時計回りに回ります。ただし色ブロックの場合は、最初に CC を切り替えて同じ DP のまま別の出口コーデルを試し、それでもだめなら DP を回す、という順序でした。1 列に並んだ帯の端のように出口コーデルが 1 つしかない場所なら、CC を切り替えても同じコーデルが選ばれるので、2 回目の試行で DP が時計回りに回ります。

次のプログラムでは、上の段の帯が画像の右端に突き当たったところで流れが下に曲がり、そのまま縦に並んだブロックへ進みます。

@piet ch08/wall caption="画像の右端で流れが下に曲がる（4 × 5 = 20 を出力）"

@grid ch08/wall

@trace ch08/wall

右上の濃赤のブロックは、右に進もうとして画像の端にぶつかり、CC を切り替えても進めないので DP を下に回します。下には黄のブロックがあるので、濃赤 → 黄の遷移で `multiply` が実行されます。白を通らずに曲がったので、曲がった直後の遷移でも命令が実行される点に注意してください。

最後のステップの `push 1` は、停止用のブロック（L 字形の淡赤）に入るときに実行される遷移です。停止用のブロックに入る遷移でも命令は実行されるので、このサンプルでは害のない `push` になるように色を選んでいます。

## 8.5 長い命令列を折りたたむ

### 渦巻き

色ブロックの中で曲がる方法を使うと、長い命令列を**折りたたんで**小さな四角形に収められます。命令列の帯を、外側から内側へ渦巻き状に並べ、帯以外の場所をすべて黒で埋めるのです。帯が端や黒にぶつかるたびに流れは時計回りに曲がり、帯に沿って内側へ進んでいきます。

@piet ch08/spiral caption="渦巻き状に折りたたんだプログラム。Piet と改行を出力する"

@grid ch08/spiral

このプログラムの命令列は次のとおりです。

```pasm
push 8, push 10, multiply, duplicate, out(char)        ; P (80)
push 5, push 5, multiply, add, duplicate, out(char)    ; i (105)
push 4, subtract, duplicate, out(char)                 ; e (101)
push 3, push 5, multiply, add, out(char)               ; t (116)
push 10, out(char)                                     ; 改行
```

1 列に並べると 70 コーデル近くになる帯が、12 × 12 の正方形に収まりました。渦巻きの外周から内側へ、ブロックが順に並んでいる様子を、色を目で追って確かめてみてください。内側の帯との間は 1 コーデル幅の黒で仕切られています。この仕切りがないと、外側の帯と内側の帯の色ブロックが隣り合い、流れが内側へ「近道」してしまいます。

### 曲がり角に大きなブロックを置くときの注意

渦巻きのように折りたたむときは、**複数コーデルのブロックが曲がり角をまたぐ**場合に注意が必要です。次のプログラムは、上と同じ命令列を 11 × 11 の渦巻きに並べたものです。

@piet ch08/spiral_bad caption="11 × 11 に並べた失敗例。Piet を出力したあと止まらなくなる"

このプログラムは `Piet` まで出力したあと、同じブロックの間を行ったり来たりして止まらなくなります。原因は、改行のための 10 コーデルのブロックが、内側の帯の左下の角をまたいで L 字形になっていることです。流れは左向きにこのブロックへ入りますが、L 字の先端（上向きの部分）から出るには DP が上を向く必要があります。ところがブロックの出口は「DP の方向に最も遠い辺」で決まるため、DP が上なら上端の 1 コーデルからしか出られず、そこは黒でふさがれています。何度か向きを変えた末に DP が右になると、ブロックの右端、つまり入ってきたコーデルから外に出て、直前のブロックへ逆戻りしてしまうのです。

大きなブロックが角をまたぐと、出口のコーデルが直感とずれることがあります。こうした問題は、

- 角に来るブロックが 1 コーデルになるように命令の位置をずらす
- 渦巻きの大きさを変える

といった方法で避けられます。正しく動いた 12 × 12 の渦巻きは、後者の方法で大きさを選んだものです。いずれの場合も、トレースで流れを確かめることが大切です（第19章）。

!!! column "コラム: 折りたたみと絵画"
    渦巻きは、命令列を折りたたむ方法の 1 つにすぎません。ジグザグ、迷路のような通路、白い余白をたっぷり取った配置など、Piet のプログラムの形は自由です。命令の色の制約を守りつつ、どこで曲がり、どこを黒で埋め、どこに白を置くかを決めていく作業は、パズルであり、同時に絵を描く作業でもあります。第15章では、こうした配置をデザインとして考えます。

## まとめ

- 白に入ると DP の方向にまっすぐ滑走し、白を通った遷移では命令が実行されない。
- 白を挟むと前後のブロックの色の関係がなくなるので、命令列の区切りや合流に使える。
- 白の中で黒や端にぶつかると、CC を切り替えて DP を時計回りに回す。白の中の曲がり角は常に時計回り。
- 仕様では、白の中で同じ経路をたどり始めたら停止する。npiet はこれを検出しないので、白で停止させる書き方は避ける。
- 黒は進入できない壁。停止、白の中での曲がり角、色ブロックの中での曲がり角に使う。
- 帯を渦巻き状に並べて黒で埋めると、長い命令列を小さく折りたためる。角をまたぐ大きなブロックには注意する。

## 練習問題

1. 右に滑走中の流れが黒にぶつかったあと、DP はどちらを向きますか。さらにもう一度黒にぶつかったらどうなりますか。
2. 次の命令列を実行するプログラムを、途中に白い通路と曲がり角を 1 つ入れて描いてください。「7 を積む、`out(number)`」。流れは右に進んでから下に曲がり、曲がった先で `out(number)` を実行すること。
3. 図「間に白を挟む」のプログラムで、白の部分を淡赤で塗りつぶしたら出力はどうなりますか。実際に試して確かめてください。
4. 上の段を右に進み、右端で下に曲がり、下の段を左に進むプログラムを描いてください。上の段で 6 と 7 を積み、曲がった直後に `multiply`、下の段で `out(number)` を実行して 42 を出力すること。
