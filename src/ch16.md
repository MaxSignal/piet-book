# 第16章 Piet インタプリタを作る

ここからは第IV部です。これまでは Piet のプログラムを「書く」側に立ってきましたが、第IV部では Piet を「処理する」側に回ります。最初に作るのは、Piet の画像を読み込んで実行するインタプリタです。

インタプリタを自分で書くと、仕様の細部がはっきり見えてきます。出口のコーデルはどう選ばれるのか、黒にぶつかったとき DP と CC はどの順で変わるのか、白い領域を滑っている途中で止まったらどうするのか。どれも、コードにしようとした瞬間にあいまいなままでは済まなくなります。本章では、本書のサンプルの検証に使っている `tools/piet.py` を題材に、約 490 行のインタプリタを順番に組み立てていきます。

!!! abstract "この章で学ぶこと"
    - Piet のプログラムをデータとして表す方法（コーデルの格子と、色相・明度の組）
    - 画像の読み込みとコーデルサイズの推定
    - 色ブロックの検出（塗りつぶしアルゴリズム）と出口コーデルの選び方
    - 1 ステップの実行: 8 回の試行、白ブロックの滑走と「同じ経路の再走査」による停止
    - 命令の実行と、実行できない命令の扱い、トレースの出力
    - 別の処理系と結果を突き合わせる差分テスト

## 16.1 全体の設計

インタプリタは、大きく 3 つの部品に分かれます。

| 部品 | 役割 | piet.py での名前 |
|---|---|---|
| プログラム | コーデルの格子を保持し、色ブロックを求める | `Program` クラス |
| 実行機械 | 位置・DP・CC・スタック・入出力を持ち、1 ステップずつ進める | `Machine` クラス |
| 補助関数 | 色の差から命令を求める、出口コーデルを選ぶ | `command_between()`、`exit_codel()` |

実行の主役は `Machine.step()` です。1 回の `step()` で「今いる色ブロックから次の色ブロックへ 1 回移る」ところまでを行い、その移動に対応する命令を実行します。プログラムが停止したら `False` を返します。`run()` は `step()` を繰り返すだけです。

```python
def run(self, max_steps=1_000_000):
    while self.steps < max_steps and self.step():
        pass
    return "".join(self.out)
```

`max_steps` は無限ループに備えた安全装置です。npiet の `-e` オプションと同じ役割をします。

## 16.2 色の表現

Piet の 20 色は、色相 6 種 × 明度 3 種の 18 色と、白・黒です。命令は「色相がいくつ進んだか」と「明度がいくつ進んだか」で決まる（[第4章](ch04.html)）ので、色は RGB 値のままではなく **(色相, 明度) の組** で持つのが自然です。

```python
HUES = ["red", "yellow", "green", "cyan", "blue", "magenta"]
LIGHTS = ["light", "normal", "dark"]
RGB = {
    (0, 0): 0xFFC0C0, (1, 0): 0xFFFFC0, ...   # 淡い 6 色
    (0, 1): 0xFF0000, (1, 1): 0xFFFF00, ...   # 通常の 6 色
    (0, 2): 0xC00000, (1, 2): 0xC0C000, ...   # 濃い 6 色
}
WHITE, BLACK = "W", "K"
```

色相の番号は赤 0、黄 1、緑 2、シアン 3、青 4、マゼンタ 5、明度の番号は淡い 0、通常 1、濃い 2 です。こうしておけば、どちらの循環も「差を取って 6 または 3 で割った余り」で計算できます。白と黒は循環の外にあるので、組ではなく特別な値 `"W"` と `"K"` にしました。

命令の表は、色相の差と明度の差で引ける 2 次元のリストにします。

```python
CMDS = [
    [None, "push", "pop"],
    ["add", "subtract", "multiply"],
    ["divide", "mod", "not"],
    ["greater", "pointer", "switch"],
    ["duplicate", "roll", "in_number"],
    ["in_char", "out_number", "out_char"],
]

def command_between(a, b):
    """色 a のブロックから色 b のブロックへ移ったときの命令名"""
    dh = (b[0] - a[0]) % 6
    dl = (b[1] - a[1]) % 3
    return CMDS[dh][dl]
```

Python の `%` は、左辺が負でも 0 以上の値を返します。`(b[0] - a[0]) % 6` と書くだけで「赤から見たマゼンタは 5 段先」が正しく求まります。C 言語で同じことを書くときは、負の余りにならないよう `+ 6` してから割るのが定石です。npiet のソースも `((get_hue (a_col) - get_hue (c_col)) + n_hue) % n_hue` と書いています。

`CMDS[0][0]` が `None` なのは、色相も明度も変わらない移動は同じ色のブロックの中の移動であり、命令が存在しないからです。

## 16.3 画像の読み込みとコーデルサイズ

プログラムは画像ファイルとして与えられます。画像処理には Pillow（`PIL`）を使い、1 ピクセルずつ RGB 値を調べて色に直します。

```python
@staticmethod
def from_image(path, codel_size=None, unknown="white"):
    from PIL import Image
    im = Image.open(path).convert("RGB")
    W, H = im.size
    px = im.load()
    if codel_size is None:
        codel_size = guess_codel_size(im)
    w, h = W // codel_size, H // codel_size
    grid = []
    for y in range(h):
        row = []
        for x in range(w):
            r, g, b = px[x * codel_size, y * codel_size]
            v = (r << 16) | (g << 8) | b
            c = RGB2COL.get(v)
            if c is None:
                c = WHITE if unknown == "white" else BLACK
            row.append(c)
        grid.append(row)
    return Program(grid)
```

ポイントは 2 つあります。

1 つめは **コーデルサイズ** です。サンプル画像の多くは、見やすいように 1 コーデルを 10×10 ピクセルなどに拡大して保存されています。拡大されたままピクセル単位で実行すると、ブロックの大きさ（コーデル数）が 100 倍になり、`push` の値が狂います。そこで、コーデルの左上のピクセルだけを読んで、コーデル単位の格子に縮めます。

2 つめは **規定外の色** です。仕様は、20 色以外の色の扱いを処理系に任せています。最も単純なのは白とみなすことで、npiet も既定では白として扱います（`-ub` で黒、`-uu` でエラー）。piet.py も引数 `unknown` で選べるようにしました。

コーデルサイズが指定されなかったときは推定します。考え方は「同じ色が横や縦に続く長さの最大公約数」です。

```python
def guess_codel_size(im):
    W, H = im.size
    px = im.load()
    g = 0
    for y in range(H):
        run = 1
        for x in range(1, W + 1):
            if x < W and px[x, y] == px[x - 1, y]:
                run += 1
            else:
                g = math.gcd(g, run)
                run = 1
                if g == 1:
                    return 1
    ...（縦方向も同様）
    return g or 1
```

すべての連続の長さがたとえば 10 の倍数なら、コーデルサイズは 10 と推定されます。ただし、これはあくまで推定です。コーデルサイズ 10 の画像でも、たまたますべての色の連続が 2 コーデル以上だと 20 と推定され、プログラムの意味が変わってしまいます。確実に実行したいときは、npiet の `-cs` や piet.py の `-cs` で明示しましょう。

!!! note "npiet の推定方法"
    npiet も、行と列を走査して最も短い同色の連続をコーデルサイズとみなします。画像の幅や高さがその値で割り切れなければエラーで終了します。推定の結果が処理系ごとに違うこともあり得るので、本書のサンプルはコーデルサイズ 1 の画像を正本とし、拡大版（`-big.png`）はコーデルサイズ 10 で保存しています。

本書では画像のほかに、1 コーデルを 1 文字で表す **テキスト格子**（[付録B](appB.html)）も読み込めるようにしています。`Program.from_text()` が文字を色に直すだけの単純な関数です。テストを書くときにはこちらのほうが手軽です。

## 16.4 色ブロックを求める

Piet の命令は「ブロックからブロックへ」の移動で決まり、`push` の値はブロックのコーデル数です。したがってインタプリタは、あるコーデルがどの色ブロックに属しているかを、すぐに答えられなければなりません。

色ブロックは、同じ色のコーデルが上下左右（4 近傍）でつながった集まりです。斜めはつながりとみなしません。これはグラフ理論の連結成分そのものなので、塗りつぶし（flood fill）で求めます。

```python
def block(self, x, y):
    """(x, y) を含む色ブロックのコーデル集合（4 近傍の連結成分）"""
    key = (x, y)
    if key in self._blocks:
        return self._blocks[key]
    c = self.grid[y][x]
    seen = {key}
    todo = [key]
    while todo:
        cx, cy = todo.pop()
        for nx, ny in ((cx + 1, cy), (cx - 1, cy), (cx, cy + 1), (cx, cy - 1)):
            if (nx, ny) not in seen and self.color(nx, ny) == c:
                seen.add((nx, ny))
                todo.append((nx, ny))
    fs = frozenset(seen)
    for p in fs:
        self._blocks[p] = fs
    return fs
```

再帰ではなく、明示的なスタック `todo` を使っているのは、大きなブロックで Python の再帰の深さ制限に引っかからないようにするためです。また、一度求めたブロックはそのブロックに属するすべてのコーデルについて記録（メモ化）します。ループを何千回も回るプログラムでは、同じブロックを何度も訪れるので、この工夫で大きく速くなります。

`self.color(x, y)` は、画像の外を指したときに `None` を返します。`None` はどの色とも等しくないので、塗りつぶしは自然に画像の端で止まります。

## 16.5 出口のコーデルを選ぶ

ブロックから出るときの規則（[第5章](ch05.html)）は次の 2 段階でした。

1. ブロックの縁のうち、DP の方向に最も遠い縁を選ぶ。
2. その縁の上で、CC の方向に最も遠いコーデルを選ぶ。

CC の「左」「右」は、DP の向きに立ったときの左右です。たとえば DP が下向きなら、進行方向（下）を向いた人にとって左は画面の右（x が大きい側）です。この対応を表にしておきます。

| DP | 縁 | CC が左のとき | CC が右のとき |
|---|---|---|---|
| 右 | x が最大の列 | y が最小（上端） | y が最大（下端） |
| 下 | y が最大の行 | x が最大（右端） | x が最小（左端） |
| 左 | x が最小の列 | y が最大（下端） | y が最小（上端） |
| 上 | y が最小の行 | x が最小（左端） | x が最大（右端） |

これをそのままコードにします。

```python
DP_VEC = [(1, 0), (0, 1), (-1, 0), (0, -1)]   # 右, 下, 左, 上 (時計回り)

def exit_codel(block, dp, cc):
    if dp == 0:   # 右
        m = max(x for x, y in block)
        edge = [(x, y) for x, y in block if x == m]
        return min(edge, key=lambda p: p[1]) if cc == 0 else max(edge, key=lambda p: p[1])
    if dp == 1:   # 下
        m = max(y for x, y in block)
        edge = [(x, y) for x, y in block if y == m]
        return max(edge, key=lambda p: p[0]) if cc == 0 else min(edge, key=lambda p: p[0])
    ...（左・上も同様）
```

DP を 0〜3 の整数（右・下・左・上の時計回り）で表しておくと、「時計回りに 1 つ回す」は `(dp + 1) % 4`、`pointer` 命令の「n 回回す」は `(dp + n) % 4` で書けます。CC は 0（左）と 1（右）で表し、切り替えは `cc ^= 1` です。

縁の上のコーデルは連続しているとは限りません。凹んだ形のブロックでは、縁が途中で途切れることもあります。それでも「最も遠いもの」を選ぶ規則は変わらないので、上のコードは形によらず正しく動きます。

## 16.6 1 ステップの実行

いよいよ心臓部の `step()` です。まずは、白ブロックを考えない部分を見ましょう（本章のリストは、トレース出力の部分を省いて簡略化しています。完全なコードは `tools/piet.py` を見てください）。

```python
def step(self):
    if self.halted:
        return False
    p = self.p
    cur = p.color(self.x, self.y)
    if cur == WHITE:
        return self._slide(self.x, self.y, None)
    block = p.block(self.x, self.y)
    for attempt in range(8):
        ex, ey = exit_codel(block, self.dp, self.cc)
        dx, dy = DP_VEC[self.dp]
        nx, ny = ex + dx, ey + dy
        nc = p.color(nx, ny)
        if nc is not None and nc != BLACK:
            if nc == WHITE:
                return self._slide(nx, ny, cur)
            cmd = command_between(cur, nc)
            res = self.execute(cmd, len(block))
            self.steps += 1
            self.x, self.y = nx, ny
            return True
        if attempt % 2 == 0:
            self.cc ^= 1
        else:
            self.dp = (self.dp + 1) % 4
    self.halted = True
    return False
```

仕様の文章とコードがほぼ 1 対 1 で対応していることを確かめてください。

- 出口のコーデルから DP の方向に 1 つ進んだ先 `(nx, ny)` を調べる。
- 画像の外（`None`）か黒なら「止められた」ことになり、CC を切り替えて再挑戦する。もう一度失敗したら DP を時計回りに回す。これを交互に繰り返す。
- 8 回とも失敗したら停止する。
- 進めたら、2 つのブロックの色の差から命令を求めて実行し、位置を移す。

`execute()` に渡す `len(block)` は、出ていくブロックの大きさです。`push` はこの値を積みます。「出ていくブロック」の大きさであって、入っていくブロックではないことに注意してください。

試行の順番は「CC → DP → CC → DP …」です。`attempt` が偶数のときに CC、奇数のときに DP を変えるので、8 回の試行で DP は 4 方向すべてを、それぞれ CC の左右両方で試すことになります。

## 16.7 白ブロックを滑る

白は「命令を実行せずに通り抜ける」領域です。白に入ったインタプリタは、DP の方向にまっすぐ滑っていき、色のついたコーデルに当たればそこへ移ります（命令は実行しません）。

難しいのは、滑っている途中で黒や画像の端にぶつかった場合です。仕様は 2008 年 1 月 25 日に「白ブロックの振る舞いの明確化」を追記し、次のように定めました。

- 白の中で止められたら、CC を切り替え、**同時に** DP を時計回りに 1 つ回して、その方向へ滑り直す。
- 白の中で、同じ経路をもう一度たどり始めたら、白から出る道はないので実行を終了する。

色ブロックでは「CC、DP を交互に変える」のに対し、白の中では「両方を一度に変える」点が違います。白には「縁」や「出口コーデル」がないので、CC はどのみち意味を持ちません。

「同じ経路をたどり始めた」ことは、止められた地点の状態 (x, y, DP, CC) を記録しておき、同じ状態が再び現れたかどうかで判定します。

```python
def _slide(self, x, y, frm):
    """白い領域を DP 方向に滑る（2008 年の仕様明確化に従う）"""
    p = self.p
    seen = set()
    while True:
        dx, dy = DP_VEC[self.dp]
        while p.color(x + dx, y + dy) == WHITE:
            x, y = x + dx, y + dy
        nc = p.color(x + dx, y + dy)
        if nc is not None and nc != BLACK:
            self.x, self.y = x + dx, y + dy
            self.steps += 1
            return True
        state = (x, y, self.dp, self.cc)
        if state in seen:
            self.halted = True
            return False
        seen.add(state)
        self.cc ^= 1
        self.dp = (self.dp + 1) % 4
```

状態が有限個（白いコーデルの数 × 4 × 2）しかないので、この判定は必ずどこかで決着します。次のプログラムで確かめてみましょう。5 を出力したあと、右側の白い「回廊」に入ります。回廊は黒で囲まれていて、右 → 下 → 左 → 上 → 右……と時計回りに回り続けるしかありません。

## 16.8 命令の実行

命令の実行は、大きな `if` の連鎖です。全体の方針は仕様の一文に従います。

> 実行できない操作（スタックに十分な値がないときの取り出しなど）は無視し、次の命令に進む。

piet.py ではこれを「スタックを一切変えずに戻る」と解釈しています。

```python
def execute(self, cmd, size):
    st = self.stack
    if cmd == "push":
        st.append(size)
    elif cmd == "pop":
        if not st:
            return "ignored"
        st.pop()
    elif cmd in ("add", "subtract", "multiply", "divide", "mod", "greater"):
        if len(st) < 2:
            return "ignored"
        a, b = st[-2], st[-1]
        if cmd in ("divide", "mod") and b == 0:
            return "ignored"
        st.pop(); st.pop()
        st.append({"add": lambda: a + b, "subtract": lambda: a - b,
                   "multiply": lambda: a * b, "divide": lambda: a // b,
                   "mod": lambda: a % b,
                   "greater": lambda: 1 if a > b else 0}[cmd]())
    ...
```

2 項演算では、`a` が 2 番目（先に積まれた値）、`b` が先頭です。`subtract` は `a - b`、`greater` は「a が b より大きいか」です。順序を逆にするのは、インタプリタ作りでいちばんありがちな誤りです。

ここで、仕様が処理系に任せている点について piet.py の選択を明記しておきます。

| 項目 | piet.py の動作 | 理由 |
|---|---|---|
| `divide` の丸め | 床関数（負の無限大の方向へ丸める） | `mod` を仕様どおり「除数と同じ符号」にすると、それと整合するのは床除算 |
| 0 による `divide`・`mod` | 無視（スタックはそのまま） | 仕様が推奨する動作 |
| 負の深さの `roll` | 無視（2 つの値も取り出さない） | 仕様が「エラーとして無視」と定める |
| 整数の大きさ | 制限なし（Python の整数） | 仕様は「概念上は無制限」 |
| `in(char)` | 1 文字（Unicode の符号位置）を読む | 仕様は文字を Unicode として扱う |

`roll` の実装はスライスで書けます。深さ `depth` の部分を取り出し、`n` 回の回転をまとめて行います。

```python
elif cmd == "roll":
    if len(st) < 2:
        return "ignored"
    depth, n = st[-2], st[-1]
    if depth < 0 or depth > len(st) - 2:
        return "ignored"
    st.pop(); st.pop()
    if depth > 0:
        n %= depth
        if n:
            seg = st[-depth:]
            st[-depth:] = seg[-n:] + seg[:-n]
```

1 回の roll は「先頭の値を depth の深さへ沈める」操作なので、`n` 回の roll は、長さ `depth` の区間を右に `n` だけ回転させるのと同じです。負の回数は逆回転ですが、`n %= depth` で正の回数に直せます（深さ 3 で -1 回は、+2 回と同じ）。

`pointer` と `switch` も同じ考え方で 1 行ずつです。

```python
elif cmd == "pointer":
    if not st:
        return "ignored"
    self.dp = (self.dp + st.pop()) % 4
elif cmd == "switch":
    if not st:
        return "ignored"
    self.cc = (self.cc + abs(st.pop())) % 2
```

`pointer` に負の値を与えると反時計回りになりますが、`% 4` が 0〜3 に直してくれるので特別扱いは要りません。`switch` は仕様どおり絶対値の回数だけ切り替えます。

## 16.9 入力と出力

入力は文字列としてまとめて受け取り、読み出し位置 `ipos` を進めながら使います。`in(number)` は空白を読み飛ばしてから、符号付きの整数を読みます。

```python
def read_number(self):
    s = self.inp
    i = self.ipos
    while i < len(s) and s[i].isspace():
        i += 1
    j = i
    if j < len(s) and s[j] in "+-":
        j += 1
    k = j
    while k < len(s) and s[k].isdigit():
        k += 1
    if k == j:
        return None          # 整数が読めない → 命令は無視
    self.ipos = k
    return int(s[i:k])
```

仕様は「入力が待っていなければエラーとして命令を無視する」「整数を読もうとして整数が来なければ無視する」と定めています。読めなかったときに `None` を返し、`execute()` がそれを見て何も積まずに戻る、という形でこれを実現しています。

出力は文字列のリスト `self.out` にためておき、最後にまとめて返します。`out(char)` は `chr()` で Unicode の文字にします。範囲外の値（負の数や 0x110000 以上）は `chr()` が例外を投げるので、先に先頭の値で `chr()` を試し、失敗したら値をスタックに残したまま無視します。ほかの命令と同じく、無視した命令はスタックを変えません。

## 16.10 トレース

デバッグのためには、各ステップで何が起きたかを表示できると便利です。piet.py の `-t` オプションは、ステップごとに 1 行のログを標準エラー出力に書きます。

```text
step 1: 淡赤(3) → 赤  push 3  stack=[3]
```

この行には、出ていくブロックの色と大きさ、入るブロックの色、実行した命令、実行後のスタックが含まれます。DP や CC が変わったときはその値も付け加えます。白を滑ったステップ、無視された命令、黒や画像の端に止められた試行（そのとき CC と DP をどう変えたか）、停止の理由も記録します。トレースの読み方と活用法は[第19章](ch19.html)で詳しく扱います。

コマンドラインからは次のように使います。

```sh
python3 tools/piet.py run -t site/img/ch16/test_add.png < /dev/null
```

## 16.11 差分テスト ― 別の処理系と突き合わせる

インタプリタができたら、正しく動くことを確かめなければなりません。ここで役に立つのが **差分テスト**（differential testing）です。同じプログラムを 2 つの独立した処理系で実行し、出力を比べます。食い違えば、少なくともどちらかに誤りがあります。

本書では npiet を比較相手にしています。`tools/samples.py` は、本書のすべてのサンプルについて次のことを行います。

1. サンプルのソース（テキスト格子・アセンブリ・Mini 言語）から PNG 画像を作る。
2. 入力ファイル（`.in`）を与えて piet.py で実行する。
3. 同じ画像と入力で npiet を実行する。
4. 両者の出力が一致するか、期待される出力（`.out`）と一致するかを調べる。

```sh
$ python3 tools/samples.py ch16
ok  ch16/test_add (8x3, 4 steps) out='7'
ok  ch16/whiteloop (12x5, 2 steps) out='5'
--- 2 ok, 0 NG
```

`whiteloop` は npiet では止まらないので、比較を省く印（`.flags` ファイルに `nonpiet`）を付けています。このように、仕様の解釈が分かれる箇所は「意図的な差」として記録し、それ以外はすべて一致することを確かめます。

本書の執筆にあたっては、npiet に付属する例題や、Piet の公式サイトのサンプル集（Hello World の数々、円周率を計算するプログラム、99 Bottles of Beer、エラトステネスのふるい、FizzBuzz など約 20 本）でも差分テストを行いました。無限ループするように作られた作品を除き、出力は npiet と一致しました。ただし、npiet は `-q` を付けないと入力のたびに `? ` というプロンプトを出力するので、比較するときは必ず `-q` を付けます。また、npiet は標準出力をバッファリングするので、無限ループするプログラムを `timeout` で強制終了すると、それまでの出力が失われることがあります。比較には `-e` でステップ数を制限するほうが確実です。

!!! tip "差分テストの相手を選ぶ"
    差分テストの価値は、相手が「独立に書かれている」ことにあります。同じ人が同じ思い込みで書いた 2 つの実装は、同じ誤りを共有しがちです。npiet のように長く使われてきた処理系は、比較相手として信頼できます。一方で、npiet にも仕様と異なる部分があるので（[付録C](appC.html)）、食い違ったときは必ず仕様の原文に立ち返りましょう。

## 16.12 Piet スタジオとブラウザ版ビューア

本書の Piet スタジオ（[第2章](ch02.html)）は、本章の `Machine` クラスをそのまま使っています。プログラムを読み込むか描き換えるたびに `Machine(prog, inp, trace=True)` で実行機械を作り直し、「1 ステップ」ボタンでは `step()` を 1 回、「実行」では停止するかブレークポイントに達するまで `step()` を繰り返し呼びます。画面に表示される位置・DP・CC・スタックは `Machine` の属性 `x`・`y`・`dp`・`cc`・`stack` を、トレースの欄は `log` に溜まった行を、そのまま表示したものです。インタプリタを「状態を持つオブジェクト」と「1 ステップ進めるメソッド」に分けておいたことで、コマンドライン、テスト（`samples.py`）、GUI の 3 つが同じ実装を共有できているわけです。

### ブラウザ版ビューア

本書の Web 版では、図に「実行」「ステップ」のボタンが付いていて、ブラウザの中でプログラムを動かせます。これは JavaScript で書かれたインタプリタで動いています。中身の設計は本章の piet.py と同じです。画像を読み込んでコーデルの格子に直し、色ブロックを塗りつぶしで求め、`step()` で 1 回ずつ遷移します。ステップ実行で現在のブロックが強調表示されるのは、`step()` の前後の位置と DP・CC をそのまま画面に描いているからです。



## まとめ

- Piet の色は (色相, 明度) の組で表すと、命令を「差の余り」で求められる。
- 画像はコーデルサイズで縮めて格子にする。コーデルサイズの推定は万能ではないので、可能なら明示する。
- 色ブロックは 4 近傍の連結成分であり、塗りつぶしで求めてメモ化する。
- 出口コーデルは「DP 方向の縁」→「CC 方向の端」の 2 段階で選ぶ。CC の左右は DP の向きから見た左右である。
- 色ブロックで止められたら CC と DP を交互に変え、8 回失敗したら停止する。白の中では両方を同時に変え、同じ状態を再び通ったら停止する。
- 実行できない命令は無視する。仕様が任せている部分（除算の丸めなど）は、方針を決めて文書にしておく。
- 差分テストで別の処理系と突き合わせると、実装の誤りを効率よく見つけられる。

## 練習問題

1. 画像の中に 20 色以外の色があったとき、黒として扱うオプション（npiet の `-ub` に相当）を piet.py のコマンドラインに追加してください。
2. 実行中に各命令が何回実行されたかを数え、終了時に回数の多い順に表示する機能を追加してください。
3. npiet と同じ結果になるよう、`divide` と `mod` を「0 の方向へ丸める」（C 言語と同じ）方式に切り替えるオプションを追加してください。−7 を 2 で割った商と、−7 を 3 で割った余りは、それぞれどうなりますか。
4. 16.5 節の表で、DP が下向きで CC が左のとき x が最大のコーデルを選ぶのはなぜですか。進行方向を向いた人の左右という考え方で説明してください。
5. 入力を使わないプログラムでは、ある時点の「位置・DP・CC・スタックの内容」がそれ以前のある時点と完全に一致したら、そのプログラムは決して停止しません。その理由を説明し、この判定で無限ループを検出する機能を piet.py に追加してください。この方法で検出できない無限ループの例も挙げてください。
