# 第4章 命令は色の変化で決まる

第3章で、Piet の 18 色が色相と明度の 2 つの環の上に並んでいることを学びました。この章では、その 2 つの環を使って命令がどのように表されるかを説明します。Piet では、色そのものには意味がありません。意味を持つのは、ある色ブロックから次の色ブロックへ移るときの**色の変化**です。命令表の読み方と、逆に「この命令を実行したいときに次の色を何色にすればよいか」を求める手順を身につけ、簡単な計算プログラムを手で設計してみましょう。

!!! abstract "この章で学ぶこと"
    - 色相の差と明度の差の組み合わせで 17 個の命令が決まること
    - 2 つの色から命令を求める方法と、命令から次の色を求める方法
    - 同じ命令を表す色の組が 18 通りあること
    - 17 個の命令の概要
    - 直線状のプログラムを手で設計する手順

## 4.1 色ではなく、色の変化

普通のプログラミング言語では、`add` や `print` のような単語が命令を表します。Piet で単語の代わりになるのは、隣り合う 2 つの色ブロックの**色の違い**です。

インタプリタは、いまいる色ブロック（移動元）から隣の色ブロック（移動先）へ移るとき、次の 2 つの値を計算します。

- **色相の差**: 移動元から移動先まで、色相の環（赤 → 黄 → 緑 → シアン → 青 → マゼンタ → 赤）を何段階進んだか（0〜5）
- **明度の差**: 移動元から移動先まで、明度の環（淡い → 通常 → 濃い → 淡い）を何段階進んだか（0〜2）

この 2 つの値の組み合わせで、実行する命令が決まります。たとえば第1章の最初のプログラムでは、赤から濃赤への移動が `push` でした。赤と濃赤は色相が同じ（差 0）で、明度が通常から濃いへ 1 段階進んでいます（差 1）。「色相の差 0、明度の差 1」が `push` を表すのです。

ここで大事なのは、**赤や濃赤という色そのものには意味がない**ことです。黄から濃黄へ移っても、淡青から青へ移っても、「色相の差 0、明度の差 1」なので同じ `push` が実行されます。

表の並びにはある程度の規則があります。

- 色相の差 0 の行は、スタックに値を出し入れする基本操作（`push` と `pop`）
- 色相の差 1〜2 の行は算術演算と論理否定（`add` `subtract` `multiply` `divide` `mod` `not`）
- 色相の差 3 の行は比較と、流れを変える命令（`greater` `pointer` `switch`）
- 色相の差 4〜5 の行はスタック操作と入出力（`duplicate` `roll` `in` `out`）

`in` と `out` には、数を扱うもの（`in(number)` と `out(number)`）と、文字を扱うもの（`in(char)` と `out(char)`）の 2 種類があります。

## 4.3 2 つの色から命令を求める

移動元と移動先の色がわかれば、命令は次の手順で求められます。

1. 色相に番号を付ける（赤 0・黄 1・緑 2・シアン 3・青 4・マゼンタ 5）。
2. 明度に番号を付ける（淡い 0・通常 1・濃い 2）。
3. 色相の差 = （移動先の色相 − 移動元の色相）を 6 で割った余り（0〜5）
4. 明度の差 = （移動先の明度 − 移動元の明度）を 3 で割った余り（0〜2）
5. 命令表の該当するマスを見る。

最初のプログラムの 2 つ目の移動、濃赤 → 淡マゼンタを計算してみましょう。

| | 移動元: 濃赤 | 移動先: 淡マゼンタ | 差 |
|---|---|---|---|
| 色相 | 赤 = 0 | マゼンタ = 5 | (5 − 0) mod 6 = **5** |
| 明度 | 濃い = 2 | 淡い = 0 | (0 − 2) mod 3 = **1** |

色相の差 5・明度の差 1 は、命令表で `out(number)` です。たしかに、最初のプログラムは 2 つ目の移動で数を出力していました。

もう一つ、淡黄 → 赤を計算してみます。色相は黄（1）→ 赤（0）で (0 − 1) mod 6 = 5、明度は淡い（0）→ 通常（1）で 1 です。これも `out(number)` です。色はまったく違うのに、同じ命令になりました。

!!! tip "ヒント"
    負の数の余りに慣れていなければ、「足りないときは 6（明度なら 3）を足す」と考えてください。(0 − 2) = −2 なら、3 を足して 1 です。あるいは、環の上を指でたどって、移動元から移動先まで一方向に何歩進むかを数えても構いません。

## 4.4 同じ命令を表す色の組

前節で見たように、一つの命令を表す色の組は一つではありません。移動元の色は 18 通りあり、どの色から出発しても、色相と明度を決まった段階だけ進めた色が一つだけ決まります。つまり、**どの命令も 18 通りの色の組で表せます**。

次の 2 つのプログラムは、色はまったく違いますが、同じ命令の列（2 を積む、3 を積む、足す、数を出力する）を実行し、どちらも 5 を出力します。

@piet ch04/add23b caption="同じ計算を淡青から始めたもの" zoom=40

1 つ目は赤・濃赤・淡赤・淡黄・赤、2 つ目は淡青・青・濃青・濃マゼンタ・淡青という色の並びです。どちらも、隣り合うブロックの色相と明度の差の並びは同じです。

この性質のおかげで、Piet のプログラムはかなり自由に色を選べます。出発点の色を変えれば、命令の意味を保ったまま全体の色合いを変えられます。命令の列は同じでも、赤っぽいプログラムにも青っぽいプログラムにもできるのです。

## 4.5 命令から次の色を求める

プログラムを**書く**ときには、逆向きの計算が必要になります。いまの色と実行したい命令がわかっているとき、次のブロックを何色にすればよいかを求めるのです。

これは 4.3 節の逆で、命令表から色相の差と明度の差を読み取り、いまの色の色相と明度にそれぞれ足すだけです。

1. 命令表で、実行したい命令の色相の差 h と明度の差 l を調べる。
2. 次の色の色相 = （いまの色相 + h）を 6 で割った余り
3. 次の色の明度 = （いまの明度 + l）を 3 で割った余り

たとえば、淡赤（色相 0、明度 0）のブロックの次に `add`（h = 1、l = 0）を実行したいなら、次の色は色相 1・明度 0、つまり淡黄です。淡黄の次に `out(number)`（h = 5、l = 1）を実行したいなら、色相 (1 + 5) mod 6 = 0、明度 (0 + 1) mod 3 = 1 で、赤です。

慣れるまでは、付録B の早見表（「いまの色」と「命令」から「次の色」を引ける表）を使うと便利です。

## 4.6 17 個の命令の概要

ここで、17 個の命令を一通り眺めておきましょう。詳しい使い方は、それぞれ後の章で説明します。スタックの変化は「実行前 → 実行後」の形で、先頭を右端に書いています。

| 命令 | 動作 | スタックの変化の例 | 詳しくは |
|---|---|---|---|
| `push` | 移動元のブロックの大きさを積む | `[ ]` → `[5]`（大きさ 5 のとき） | 第6章 |
| `pop` | 先頭を取り除く | `[1 2]` → `[1]` | 第6章 |
| `add` | 上 2 つを取り出し、和を積む | `[2 3]` → `[5]` | 第6章 |
| `subtract` | 2 番目 − 先頭 を積む | `[7 3]` → `[4]` | 第6章 |
| `multiply` | 積を積む | `[6 7]` → `[42]` | 第6章 |
| `divide` | 2 番目 ÷ 先頭（整数の商）を積む | `[7 2]` → `[3]` | 第6章 |
| `mod` | 2 番目を先頭で割った余りを積む | `[7 3]` → `[1]` | 第6章 |
| `not` | 先頭が 0 なら 1、それ以外なら 0 に置き換える | `[5]` → `[0]` | 第9章 |
| `greater` | 2 番目 > 先頭 なら 1、そうでなければ 0 を積む | `[5 3]` → `[1]` | 第9章 |
| `pointer` | 先頭を取り出し、その回数だけ DP を時計回りに回す | `[1]` → `[ ]` | 第9章 |
| `switch` | 先頭を取り出し、その回数だけ CC を切り替える | `[1]` → `[ ]` | 第9章 |
| `duplicate` | 先頭を複製して積む | `[4]` → `[4 4]` | 第11章 |
| `roll` | スタックの一部を回転させる | `[1 2 3 3 1]` → `[3 1 2]` | 第11章 |
| `in(number)` | 数を 1 つ読み込んで積む | 入力 `42` で `[ ]` → `[42]` | 第7章 |
| `in(char)` | 文字を 1 つ読み込み、その文字コードを積む | 入力 `A` で `[ ]` → `[65]` | 第7章 |
| `out(number)` | 先頭を取り出し、数として出力する | `[42]` → `[ ]`、出力 `42` | 第7章 |
| `out(char)` | 先頭を取り出し、文字として出力する | `[65]` → `[ ]`、出力 `A` | 第7章 |

二項演算（`add` から `mod` まで、および `greater`）では、**先に積んだ値（2 番目）が左側、あとから積んだ値（先頭）が右側**になります。`[7 3]` で `subtract` を実行すると 7 − 3 = 4 です。普通の数式と同じ順に値を積めばよい、と覚えておきましょう。

仕様は、実行できない命令について「無視して次の命令に進む」と定めています。たとえばスタックが空のときに `pop` や `add` を実行しても、エラーにはならず、何も起きません。0 による除算などの扱いには処理系による違いがあるので、第6章と付録C で説明します。

!!! note "メモ"
    白いブロックや黒いブロックは色相と明度を持たないので、白や黒が関わる移動では命令は実行されません。色ブロックから白い領域に入り、白い領域を通り抜けて別の色ブロックに入ったときも、命令は実行されません（第8章）。

## 4.7 プログラムを手で設計する

命令表の使い方がわかったので、簡単なプログラムを設計してみましょう。ここでは、左から右へ一直線にブロックが並ぶ、**直線状のプログラム**を考えます。設計は次の手順で行います。

1. 実行したい命令の列を書き出す。
2. 各ブロックの大きさを決める。`push n` の直前のブロックは大きさ n にする。それ以外のブロックは大きさ 1 でよい。
3. 最初のブロックの色を決め、4.5 節の方法で次々に色を求める。
4. ブロックを左から右へ並べる。
5. 最後に、プログラムを終了させるための「わな」（第5章）を置く。

### 例 1: 2 + 3

2 と 3 を足して出力するプログラムを作ります。命令の列は次のとおりです。

```text
push 2, push 3, add, out(number)
```

`push 2` の直前のブロック（最初のブロック）は大きさ 2、`push 3` の直前のブロック（2 番目のブロック）は大きさ 3 にします。最初の色を赤とすると、色は次のように決まります。

| ブロック | 色 | 大きさ | 次のブロックへ移るときの命令 |
|---|---|---|---|
| 1 | 赤 | 2 | `push`（色相 +0、明度 +1）→ 2 を積む |
| 2 | 濃赤 | 3 | `push`（色相 +0、明度 +1）→ 3 を積む |
| 3 | 淡赤 | 1 | `add`（色相 +1、明度 +0） |
| 4 | 淡黄 | 1 | `out(number)`（色相 +5、明度 +1） |
| 5 | 赤 | （終端） | |

濃赤（明度 2）に明度の差 1 を足すと (2 + 1) mod 3 = 0 で淡い色になる点に注意してください。明度の環を一周したのです。

これを左から並べ、最後の赤を L 字形にして黒で囲んだのが、4.4 節の 1 つ目のプログラムです。テキスト記法では次のようになります。

設計どおり、`push 2`、`push 3`、`add`、`out(number)` の順に実行され、5 が出力されています。

### 例 2: 6 × 7（ブロックの形を工夫する）

6 と 7 を掛けて 42 を出力するプログラムです。命令の列は `push 6, push 7, multiply, out(number)` で、色は緑から始めて、緑・濃緑・淡緑・濃シアン・淡緑と決まります。

大きさ 6 と 7 のブロックを一列に並べると横に長くなるので、ここではブロックを 2 段に折りたたみました。

@piet ch04/mul67 caption="6 × 7 を計算して 42 を出力する" zoom=36

@grid ch04/mul67

緑のブロックは 3×2 の 6 コーデル、濃緑のブロックは 1 段目に 4 コーデル、2 段目に 3 コーデルの 7 コーデルです。ブロックをどんな形にしても大きさが合っていれば `push` で積まれる値は同じですが、**次のブロックへの出口がどこになるか**は形によって変わります。ここでは、右上の角から右隣のブロックへ出るように形を決めています。この「出口」の決まり方が次の第5章のテーマです。

### 例 3: 7 − 3（値を積む順番）

引き算では値を積む順番が重要です。次のプログラムは 7 を積み、3 を積み、`subtract` を実行します。

@piet ch04/sub73 caption="7 − 3 を計算して 4 を出力する" zoom=36

@trace ch04/sub73

スタックが `[7 3]` のときの `subtract` は「2 番目 − 先頭」、つまり 7 − 3 = 4 を計算します。もし 3 を先に、7 をあとに積めば、結果は 3 − 7 = −4 になります。

### 例 4: 文字 A を出力する

最後に、文字を出力するプログラムです。`out(char)` は、スタックの先頭の値を文字コードとみなして文字を出力します。`A` の文字コードは 65 なので、65 を積んでから `out(char)` を実行すればよいのですが、大きさ 65 のブロックを描くのは大変です。そこで、65 = 8 × 8 + 1 と分解し、次の命令の列にします。

```text
push 8, duplicate, multiply, push 1, add, out(char)
```

`duplicate` で 8 を複製し、`multiply` で 8 × 8 = 64 を作り、1 を足して 65 にします。

@piet ch04/letter_a caption="8 × 8 + 1 = 65 を作り、文字 A を出力する" zoom=36

@trace ch04/letter_a

大きさ 8 のマゼンタのブロック（4×2）から始まり、6 回の命令で `A` が出力されます。大きな数を小さなブロックの組み合わせで作る技法は、第6章で詳しく学びます。

## まとめ

- Piet の命令は、移動元と移動先の色ブロックの**色相の差**（0〜5）と**明度の差**（0〜2）の組み合わせで決まる。色そのものには意味がない。
- 18 通りの組み合わせのうち、差がどちらも 0 のものを除く 17 通りが 17 個の命令に対応する。
- どの命令も 18 通りの色の組で表せる。出発点の色を変えても、命令の意味は保たれる。
- 次の色は、いまの色の色相と明度に、命令の色相の差と明度の差をそれぞれ足して（6 または 3 で割った余りを取って）求める。
- 直線状のプログラムは、命令の列を書き、ブロックの大きさを決め、色を順に求めて並べ、最後に終了のための構造を置いて作る。

## 練習問題

1. 次の色の組で実行される命令を答えてください。(a) 緑 → 濃シアン (b) 淡青 → 赤 (c) 濃マゼンタ → 黄 (d) シアン → 淡シアン
2. 次の色のブロックの次に、指定した命令を実行するには、何色のブロックを置けばよいですか。(a) 黄のあとに `subtract` (b) 濃青のあとに `out(char)` (c) 淡マゼンタのあとに `duplicate`
3. 3 を積み、`duplicate` と `multiply` で 3 × 3 = 9 を作って出力するプログラムを、黄から始めて設計してください。テキスト記法で書き、実行して確かめてください。
4. 10 − 4 を計算して 6 を出力するプログラムを、緑から始めて設計してください。大きさ 10 のブロックは一列に並べず、形を工夫してください。
5. 4.4 節の 2 つの 2 + 3 のプログラムについて、隣り合うブロックごとに色相の差と明度の差を計算し、両者が一致することを確かめてください。
