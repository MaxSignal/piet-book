### 問題 18-1

字句解析では `+=` と `-=` を 2 文字の演算子として認識させます（正規表現の `op` に、`=` より前に `\+=|-=` を加える）。構文解析の `stmt()` で、名前の後に `=` だけでなく `+=`・`-=` も受け付け、木の段階で通常の代入に書き換えるのがいちばん簡単です。


```python
if kind == "id":
    self.take()
    op = self.take()[1]                 # "=", "+=", "-="
    e = self.expr()
    self.take(";")
    if op != "=":
        e = (op[0], ("var", val), e)    # x += e  →  x = x + e
    return ("assign", val, e)
```

コード生成は一切変更する必要がありません。このように、新しい構文を既存の構文の組み合わせに置き換えることを「糖衣構文（シンタックスシュガー）の脱糖」と呼びます。

### 問題 18-3

変数 a, b があり、`a = 5; b = 7;` の後で `a = b;` をコンパイルすると、次の部分が出力されます。


```pasm
  pick 0     ; b
  bury 2
  push 2
  push 1
  roll
  pop     ; → a
```

| 命令 | スタック（左が底） |
|---|---|
| | `[5 7]` |
| `pick 0` | `[5 7 7]` |
| `bury 2` | `[7 5 7]` |
| `push 2` `push 1` `roll` | `[7 7 5]` |
| `pop` | `[7 7]` |

b の値 7 を複製して先頭に積み、a の位置へ書き込んでいます。

### 問題 18-4

番兵 −1 を積んだ後、`in(number)` は −5 を読めるので、スタックの先頭は `[… -1 -5]` になります。`dup` で `[… -1 -5 -5]`、`push -1` と `gt` で「−5 > −1」を計算すると 0 になり、`jz` は「読めなかった」と判断してジャンプします。このとき、番兵の −1 を捨てる `swap` `pop` が実行されないので、スタックには `[… -1 -5]` と 2 つの値が残ります。続く書き込みは先頭の −5 を x に入れますが、番兵の −1 が変数の上に余分に残るため、それ以降、コンパイラが計算した変数の深さはすべて 1 つずれ、プログラムは誤った変数を読み書きします。これが「read は 0 以上の整数を前提とする」理由です。


### 問題 18-5

条件を先頭で 1 回、本体の末尾でもう 1 回計算する形に翻訳します。


```pasm
  （条件）
  jz wend
wtop:
  （本体）
  （条件）
  jnz wtop
wend:
```

元の翻訳では、1 回の繰り返しごとに「条件の行で `jz` が不成立 → 本体の行へ移る」と「本体の行の末尾の `jmp` で条件の行へ戻る」の 2 回、行と行の移動があります。pasm.py のレイアウトでは、行の移動はすべて画像の下端を回る白い配線を通るので、移動が 1 回で済む回転後の形のほうが、実行ステップ数が少なくなります。その代わり、条件の命令列を 2 か所に置くので、画像は条件の分だけ大きくなります。
