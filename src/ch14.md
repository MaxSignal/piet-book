# 第14章 総合演習

この章では、これまでに学んだことを総動員して、少し大きなプログラムをいくつか作ります。題材は、プログラミングの練習問題として世界中で親しまれている FizzBuzz、コラッツ数列、電卓、九九の表、そして「99 Bottles of Beer」です。どれも、ほかの言語なら数行から数十行で書けるものですが、Piet では設計の手順を意識しないとすぐに迷子になります。最初に、本書がすすめるプログラム作りの手順をまとめ、各プログラムをその手順に沿って作っていきます。最後に、アセンブラで作ったプログラムを手で描き直して小さくする「手作業の最適化」を体験します。

!!! abstract "この章で学ぶこと"
    - 仕様から完成した画像までの、プログラム作りの手順
    - ループの中での多方向の分岐（FizzBuzz）と、入れ子のループ（九九）
    - 入力された演算子による多方向の分岐（電卓）
    - 戻り先の番号を使ってサブルーチン呼び出しをまねる方法（99 Bottles of Beer）
    - アセンブラの出力を手で描き直して小さくする方法

## 14.1 プログラム作りの手順

本書では、Piet のプログラムを次の 6 つの段階で作ります。第12章と第13章でも暗に使ってきた手順です。

1. **仕様を決める** ― 入力と出力の形式を、例を挙げて正確に決める。改行の有無まで決める
2. **擬似コードを書く** ― ふつうの言語のつもりでアルゴリズムを書く
3. **スタックの配置を決める** ― 変数をスタックのどの深さに置くかを決める。ループの入口でのスタックの形を「不変条件」として書いておく
4. **pasm で書く** ― 命令ごとに、実行後のスタックの状態をコメントに書く
5. **テストする** ― 期待される出力を先に用意し、境界値を含む複数の入力で確かめる
6. **（必要なら）手で最適化する** ― 小さく、あるいは美しくしたいときに、画像を手で描き直す。描き直したら 5 のテストをもう一度行う

段階 5 のテストは、本書では `tools/samples.py` で自動化しています。サンプルごとに入力ファイル（`.in`）と期待される出力ファイル（`.out`）を用意しておくと、本書の piet.py と npiet の両方で実行して、出力が期待どおりかを比べてくれます。

```sh
python3 tools/samples.py ch14
```

```text
ok  ch14/fizzbuzz (111x87, 6029 steps) out='1\n2\nFizz\n4\nBuzz\nFizz\n7\n8\nFizz\nBuzz\n11\nFizz\n13\n14\nF'
...
```

期待される出力は、プログラムを書く**前**に、手で、あるいはほかの言語で作っておきます。この章の FizzBuzz や 99 Bottles of Beer の期待出力は、Python で同じ処理を書いて生成しました。Piet で書いたプログラムの出力を見てから「たぶん合っている」と判断するのでは、テストになりません。

## 14.2 FizzBuzz

### 仕様

1 から 100 までの整数を 1 行に 1 つずつ出力します。ただし、3 の倍数のときは数のかわりに `Fizz`、5 の倍数のときは `Buzz`、3 と 5 の両方の倍数（15 の倍数）のときは `FizzBuzz` と出力します。

### 擬似コードとスタック

```text
i = 1
loop:
    if i mod 15 == 0: "FizzBuzz" を出力
    elif i mod 3 == 0: "Fizz" を出力
    elif i mod 5 == 0: "Buzz" を出力
    else: i を出力
    改行を出力
    i = i + 1
    if i != 101: goto loop
```

変数は `i` だけなので、スタックは `[i]` です。各判定では `dup` で `i` を複製してから `mod` を計算し、`jz` で分岐します。判定に使った値は `jz` が取り除くので、どの枝に進んでもスタックは `[i]` のままです。

### pasm のソース

```pasm
; FizzBuzz（1 から 100 まで）
        push 1          ; [i]
loop:
        dup
        push 15
        mod
        jz fb           ; 15 の倍数
        dup
        push 3
        mod
        jz f            ; 3 の倍数
        dup
        push 5
        mod
        jz b            ; 5 の倍数
        dup
        outn            ; それ以外は数そのもの
next:
        push 10
        outc
        push 1
        add             ; [i+1]
        dup
        push 101
        sub
        jnz loop        ; i+1 が 101 でなければ続ける
        halt
fb:
        prints "FizzBuzz"
        jmp next
f:
        prints "Fizz"
        jmp next
b:
        prints "Buzz"
        jmp next
```

`if`〜`elif`〜`else` の連鎖は、「条件が成り立ったら専用のラベルへ飛び、そこで処理してから合流点 `next:` へ戻る」という形で書きます。3 つの枝（`fb:`、`f:`、`b:`）と、ジャンプしなかった場合の `dup` `outn` の 4 つの経路が、すべて `next:` で合流します。どの経路でも、`next:` に来たときのスタックは `[i]` です。

ループの終了条件は `i + 1 - 101` が 0 かどうかで判定しています。「等しいか」は引き算して `jz`（または `jnz`）で調べるのでした。

@piet ch14/fizzbuzz caption="FizzBuzz（111×87 コーデル、6029 ステップ）" zoom=4

文字列の出力を含む 4 つの枝があるので、画像の高さが増えています。pasm は基本ブロックごとに 1 行を使い、行ごとに左右の縦の通路と下の横の通路を 1 本ずつ用意するので、基本ブロックの数が増えると、画像はその数に比例して縦にも横にも大きくなります。

## 14.3 コラッツ数列を出力する

第12章ではコラッツ問題の手数を数えました。今度は、途中の数をすべて空白で区切って出力します。

```text
n を読む
loop:
    n を出力
    if n == 1: 改行を出力して終了
    空白を出力
    if n が偶数: n = n / 2 else: n = 3n + 1
```

```pasm
; コラッツ数列を 1 になるまで出力する
        inn             ; [n]
loop:
        dup
        outn
        dup
        push 1
        sub
        jz done         ; n = 1 で終わり
        push 32
        outc            ; 区切りの空白
        dup
        push 2
        mod
        jz even
        push 3
        mul
        push 1
        add             ; [3n+1]
        jmp loop
even:
        push 2
        div             ; [n/2]
        jmp loop
done:
        push 10
        outc
```

@piet ch14/collatz_seq caption="コラッツ数列を出力するプログラム" input="6\n"

仕様の「数と数の間に空白を 1 つ、最後の数の後には改行」を守るために、空白は「次の数がある」ことがわかってから（`n == 1` の判定の後で）出力しています。区切り文字の出し方は、どの言語でも間違えやすいところです。6 を入力すると `6 3 10 5 16 8 4 2 1`、1 を入力すると `1` だけが出力されます。

## 14.4 電卓

### 仕様

`12+30` のように、「整数、演算子 1 文字、整数」を空白なしで 1 行に入力すると、計算結果を出力します。演算子は `+` `-` `*` `/` `%` の 5 つで、それ以外の演算子には `?` と出力します。

### 入力の読み方

`in(number)` は、数字が続くかぎり読んで、数字でない文字の手前で止まります。そこで `in(number)`、`in(char)`、`in(number)` の順に実行すると、`12+30` を `12`、`+`、`30` に分けて読めます。

!!! warning "注意"
    `in(number)` は数の**前**の空白は読み飛ばしますが、数の後の空白はそのまま残します。`12 + 30` のように空白を入れると、`in(char)` が演算子ではなく空白を読んでしまいます。この電卓では、入力に空白を入れないことを仕様としました。

### 演算子による分岐

演算子の文字コードを 1 つずつ引き算して、0 になったところで分岐します。C 言語の `switch` 文にあたる処理です。

```pasm
; 「数 演算子 数」を読んで計算する電卓（+ - * / %）
        inn             ; [a]
        inc             ; [a op]
        inn             ; [a op b]
        swap            ; [a b op]
        dup
        push 43         ; '+'
        sub
        jz plus
        dup
        push 45         ; '-'
        sub
        jz minus
        dup
        push 42         ; '*'
        sub
        jz times
        dup
        push 47         ; '/'
        sub
        jz divide
        dup
        push 37         ; '%'
        sub
        jz modulo
        prints "?\n"    ; 知らない演算子
        halt
plus:
        pop
        add
        jmp print
minus:
        pop
        sub
        jmp print
times:
        pop
        mul
        jmp print
divide:
        pop
        div
        jmp print
modulo:
        pop
        mod
print:
        outn
        push 10
        outc
```

読んだ直後のスタックは `[a op b]` です。`swap` で `[a b op]` にしておくと、演算子を判定して `pop` で捨てたあとに `[a b]` が残り、すぐに `add` などの命令を実行できます。各枝で `[a b]` から結果 1 つを作り、合流点 `print:` で出力します。

@piet ch14/calc caption="5 種類の演算子を扱う電卓" input="12+30\n"

| 入力 | 出力 |
|---|---|
| `12+30` | `42` |
| `7-10` | `-3` |
| `6*7` | `42` |
| `100/7` | `14` |
| `100%7` | `2` |
| `2^8` | `?` |

負の数どうしの割り算や剰余は、処理系によって結果が違うことに注意してください（付録C）。

## 14.5 九九の表

入れ子のループの例として、九九の表を出力します。各行に 9 つの積を、2 桁に右寄せして空白で区切って並べます。

```text
 1  2  3  4  5  6  7  8  9
 2  4  6  8 10 12 14 16 18
...
 9 18 27 36 45 54 63 72 81
```

スタックは `[i j]` です。外側のループは `row:`、内側のループは `col:` から始まります。積 `p` が 1 桁なら（`10 > p` なら）、数の前に空白を 1 つ出力して右寄せにします。

```pasm
; 九九の表（右寄せ 2 桁、空白区切り）
        push 1          ; [i]
row:
        push 1          ; [i j]
col:
        pick 1
        pick 1
        mul             ; [i j p]
        dup
        push 10
        swap
        gt              ; [i j p (10>p)]
        jz wide
        push 32
        outc            ; 1 桁なら空白を 1 つ足す
wide:
        outn            ; [i j]
        dup
        push 9
        sub
        jz endrow       ; j = 9 なら行の終わり
        push 32
        outc
        push 1
        add             ; [i j+1]
        jmp col
endrow:
        pop             ; [i]
        push 10
        outc
        dup
        push 9
        sub
        jz done
        push 1
        add
        jmp row
done:
        halt
```

入れ子のループでは、**内側のループの変数は外側のループの変数より上に積む**のが原則です。内側のループに入るときに `j` を積み（`push 1`）、内側のループを抜けたら `j` を捨てる（`pop`）と、外側のループから見たスタックは常に `[i]` のままになります。ふつうの言語でいう「ブロックの中だけで有効な局所変数」を、スタックの積み下ろしで表しているわけです。

## 14.6 99 Bottles of Beer

### 仕様

「99 Bottles of Beer」は、99 本のビールの瓶が 1 本ずつ減っていく英語の数え歌です。いろいろな言語で歌詞を出力するプログラムを書くのが、昔から定番になっています。Piet の公式サンプルページにも、Eddy Ferreira によるものが掲載されています。本書では次の歌詞を出力します。

```text
99 bottles of beer on the wall, 99 bottles of beer.
Take one down and pass it around, 98 bottles of beer on the wall.

98 bottles of beer on the wall, 98 bottles of beer.
...
1 bottle of beer on the wall, 1 bottle of beer.
Take one down and pass it around, no more bottles of beer on the wall.

No more bottles of beer on the wall, no more bottles of beer.
Go to the store and buy some more, 99 bottles of beer on the wall.
```

難しいのは、瓶の本数の言い方が 3 通りあることです。2 本以上なら `98 bottles`、1 本なら `1 bottle`（単数形）、0 本なら `no more bottles` です。しかもこの部分は 1 番の歌詞の中に 3 回出てきます。

### サブルーチンをまねる

ふつうの言語なら、本数の言い方を関数にして 3 回呼び出すところです。しかし Piet には関数呼び出しの命令がありません。呼び出すこと自体は `jmp` でできますが、問題は**戻る**ほうです。呼び出し元が 3 か所あるので、関数の終わりで「どこへ戻るか」がわかりません。

そこで、呼び出すときに**戻り先の番号**をスタックに積んでおき、関数の終わりでその番号を見て分岐することにします。実際のコンピュータが戻りアドレスをスタックに積んでから関数を呼ぶのと同じ考え方です。Piet の画像の中には「アドレス」がないので、かわりに戻り先ごとに 1, 2, 3 という番号を付け、番号から戻り先のラベルへ分岐します。

```text
bottles(m, r):          ; m 本の言い方を出力し、r 番の戻り先へ戻る
    if m == 0: "no more bottles"
    elif m == 1: "1 bottle"
    else: m と " bottles"
    if r == 1: goto ret1
    elif r == 2: goto ret2
    else: goto ret3
```

### pasm のソース

```pasm
; 99 Bottles of Beer
; 「n bottles」を出力する部分を、戻り先番号 r を使って共有する
        push 99                 ; [n]
verse:
        dup
        push 1                  ; [n n 1]   戻り先 1
        jmp bottles
ret1:
        prints " of beer on the wall, "
        dup
        push 2                  ; [n n 2]   戻り先 2
        jmp bottles
ret2:
        prints " of beer.\nTake one down and pass it around, "
        push 1
        sub                     ; [n-1]
        dup
        push 3                  ; [n-1 n-1 3]  戻り先 3
        jmp bottles
ret3:
        prints " of beer on the wall.\n\n"
        dup
        jnz verse               ; [n]
        pop
        prints "No more bottles of beer on the wall, no more bottles of beer.\n"
        prints "Go to the store and buy some more, 99 bottles of beer on the wall.\n"
        halt

; ---- サブルーチン bottles: [.. m r] → m に応じて出力し、r 番の戻り先へ
bottles:
        swap                    ; [r m]
        dup
        jz b0                   ; m = 0
        dup
        push 1
        sub
        jz b1                   ; m = 1
        outn
        prints " bottles"
        jmp return
b0:
        pop
        prints "no more bottles"
        jmp return
b1:
        outn
        prints " bottle"
return:                         ; [r]
        dup
        push 1
        sub
        jz r1
        dup
        push 2
        sub
        jz r2
        pop
        jmp ret3
r1:
        pop
        jmp ret1
r2:
        pop
        jmp ret2
```

サブルーチン `bottles` の**呼び出し規約**（引数と戻り値の受け渡しの約束）は次のとおりです。

- 呼び出し側は、引数 `m` と戻り先番号 `r` を `[… m r]` の順に積んでから `jmp bottles` する
- `bottles` は `m` と `r` を取り除き、スタックを呼び出し前の `[…]` に戻してから、戻り先へジャンプする

`bottles` の中では、`swap` で `[r m]` にしてから `m` を調べます。`m` を出力または `pop` で取り除くと `[r]` が残り、`return:` で `r` を調べて戻り先へ分岐します。戻り先の番号は分岐の前に `pop` で捨てます。

本数の言い方を変えたいときは、`bottles` だけを直せば 3 か所すべてに反映されます。サブルーチンにまとめることの利点は、Piet でも変わりません。

@piet ch14/bottles caption="99 Bottles of Beer（403×525 コーデル、96639 ステップ）" zoom=2

歌詞の全体は 99 番まであるので、実行には約 9 万 7 千ステップかかります。Piet スタジオで実行するときは、少し時間がかかるかもしれません。

!!! note "メモ"
    この画像は 403×525 コーデルと、本書のサンプルの中でもかなり大きなものです。歌詞の文字列が長いことに加え、pasm が長い基本ブロックを幅 48 コーデルごとに折り返し、折り返した行ごとに配線を用意するためです。練習問題 1 では、文字列の共通部分をサブルーチンに移して小さくする方法を考えます。

## 14.7 手で最適化する

### アセンブラの出力の無駄

アセンブラは、どんなプログラムでも正しく動く画像を作るために、ゆとりのある配置を使います。第12章のユークリッドの互除法のプログラムは 34×27 コーデルでしたが、その大部分は白い通路と余白です。命令は少ないので、手で描けばずっと小さくできるはずです。手順の段階 6、手作業の最適化をやってみましょう。

### 設計

互除法のプログラムに必要な命令を、ループの形を意識して並べ直します。

```text
in(number) in(number)
loop: duplicate not pointer          ; b == 0 なら DP を下へ（ループを抜ける）
      duplicate push 3 push 1 roll mod  ; (a, b) = (b, a mod b)
      → loop の先頭へ戻る
出口: pop out(number)
```

`jz` のかわりに、第9章で学んだ `not` と `pointer` を直接使います。`b` を `duplicate` して `not` すると、`b` が 0 のときだけ 1 になります。`pointer` は DP を時計回りにその回数だけ回すので、`b` が 0 なら DP は右から下に変わり、そうでなければ右のままです。pasm の `jz` は `push 3` と `multiply` を加えて上に曲げていましたが、手で描くなら下に曲げるほうが単純です。

配置は次のように考えます。

- 1 行目に、`in(number)` 2 つとループの本体を左から右へ並べる
- ループの本体の右端から出た流れを、白い通路で下 → 左 → 上 → 右と時計回りに一周させ、ループの先頭に戻す。白い通路で曲がるには、行き止まりに黒（または画像の端）を置けばよい（第8章）
- `pointer` で DP が下を向いたときは、そのまま白い通路を下に滑り落ちて、出口の命令に入る

@grid ch14/gcd_hand

1 行目の左から順に見ていきます。

- `r` `5` `G`: 淡赤 → 濃青 → 緑で `in(number)` を 2 回実行する
- `.`: 白。緑のブロックを出た流れはここを滑って、ループの先頭の淡青 `b` に入る（白を通ったので命令は実行されない）
- `b` `g` `5` `y`: `duplicate`・`not`・`pointer`。`y`（淡黄）に入ったとき DP が決まる
- `m` `m` `m`: 大きさ 3 の淡マゼンタのブロック。淡黄から入るときに `duplicate`、出るときに `push 3`
- `M` `6` `c` `M`: `push 1`・`roll`・`mod`
- `.` `#`: 右端の白を滑り、黒にぶつかって DP が下に回る。1 列下がったところで黒（3 行目右の `#`）にぶつかって左に回り、2 行目の白い通路を左へ進む。2 行目左の `#` で上に回り、画像の上端で右に回って、ループの先頭の `b` に戻る

`pointer` で DP が下を向いたときは、淡黄 `y` から真下の白を滑り落ちて 3 行目の淡緑 `g` に入り、`pop`（淡緑 → 濃緑）と `out(number)`（濃緑 → 淡黄）を実行します。最後の淡黄のブロックは L 字形で、周りを黒と画像の端に囲まれているので、ここでプログラムは終了します（第5章のわな）。

途中の 2 行目は、ループの帰り道（左向き）と出口の通路（下向き）が**交差**しています。白い通路は、まっすぐ滑るかぎり、ほかの通路と交差してもかまいません。流れが曲がるのは黒や画像の端にぶつかったときだけなので、交差点に黒を置かないかぎり、2 つの流れは互いに影響しません。

12 と 18 を入力したときのトレースの前半を示します。ループを 1 周するごとに、スタックの 2 つの値が `(b, a mod b)` に置き換わっていく様子がわかります。

@trace ch14/gcd_hand input="12 18\n" steps=14

34×27 = 918 コーデルだった画像が、17×6 = 102 コーデルと、ちょうど 9 分の 1 になりました。ただし、手で描いた版は最後の改行を出力しません。また、手で描くと色の計算や配置を間違えやすいので、描き直したら必ずテストをやり直します。このプログラムも、pasm 版と同じ入力（`12 18`、`1071 1029`、`0 9`）で、piet.py と npiet の両方の出力が期待どおりであることを確かめました。

!!! tip "ヒント"
    手で描くときは、Piet スタジオ（第2章）を使うと便利です。パレットには選んでいる色から各命令を実行するための色が表示されるので、命令の列を見ながら色を置いていけます。描いたらその場で 1 ステップずつ実行し、スタックや DP・CC の変化を確かめながら直しましょう。テキスト格子（付録B）で下書きして `tools/piet.py run -t` でトレースを見る方法もあります。この節の互除法も、Piet スタジオで描いて実行してみましょう。

## まとめ

- プログラムは「仕様 → 擬似コード → スタックの配置 → pasm → テスト → 手作業の最適化」の順に作る。期待される出力はプログラムを書く前に用意する
- `if`〜`elif`〜`else` は、各条件で専用のラベルへ飛び、処理後に合流点へ戻る形で書く。合流点でのスタックの形をそろえる
- 入れ子のループでは、内側の変数を外側の変数より上に積み、内側のループを抜けたら捨てる
- 関数呼び出しは、引数と戻り先の番号を積んで `jmp` し、関数の終わりで番号によって分岐することでまねられる
- アセンブラの出力は大きいが、命令の少ないループは手で描き直すと大幅に小さくできる。白い通路は交差させてもよい

## 練習問題

1. 99 Bottles of Beer の歌詞では、`bottles` の出力の直後に必ず ` of beer` が続きます。この ` of beer` の出力をサブルーチン `bottles` の中に移し、出力が変わらないことを確かめてください。画像の大きさはどう変わるでしょうか。
2. FizzBuzz を、「3 の倍数なら `Fizz` を出力し、5 の倍数なら `Buzz` を出力し、どちらも出力しなかったら数を出力する」という考え方で書き直してください。15 の倍数の判定が要らなくなります。
3. 電卓に、累乗の演算子 `^` を追加してください。`2^10` で `1024` を出力します。
4. 2 つの数を読んで和を出力するプログラムを、手で、できるだけ小さく描いてください。ヒント: 命令は `in(number)`・`in(number)`・`add`・`out(number)` の 4 つで、最後に終了のためのわなが必要です。
5. 14.7 節の手で描いた互除法のプログラムを、最後に改行を出力するように直してください。どこに何を追加すればよいでしょうか。
