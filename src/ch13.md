# 第13章 文字と文字列

Piet が扱えるデータは整数だけです。文字は「文字コードという整数」として扱い、`out(char)` で出力するときと `in(char)` で読むときにだけ文字になります。この章では、文字列をなるべく少ないコーデルで出力する方法を比べたあと、入力を 1 文字ずつ読んで加工する、いわゆる**フィルタ**型のプログラムを書いていきます。UNIX の `tr`、`rev`、`wc` のような小さな道具を Piet で作ってみましょう。

!!! abstract "この章で学ぶこと"
    - 文字列を出力する 3 つの方法と、その大きさの比較
    - 入力の終わり（EOF）を見分ける「番兵」の技法
    - 分岐を使わずに計算で文字を変換する方法（大文字への変換）
    - 文字の範囲で分岐する方法（ROT13）
    - スタックを文字のバッファとして使う方法（逆順出力、2 進数の出力）

## 13.1 文字列を出力する

### 素朴な方法

「Hello, World!」と改行を出力するいちばん素朴な方法は、文字ごとに文字コードを積んで `out(char)` することです。

```pasm
; 1 文字ずつ push して out(char) する
        push 72   ; 'H'
        outc
        push 101  ; 'e'
        outc
        push 108  ; 'l'
        outc
        ...
```

pasm の `prints "Hello, World!\n"` も、中ではこれと同じ命令列に展開されます。文字コード 72 は、大きさ 72 のブロックで直接積むこともできますが、pasm はもっと少ないコーデルで済む計算式を探します。72 なら `push 2` `push 6` `duplicate` `multiply` `multiply`（2 × 6²、2 + 6 + 1 + 1 + 1 = 11 コーデル）、101 なら `push 2` `push 5` `multiply` `duplicate` `multiply` `push 1` `add`（(2 × 5)² + 1）のような具合です。

@piet ch13/hello_naive caption="1 文字ずつ出力する素朴な Hello, World!" zoom=6

### 番兵とループを使う方法

2 つめの方法は、文字を**逆順に**すべてスタックに積んでから、ループで 1 文字ずつ出力するものです。スタックの底には目印として 0 を置いておき、0 が出てきたらループを終えます。このような「データの終わりを示す特別な値」を**番兵**（sentinel）と呼びます。

```pasm
; 文字を逆順に積んでから、0 が出るまで出力するループ
        push 0          ; 番兵
        push 10   ; '\n'
        push 33   ; '!'
        push 100  ; 'd'
        ...
        push 72   ; 'H'
loop:
        dup
        jz done         ; 番兵の 0 なら終わり
        outc
        jmp loop
done:
        halt
```

逆順に積むのは、スタックの先頭から取り出したときに正しい順になるようにするためです。

@piet ch13/hello_loop caption="番兵とループで出力する Hello, World!" zoom=6

### 差分を使う方法

3 つめの方法は、**直前の文字との差**だけを計算するものです。英文では隣り合う文字のコードが近いことが多いので、差は小さな数になりがちです。直前の文字を `dup` で残しておき、差を足し引きしてから出力します。

```pasm
; 直前の文字との差だけを足し引きする
        push 72   ; 'H'
        dup
        outc
        dup
        push 29   ; +29 → 'e'
        add
        dup
        outc
        dup
        push 7    ; +7 → 'l'
        add
        dup
        outc
        dup
        ; 差 0 → 'l'
        dup
        outc
        ...
```

@piet ch13/hello_delta caption="直前の文字との差で出力する Hello, World!" zoom=6

### どれがいちばん小さいか

3 つの方法で、命令に使うブロックのコーデル数（`push N` なら N、それ以外の命令は 1 として合計したもの）を数えてみました。番兵とループの方法には、このほかにループの分岐（`not` `push 3` `multiply` `pointer`）の 6 コーデルほどがかかります。

| 文字列 | 文字数 | 素朴な方法 | 番兵とループ | 差分 |
|---|---|---|---|---|
| `Hello, World!\n` | 14 | 184 | 174 + 分岐 | 178 |
| `the quick brown fox jumps over the lazy dog\n` | 44 | 636 | 596 + 分岐 | 584 |

意外なことに、差はそれほど大きくありません。どの方法でも、コストのほとんどは**文字コードという数を作る部分**にあるからです。番兵とループの方法は、文字ごとの `out(char)` の 1 コーデルを節約しますが、ループの分岐のぶんだけ増えます。差分の方法は、小文字が続く英文で効果が出ますが、`dup` と `add` のぶん 1 文字あたりの命令は増えます。

pasm が生成する画像の大きさ（幅×高さ）は、配線の都合でむしろ番兵とループの方法がいちばん大きくなりました（素朴な方法と差分は 71×27、番兵とループは 83×45 コーデル）。

!!! tip "ヒント"
    結論として、短い文字列なら素朴な方法で十分です。長い文章を出力するときや、同じ文字列を何度も出力するときは、文字列の共通部分をまとめる工夫（第14章の 99 Bottles of Beer で扱います）のほうが効果があります。最適化をするときは、このように**まず測る**ことが大切です。

## 13.2 入力の終わりを見分ける

### `in(char)` と EOF

フィルタ型のプログラムは、入力を「最後まで」読みます。ところが Piet には「入力が終わったか」を調べる命令がありません。仕様では、`in` 命令を実行したときに入力がなければ、それはエラーとして**命令が無視される**、と決められています。つまり、入力の終わり（EOF）で `in(char)` を実行すると、スタックには何も積まれません。

これを逆手にとって、EOF を見分けることができます。`in(char)` の前に番兵の 0 を積んでおくのです。

```pasm
        push 0          ; [0]            EOF 検出用の番兵
        inc             ; [0 c] または [0]
        dup
        jz eof          ; 何も読めなかった
        swap
        pop             ; [c]
```

文字が読めたときはスタックが `[0 c]` になり、先頭の `c` は 0 ではありません。読めなかったときは `[0]` のままで、先頭は番兵の 0 です。`dup` と `jz` で先頭を調べ、0 なら EOF の処理へ進みます。文字が読めたときは、`swap` `pop` で下に残った番兵を捨てて `[c]` にします。

この方法には 1 つだけ弱点があります。入力の中に文字コード 0 の文字（NUL）があると、それを EOF と区別できません。ふつうのテキストには NUL は含まれないので、本書ではこの方法を使います。

!!! column "コラム: 文字コードと処理系"
    仕様では、文字の入出力は Unicode の値で行うとされています。本書の piet.py は入力を Unicode の文字として読み、`out(char)` も Unicode の文字を出力するので、たとえば 12354 を `out(char)` すると「あ」が出力されます。

    一方、npiet 1.3h は C 言語の `getchar` と `printf("%c")` を使っていて、入出力は**バイト単位**です。`out(char)` は値の下位 8 ビットだけを出力するので、12354（16 進数で 0x3042）を出力すると、0x42 の「B」が出てしまいます。また `in(char)` は UTF-8 の日本語 1 文字を 3 つのバイトとして読みます。本書のサンプルは、どちらの処理系でも同じ結果になるように、入出力を ASCII の範囲に限っています。処理系ごとの違いは付録C にまとめています。

## 13.3 大文字に変換する

最初のフィルタは、英小文字を大文字に変換し、それ以外の文字はそのまま出力するプログラムです。ASCII では、`a`（97）〜`z`（122）と `A`（65）〜`Z`（90）の差はちょうど 32 です。

ふつうの言語なら `if` で書くところですが、ここでは**分岐を使わずに計算で**変換してみます。

```text
f = (c > 96) かつ (123 > c)   ; 小文字なら 1、そうでなければ 0
c = c - 32 * f
```

「かつ」は、0 か 1 の値どうしの掛け算で表せます。

```pasm
; 入力を大文字に変換して出力する（EOF まで）
loop:
        push 0          ; [0]            EOF 検出用の番兵
        inc             ; [0 c] または [0]
        dup
        jz eof          ; 何も読めなかった
        swap
        pop             ; [c]
        dup             ; [c c]
        push 96
        gt              ; [c (c>96)]
        pick 1          ; [c f1 c]
        push 123
        swap            ; [c f1 123 c]
        gt              ; [c f1 (123>c)]
        mul             ; [c f]          f = 1 なら英小文字
        push 32
        mul             ; [c 32f]
        sub             ; [c-32f]
        outc
        jmp loop
eof:
        halt
```

`123 > c` を作るところでは、`push 123` `swap` で `123` と `c` の順番を入れ替えています。`greater` は「2 番目 > 先頭」なので、比べる 2 つの値を正しい順に並べる必要があります。

@piet ch13/upper caption="英小文字を大文字にするフィルタ" input="Hello, Piet!\nabc xyz {}\n"

入力 `abc xyz {}` に対して `ABC XYZ {}` が出力されます。`{` と `}`（123 と 125）は小文字の範囲のすぐ外にあるので、境界のテストに使えます。空の入力では、最初の `in(char)` で EOF になり、何も出力せずに終わります。

分岐を使わないので、このプログラムは基本ブロックが少なく、配線も単純です。比較の結果を計算に使う書き方は、Piet では画像を小さくするのに有効です。

## 13.4 ROT13

ROT13 は、英字をアルファベット順に 13 文字ずらす簡単な暗号です。英字は 26 文字なので、2 回かけると元に戻ります。

大文字と小文字で計算が違うので、今度は分岐を使います。大文字 `c` は `(c - 65 + 13) mod 26 + 65` に、小文字は `(c - 97 + 13) mod 26 + 97` に変換し、それ以外の文字はそのまま出力します。

```pasm
; ROT13: 英字を 13 文字ずらす（EOF まで）
loop:
        push 0
        inc             ; [0 c] または [0]
        dup
        jz eof
        swap
        pop             ; [c]
        dup
        push 64
        gt              ; [c (c>64)]
        pick 1
        push 91
        swap
        gt              ; [c (c>64) (91>c)]
        mul             ; [c U]          U = 1 なら英大文字
        jnz upper       ; [c]
        dup
        push 96
        gt
        pick 1
        push 123
        swap
        gt
        mul             ; [c L]          L = 1 なら英小文字
        jnz lower       ; [c]
        outc            ; 英字以外はそのまま
        jmp loop
upper:
        push 52
        sub             ; [c-65+13]
        push 26
        mod
        push 65
        add
        outc
        jmp loop
lower:
        push 84
        sub             ; [c-97+13]
        push 26
        mod
        push 97
        add
        outc
        jmp loop
eof:
        halt
```

`c - 65 + 13` は `c - 52` と 1 回の引き算にまとめています。この値は大文字なら 13 以上なので、`mod` に負の数を渡す心配はありません（`mod` の符号は処理系によって違うのでした）。

@piet ch13/rot13 caption="ROT13 のフィルタ" input="Hello, World!\n"

`Hello, World!` は `Uryyb, Jbeyq!` になり、それをもう一度入力すると元に戻ります。``AZaz@[`{`` のような、英字の範囲の両端とそのすぐ外側の文字を並べた入力は、境界の判定をテストするのに便利です。

## 13.5 1 行を逆順に出力する

スタックは、後から積んだものが先に出てくる構造です。これを利用すると、文字列を逆順にするのはとても簡単です。読んだ文字を全部積んでから、先頭から順に出力するだけです。

ただし、どこまでが読んだ文字なのかを知るために、最初に**底の番兵** 0 を置いておきます。EOF 検出用の番兵と合わせて、2 種類の番兵を使うことになります。

```pasm
; 1 行を読んで逆順に出力する
        push 0          ; [0]            底の番兵
read:
        push 0
        inc             ; [0 .. 0 c] または [0 .. 0]
        dup
        jz eof
        swap
        pop             ; [0 .. c]
        dup
        push 10
        sub             ; [0 .. c c-10]
        jz newline      ; 改行なら読み込み終了
        jmp read
newline:
        pop             ; 改行を捨てる
        jmp print
eof:
        pop             ; EOF 検出用の 0 を捨てる
print:
        dup
        jz done         ; 底の番兵に着いた
        outc
        jmp print
done:
        push 10
        outc
```

読み込みのループは、改行を読んだときと EOF になったときの 2 か所から抜け出します。どちらの出口でも、`print:` に来るときにはスタックが `[0 c₁ c₂ … cₖ]` の形になるように、余分な値（改行文字、または EOF 検出用の 0）を `pop` しています。

@piet ch13/reverse caption="1 行を逆順に出力するプログラム" input="stressed\n"

`stressed` を入力すると `desserts` が出力されます。最後に改行のない入力（`Piet Mondrian` で入力が終わる場合）でも、EOF の出口から正しく `nairdnoM teiP` が出力されます。

!!! note "メモ"
    スタックの深さは、仕様上は無制限です。npiet もスタックを必要に応じて広げるので、長い行でも逆順にできます。ただし、すべての処理系がそうとは限りません。

## 13.6 文字と行を数える

UNIX の `wc` は、入力の行数・単語数・文字数（バイト数）を数えるコマンドです。ここでは行数と文字数を数えて、`行数 文字数` の形式で出力します。

スタックは `[L C]`（行数と文字数）です。1 文字読むたびに `C` を 1 増やし、その文字が改行なら `L` も 1 増やします。ここでも分岐を使わず、「改行なら 1」という値をそのまま `L` に足します。

```pasm
; 行数と文字数を数える（wc -l -c のようなもの）
        push 0          ; [L]
        push 0          ; [L C]
loop:
        push 0
        inc             ; [L C 0 c] または [L C 0]
        dup
        jz eof
        swap
        pop             ; [L C c]
        swap
        push 1
        add
        swap            ; [L C+1 c]
        push 10
        sub
        not             ; [L C f]        f = 1 なら改行
        swap            ; [L f C]
        bury 2          ; [C L f]
        add             ; [C L+f]
        swap            ; [L' C]
        jmp loop
eof:
        pop             ; [L C]
        swap
        outn            ; 行数
        push 32
        outc
        outn            ; 文字数
        push 10
        outc
```

`c - 10` を `not` すると、`c` が改行（10）のときだけ 1 になります。「等しいか」を `subtract` と `not` で 0 か 1 の値にする、よく使う組み合わせです。

`[L C f]` の `f` を、深さ 2 にある `L` に足すために、`swap` `bury 2` で `[C L f]` に並べ替えています。3 つの値の並べ替えは、`swap` と `bury`・`pick` の組み合わせで、たいていのものが 2〜3 手で書けます。

@piet ch13/wc caption="行数と文字数を数えるプログラム" input="one\ntwo\nthree\n"

`one`、`two`、`three` の 3 行（改行を含めて 14 文字）では `3 14` が、空の入力では `0 0` が出力されます。

## 13.7 数を 2 進数で出力する

第12章の「各桁の和」では、10 で割った余りで一の位から順に桁を取り出しました。2 進数も同じで、2 で割った余りが最下位のビットです。ただし、出力は**上の桁から**しなければなりません。取り出す順と出力する順が逆なので、ここでもスタックの「逆順」の性質が役に立ちます。取り出した桁を順に積んでおけば、先頭から出力するだけで上の桁から並びます。

桁は 0 か 1 なので、番兵には 2 を使います。

```pasm
; 整数を 2 進数で出力する
        inn             ; [n]
        push 2
        swap            ; [2 n]          2 は番兵（桁は 0 か 1）
loop:
        dup
        push 2
        mod             ; [2 .. n b]
        swap
        push 2
        div             ; [2 .. b n/2]
        dup
        jnz loop        ; n/2 が 0 でなければ続ける
        pop             ; [2 b_k .. b_0]  上位の桁が先頭
print:
        dup
        push 2
        sub
        jz done         ; 番兵に着いた
        outn
        jmp print
done:
        push 10
        outc
```

ループを抜けるのは商が 0 になったときなので、0 を入力しても最低 1 回はループの本体を実行し、`0` が出力されます。0 の扱いは、桁を取り出すプログラムでよく間違えるところです。

@piet ch13/binary caption="整数を 2 進数で出力するプログラム" input="10\n"

10 で `1010`、255 で `11111111`、0 で `0`、1 で `1` が出力されます。

## まとめ

- 文字は文字コードという整数で扱う。文字列の出力のコストは、ほとんどが文字コードを作る部分にかかる
- 文字列の出力方法には、素朴な方法・番兵とループ・差分の 3 つがある。どれが小さくなるかは場合によるので、測ってから選ぶ
- `in(char)` は EOF で無視されるので、事前に番兵の 0 を積んでおけば EOF を見分けられる（NUL 文字とは区別できない）
- 比較の結果（0 か 1）を掛け算や足し算に使うと、分岐なしで条件つきの計算ができる
- スタックは文字のバッファとして使え、逆順にする処理が自然に書ける。データの終わりは番兵で示す
- npiet の文字の入出力はバイト単位で、Unicode の文字は正しく扱えない

## 練習問題

1. 英大文字を小文字に変換し、それ以外の文字はそのまま出力するフィルタを書いてください。`Hello, PIET!` は `hello, piet!` になります。
2. 入力から数字（`0`〜`9`）の文字だけを取り出して出力し、最後に改行を出力するプログラムを書いてください。`Tel: 03-1234-5678 (ext. 9)` からは `03123456789` が出力されます。
3. 整数を 8 進数で出力するプログラムを書いてください。64 は `100`、511 は `777` です。番兵には何を使えばよいでしょうか。
4. 13.2 節の EOF の見分け方では、NUL 文字（文字コード 0）を EOF と区別できません。NUL 文字も扱えるようにするには、番兵の値をどう変えればよいでしょうか。また、そのとき npiet で問題が起きないかも考えてください。
5. 13.1 節の 3 つの方法を組み合わせて、`Hello, World!` と改行を出力する、もっと小さなプログラムを考えてください（決まった答えはありません）。
