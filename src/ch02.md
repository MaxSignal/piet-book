# 第2章 開発環境を整える

この章では、Piet のプログラムを手元のコンピュータで実行するための環境を整えます。中心になるのは、Piet の処理系として最もよく使われている **npiet** です。npiet をソースコードからビルドし、プログラムの実行、実行の追跡（トレース）、トレース画像の作成を試します。あわせて、本書付属の Python 製ツール（とくにエディタ兼デバッガの Piet スタジオ）と、画像編集ソフトで Piet のプログラムを描くときの注意点を説明します。

!!! abstract "この章で学ぶこと"
    - npiet 1.3h の入手とビルドの方法
    - npiet のコマンドラインオプションと、トレース・トレース画像の読み方
    - コーデルサイズの指定と自動推定の落とし穴
    - 本書付属の Python 製ツール（Piet スタジオ・piet.py・pasm.py）とブラウザ版ビューア
    - 画像編集ソフトで Piet を描くときの注意

## 2.1 処理系を選ぶ

Piet の処理系は世界中でたくさん作られています。C、Python、Rust、Go、JavaScript などの言語で書かれたインタプリタ、ブラウザで動く統合開発環境、Piet のプログラムを機械語に変換するコンパイラまであります（第20章で紹介します）。

本書では主に次の処理系を使います。

| 処理系 | 種類 | 本書での使い方 |
|---|---|---|
| Piet スタジオ | 本書付属の Python 製エディタ兼デバッガ（デスクトップアプリ） | 描く・実行する・1 ステップずつ追う。本書のメインの道具 |
| npiet 1.3h | C で書かれたコマンドラインのインタプリタ | 標準的な実行環境として使う |
| piet.py | 本書付属の Python 製インタプリタ | トレースの表示、第16章の題材 |

本書付属のツールはすべて Python で書かれています。Python は初学者にも扱いやすく、Windows・macOS・Linux のどれでも同じように動きます。付属ツールのソースコードは付録G にすべて載せてあるので、そこからファイルに保存して使ってください。

npiet は Erik Schoenfelder が開発しているインタプリタで、ソースコードは GPL バージョン 2 で公開されています。ソースの冒頭には 2004 年 5 月の日付があり、20 年以上にわたって保守が続いています。本書執筆時点の最新版は 2026 年 11 月 1 日に公開されたバージョン 1.3h です。npiet には次のプログラムが同梱されています。

- **npiet**: インタプリタ本体
- **npietedit**: Tcl/Tk で書かれた簡単な Piet エディタ
- **npiet-foogol**: ALGOL 風の小さな言語 foogol で書いたプログラムを Piet の画像に変換するコンパイラ（第18章で触れます）

!!! note "メモ"
    npiet の配布ページ https://www.bertnase.de/npiet/ には、Web ブラウザからプログラムをアップロードして実行できるオンライン版（npiet-execute.php）もあります。手元にビルド環境がない場合は、まずこちらで試してみてもよいでしょう。Windows 向けにはビルド済みのバイナリ（バージョン 1.3a）も配布されています。

## 2.2 npiet をビルドする

ここでは Linux（Debian や Ubuntu 系）を例に、ソースコードからビルドする手順を説明します。ほかの環境でも手順の流れは同じですが、必要なライブラリのパッケージ名やインストール方法は環境によって異なります。

### 必要なもの

npiet 本体は C コンパイラさえあればビルドできますが、そのままでは PPM 形式（テキストまたはバイナリで画素を並べただけの単純な画像形式）の画像しか読めません。PNG や GIF の画像を読むには、ビルドの前に次のライブラリの開発用パッケージを入れておく必要があります。

- **libpng**: PNG 画像の読み込み
- **libgd**（GD Graphics Library）: トレース画像の出力、および npiet-foogol に必要
- **giflib**: GIF 画像の読み込み（任意）

Debian や Ubuntu では、たとえば次のようにインストールします。

```sh
sudo apt-get install build-essential libpng-dev libgd-dev
```

### ダウンロードとビルド

配布ページから `npiet-1.3h.tar.gz` をダウンロードし、展開してビルドします。

```sh
curl -O https://www.bertnase.de/npiet/npiet-1.3h.tar.gz
tar xzf npiet-1.3h.tar.gz
cd npiet-1.3h
./configure
make
```

`configure` が、PNG・GD・GIF のライブラリが使えるかどうかを調べ、使えるものを組み込むように設定します。ビルドが終わったら、`-h` オプションで組み込まれた機能を確かめましょう。最初の行に、どの画像形式に対応しているかが表示されます。

```text
$ ./npiet -h
npiet v1.3h  (with GD support, without GIF support, with PNG support)

use: npiet [<options>] <filename>
```

この例では GD と PNG が有効で、GIF は無効です。`without PNG support` と表示された場合は、libpng の開発用パッケージが見つからなかったということです。パッケージを入れてから `./configure` をやり直してください。

システム全体で使えるようにするには、`make install` を実行します（通常は管理者権限が必要です）。インストールしない場合は、ビルドしたディレクトリの `./npiet` をそのまま使えます。本書の残りの部分では、`npiet` というコマンドで実行できるものとして説明します。

!!! tip "ヒント"
    PNG に対応していない npiet しか用意できない場合でも、画像を PPM 形式に変換すれば実行できます。たとえば ImageMagick があれば `convert prog.png prog.ppm` のように変換できます。本書付属の piet.py は PPM 形式での保存にも対応しています（第16章）。

## 2.3 プログラムを実行する

npiet でプログラムを実行するには、画像ファイルの名前を引数に指定します。第1章の最初のプログラムを実行してみましょう。

```text
$ npiet five.png
5
```

この章では、もう一つ小さなプログラムを用意しました。3 と 4 を足して 7 を出力するプログラムです。

@piet ch02/seven caption="3 + 4 を計算して 7 を出力するプログラム" zoom=40

左の青のブロックが 3 コーデル、その右の濃青のブロックが 2×2 の 4 コーデルです。青 → 濃青で 3 を積み、濃青 → 淡青で 4 を積み、淡青 → 淡マゼンタで足し算（`add`）をして、淡マゼンタ → 青で結果を出力（`out(number)`）します。

```text
$ npiet seven.png
7
```

### コマンドラインオプション

npiet 1.3h のオプションは次のとおりです（`npiet -h` の出力に基づきます）。

| オプション | 意味 |
|---|---|
| `-v` | 詳しい情報を表示する（推定したコーデルサイズなど） |
| `-q` | 入力命令の前にプロンプト `? ` を表示しない |
| `-w` | 警告を表示する（0 による除算、スタック不足など） |
| `-e <n>` | 実行するステップ数の上限（既定: 無制限） |
| `-t` | 1 ステップごとのトレースを表示する |
| `-ub` | 規定外の色を黒として扱う（既定は白） |
| `-uu` | 規定外の色をエラーにする |
| `-cs <n>` | 入力画像のコーデルサイズ（既定: 推定） |
| `-tpic` | トレース画像を作る（GD が必要） |
| `-tpf <n>` | トレース画像の拡大率 |
| `-tps` | DP・CC の情報を省いた簡易トレース画像を作る |
| `-ts <n>` / `-te <n>` | トレース画像に描くステップの開始・終了 |
| `-n-str <s>` | 文字列 s を出力するプログラムを生成する |
| `-d` | デバッグ情報を表示する |
| `-dpbug` | Perl 版インタプリタの挙動をまねる |
| `-v11` | npiet バージョン 1.1 の挙動をまねる |

よく使うのは `-q`、`-e`、`-t`、`-tpic`、`-cs` です。

**`-q`** は入力を使うプログラムで重要です。npiet は既定では、`in(number)` や `in(char)` 命令で入力を読む前に `? ` というプロンプトを標準出力に表示します。キーボードから対話的に使うには便利ですが、入力をファイルやパイプから与えて出力を比べたいときには邪魔になります。本書では、入力を使うプログラムは `-q` 付きで実行します。

```sh
echo 10 | npiet -q fact.png
```

**`-e`** は実行ステップ数の上限です。停止しないプログラムを試すとき、あるいはプログラムが意図せず無限ループに陥っているかを確かめたいときに使います。上限に達すると、npiet は次のようなメッセージを出して終了します。

```text
error: configured execution steps exceeded (12 steps)
```

## 2.4 トレースを読む

**`-t`** オプションを付けると、npiet は 1 ステップごとに、どこからどこへ移動し、どの命令を実行し、スタックがどうなったかを表示します。7 を出力するプログラムのトレースは次のとおりです。

```text
$ npiet -t seven.png

trace: step 0  (0,0/r,l nB -> 3,0/r,l dB):
action: push, value 3
trace: stack (1 values): 3

trace: step 1  (3,0/r,l dB -> 5,0/r,l lB):
action: push, value 4
trace: stack (2 values): 4 3

trace: step 2  (5,0/r,l lB -> 6,0/r,l lM):
action: add
trace: stack (1 values): 7

trace: step 3  (6,0/r,l lM -> 7,0/r,l nB):
action: out(number)
7
trace: stack is empty
```

`trace: step` の行は、次の形をしています。

```text
(移動元の x,y / DP,CC  色  ->  移動先の x,y / DP,CC  色)
```

- 座標は左上を (0,0) とするコーデル単位の座標です。x は右へ、y は下へ増えます。
- `r,l` は、**DP**（方向ポインタ）が右（right）、**CC**（コーデルチューザ）が左（left）であることを表します。DP と CC は、インタプリタが次にどちらへ進むかを決める 2 つの「向き」で、第5章で詳しく説明します。
- 色は 2 文字の略号で表されます。1 文字目が明度（`l` = light 淡、`n` = normal 通常、`d` = dark 濃）、2 文字目が色相（`R` 赤、`Y` 黄、`G` 緑、`C` シアン、`B` 青、`M` マゼンタ）です。白は `WW`、黒は `BB` と表示されます。

`action:` の行が実行した命令、`trace: stack` の行が命令を実行したあとのスタックです。npiet はスタックを**先頭から順に**表示する点に注意してください。`4 3` は「先頭が 4、その下が 3」という意味で、本書の表記では `[3 4]` になります。

### 本書付属のインタプリタのトレース

本書付属の piet.py でも、`-t` オプションでトレースを表示できます。表示は日本語で、スタックは本書の表記（左が底、右が先頭）です。

@trace ch02/seven

本書では、プログラムの動きを説明するときに主にこの形式のトレースを使います。

## 2.5 トレース画像を作る

npiet を GD 付きでビルドしていれば、**`-tpic`** オプションで実行の軌跡を描いた画像を作れます。画像はカレントディレクトリに `npiet-trace.png` という名前で保存されます。**`-tpf`** で拡大率（1 コーデルを何ピクセルで描くか）を指定できます。

```sh
npiet -tpic -tpf 64 seven.png
```

こうして作ったトレース画像が次の図です。

@img ch02/seven-trace.png caption="npiet -tpic で作ったトレース画像（-tpf 64）"

黒い線と丸が実行の経路を表し、線の上に実行した命令（`push(3)`、`push(4)`、`add`、`outN`）が書き込まれます。コーデルの隅の小さな文字は、インタプリタがそのコーデルから出ようと試みたときの記録で、上の段が「ステップ番号.試行番号」、下の段がそのときの DP と CC（`r/l` なら DP が右、CC が左）です。右端の青のブロックの周りに記録がいくつも並んでいるのは、最後のブロックから出ようとして 8 回失敗し、終了したことを示しています。

トレース画像は、プログラムが思ったとおりの経路を通っているかを確かめるのにとても便利です。長いプログラムでは、`-ts` と `-te` で描くステップの範囲を絞るとよいでしょう。

## 2.6 コーデルサイズ

Piet の 1 コーデルは、画像の 1 ピクセルである必要はありません。1 ピクセルのままでは小さすぎて見づらいので、Piet のプログラムは、1 コーデルを 10×10 ピクセルなどの正方形に拡大して配布されることがよくあります。この 1 辺のピクセル数を**コーデルサイズ**と呼びます。

npiet は、コーデルサイズを指定しないと画像から推定します。同じ色が縦または横に続く長さを調べ、その最小の単位をコーデルサイズとみなします。`-v` を付けると、推定した値が表示されます。本書のサンプルは、1 コーデル = 1 ピクセルの画像と、1 コーデル = 10 ピクセルの画像（ファイル名の末尾が `-big`）の両方を用意しています。

```text
$ npiet -v seven-big.png
info: verbose set to 1
info: using file seven-big.png
info: got 90 x 30 pixel with 256 cols
info: codelsize guessed is 10 pixel
7
info: program end
```

90×30 ピクセルの画像から、コーデルサイズ 10 が正しく推定されています。

### 推定が外れる場合

この推定は、たいていはうまくいきますが、万能ではありません。プログラムに含まれる色の並びが、縦にも横にもすべて偶数コーデルの長さになっていると、実際より大きなコーデルサイズが推定されてしまいます。次のプログラムは、1 コーデル = 1 ピクセルの画像として 4 を出力するように作ったものです。

@piet ch02/even caption="すべての色の並びが 2 の倍数になっているプログラム。コーデルサイズ 1 なら 4 を出力する" zoom=32

赤のブロックは 2×2 の 4 コーデルです。ところが、この画像では赤も濃赤も淡マゼンタも黒も、すべて 2 コーデル単位で並んでいるため、npiet はコーデルサイズを 2 と推定し、赤のブロックを 1 コーデルとみなしてしまいます。

```text
$ npiet -v even.png
info: verbose set to 1
info: using file even.png
info: got 8 x 6 pixel with 256 cols
info: codelsize guessed is 2 pixel
1
info: program end
$ npiet -cs 1 even.png
4
```

推定に頼らず `-cs 1` を指定すると、意図どおり 4 が出力されます。コーデルサイズを指定するのを習慣にしておくと、こうした思わぬ違いを避けられます。

!!! column "コラム: 2 通りに読める絵"
    コーデルサイズによって意味が変わる性質を逆手に取った作品もあります。作者のサンプル集には、コーデルサイズ 1 で実行すると「Hello world!」を、コーデルサイズ 2 で実行すると「Piet」を出力するプログラムが掲載されています（Matthias Ernst 作）。

本書には、Python 3 で書いたツールが付属しています。ソースコードは付録G に全文を載せているほか、本書のサンプルプログラムとあわせて GitHub（https://github.com/MaxSignal/piet-book）でも公開しています（CC0 1.0、パブリックドメイン提供）。同じフォルダ（本書では `tools/`）に置いて使います。

### Piet スタジオ

Piet スタジオ（`pietstudio.py`）は、本書のために作った Piet のエディタ兼デバッガです。Python に標準で付いている GUI ライブラリ tkinter だけで動くので、Python さえあれば追加のインストールなしに使えます。

```sh
python3 tools/pietstudio.py              # 新しいキャンバスで起動する
python3 tools/pietstudio.py prog.png     # 画像を開いて起動する
```

@img ch02/studio.png caption="Piet スタジオ。第12章の階乗のプログラムを開き、入力 5 を与えて 9 ステップ進めたところ。左の格子で、実行中のブロックが白黒の枠で、進む向き（DP）が三角形で示されている。中段の赤い点はブレークポイント"

!!! note "tkinter が見つからないとき"
    python.org から入手した Windows 版・macOS 版の Python には tkinter が含まれています。Ubuntu や Debian の Python では別パッケージになっていることがあり、`ModuleNotFoundError: No module named 'tkinter'` と表示されたら `sudo apt install python3-tk` でインストールします。

画面の左側がキャンバス、右側がパレットと実行パネルです。

- **描く**: パレットで色を選び、格子をクリック（ドラッグ）して塗ります。道具は「塗る」「塗りつぶし」（つながった同じ色のコーデルをまとめて塗る）「スポイト」（格子から色を拾う）の 3 つです。Ctrl+Z で元に戻せます。
- **命令から色を選ぶ**: パレットの各マスには、いま選んでいる色からその色へ移ったときに実行される命令が表示されます。たとえば赤を選んでいるとき、`push` と書かれたマスは濃赤です。命令と色の関係（第4章）を覚えていなくても、「次に実行したい命令」のマスを選べば正しい色になります。
- **調べる**: 格子の上にマウスを置くと、下のステータス欄にそのコーデルの座標・色・ブロックの大きさが表示されます。
- **実行する**: 「実行」（F5）で最後まで、「1 ステップ」（F10）で 1 回の移動だけ、「再生」（F6）で一定の速さで動かします。入力欄の内容が標準入力になり、出力・スタック・DP と CC・トレースが右側に表示されます。
- **ブレークポイント**: 格子を右クリックすると赤い点が付き、実行がそのコーデルを含むブロックに入ったところで止まります。ループの途中のスタックを調べるときに便利です（第19章）。
- **保存する**: 「ファイル」メニューから PNG・GIF・PPM で保存できます。保存時にコーデルサイズ（1 コーデルを何ピクセルで描くか）を指定します。本書のテキスト記法（第3章）での読み書きもできます。

これから先の章では、図のプログラムを Piet スタジオで描き写して動かしてみることをおすすめします。手を動かして描くと、色と命令の関係や、ブロックの形が実行の流れにどう影響するかが早く身につきます。

### piet.py

piet.py は次のように使います。

```sh
python3 tools/piet.py run prog.png            # 実行する
python3 tools/piet.py run -t prog.png         # トレースを標準エラーに表示しながら実行する
python3 tools/piet.py run -cs 10 prog-big.png # コーデルサイズを指定する
python3 tools/piet.py run -e 1000 prog.png    # 1000 ステップで打ち切る
python3 tools/piet.py show prog.png           # テキスト記法で表示する
python3 tools/piet.py png prog.txt prog.png   # テキスト記法から PNG 画像を作る
```

入力は標準入力から読みます。`show` サブコマンドは画像を本書のテキスト記法（第3章）に変換して表示するので、他人が作ったプログラムを調べるときにも便利です。

```text
$ python3 tools/piet.py show seven-big.png
BBB55bmB#
...55#BB#
......##.
```

piet.py は仕様に従って実装したインタプリタで、npiet とは細部の扱いが一部異なります（付録C）。本書のサンプルプログラムは、どちらで実行しても同じ結果になるように作ってあります。piet.py の作り方は第16章で解説します。

### pasm.py

pasm.py は、第1章で Hello World の画像を生成したアセンブラです。`push 72` や `out(char)` といった命令の列とジャンプを書いたテキストから、実行可能な Piet の画像を作ります。

```sh
python3 tools/pasm.py hello.pasm -o hello.png
```

## 2.8 画像編集ソフトで描く

Piet のプログラムは、普通の画像編集ソフト（GIMP、Krita、ペイントなど）で描くこともできます。ただし、写真やイラストを描くときとは違う注意が必要です。

**ブラシではなく鉛筆を使う。** 多くの画像編集ソフトのブラシは、縁を滑らかに見せるために中間色を塗ります（アンチエイリアス）。Piet では規定の 20 色以外の色は意味を持たないので、中間色が混じるとプログラムが壊れます。1 ピクセル単位で正確な色を塗る「鉛筆」ツールを使い、アンチエイリアスは切っておきます。

**色は数値で指定する。** 色は 16 進数の RGB 値で正確に指定します（第3章の色表、付録B を参照）。あらかじめ 20 色のパレットを作っておくと、塗るたびに数値を入力する手間が省けます。

**JPEG で保存しない。** JPEG は画質と引き換えにファイルを小さくする非可逆圧縮の形式で、保存のたびに色が微妙に変わってしまいます。必ず PNG か GIF（または PPM）のような可逆の形式で保存してください。

**拡大は「補間なし」で。** 1 コーデル = 1 ピクセルで描いたプログラムを拡大するときは、補間方法に「なし」（ニアレストネイバー法）を選びます。バイリニアなどの補間を使うと境目に中間色ができてしまいます。拡大率は整数にして、npiet には `-cs` で拡大率を伝えます。

**色の管理に注意する。** 画像ファイルに埋め込まれたカラープロファイルや、ソフトの色変換機能によって、保存した色の数値が変わることがあります。保存後に piet.py の `show` などで、意図した色になっているかを確かめると安心です。なお、npiet が `libpng warning: iCCP: known incorrect sRGB profile` という警告を出すことがありますが、これは画像に埋め込まれたプロファイル情報についての警告で、実行結果には影響しません。

!!! tip "ヒント"
    本書では、小さなプログラムはテキスト記法で書いて piet.py で画像に変換しています。テキストならエディタで編集でき、差分も取りやすく、色の数値を間違える心配もありません。Piet 専用のエディタやオンラインの開発環境については第20章で紹介します。

## まとめ

- 本書では npiet 1.3h を標準の処理系として使う。PNG を読むには libpng、トレース画像には libgd が必要。
- 入力を使うプログラムは `-q` で、停止しないかもしれないプログラムは `-e` で実行するとよい。
- `-t` でステップごとのトレースを、`-tpic` でトレース画像を得られる。npiet のトレースはスタックを先頭から表示する。
- コーデルサイズの推定は外れることがある。`-cs` で明示するのが安全。
- 画像編集ソフトで描くときは、鉛筆ツール・正確な RGB 値・可逆形式での保存・補間なしの拡大を守る。

## 練習問題

1. npiet を `-h` 付きで実行したところ、最初の行に `without PNG support` と表示されました。考えられる原因と対処方法を説明してください。
2. 入力を 1 つ読んで処理するプログラム `prog.png` に、ファイル `input.txt` の内容を与えて実行し、出力だけを `out.txt` に保存するコマンドを書いてください。
3. npiet のトレースに `(3,0/r,l dB -> 5,0/r,l lB)` と表示されました。移動元と移動先の位置、DP と CC、色をそれぞれ説明してください。
4. 1 コーデル = 1 ピクセルで描いたプログラム `a.png` を、画像編集ソフトで 12 倍に拡大して `a12.png` として保存しました。拡大のときに注意することと、npiet で確実に実行するためのコマンドを書いてください。
5. 2.6 節の `even.png` のように、コーデルサイズの推定が外れるプログラムを避けるには、プログラムを描く側でどんな工夫ができるでしょうか。
