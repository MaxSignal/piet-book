# 付録I Piet イディオム集

Piet のプログラムを書いていると、同じ形の命令の組が何度も出てきます。0 を積む、上の 2 つを入れ替える、2 つの数が等しいか調べる、文字列を出力する、といった小さな「決まった言い回し」です。この付録では、そうした言い回し（イディオム）を目的別に集めました。プログラムを描いていて「これはどう書けばいいのだったか」と迷ったときに引いてください。

!!! abstract "この付録の読み方"
    - 各イディオムには、**スタックの変化**、**コスト**、**解説している章**を示します。
    - スタックは本文と同じく `[a b]` のように書き、右端が先頭（トップ）です。`→` の左が実行前、右が実行後です。
    - コストは、1 行に並べたときに使うコーデルの数です。`push n` は直前のブロックが n コーデルになるので n、それ以外の命令は 1 と数えます（第17章 17.4 節）。
    - 命令の並びは、本書のアセンブラ pasm の書き方で示します。`swap` や `pick` などのマクロは、展開後の命令列もあわせて書きます（第17章 17.3 節）。
    - 図のプログラムはすべて、テキスト記法で書いて piet.py と npiet の両方で実行し、出力を確かめたものです。モノクロの図では、各コーデルの記号（淡: `r y g c b m`、通常: `R Y G C B M`、濃: `1`〜`6`、白 `.`、黒 `#`）で色を読み取ってください。

## I.1 数を積む

Piet には「数を書く」場所がありません。数はすべて、色ブロックの大きさ（コーデル数）と、それを組み合わせる計算から作ります（第6章 6.2 節、6.6 節）。

### push n ― 大きさ n のブロック

| スタック | コスト | 参照 |
|---|---|---|
| `[]` → `[n]` | n | 第6章 6.2 節 |

ブロックから出るときに `push` の色の変化（色相 0 段階・明度 1 段階）が起きると、**出ていくブロックの大きさ**が積まれます。1 から 12 程度までは、この方法がいちばん簡単です。大きいブロックは 1 行に並べる必要はなく、四角形や L 字でもかまいません（第15章 15.3 節）。

### 0 を積む ― push 1, not

| スタック | コスト | 参照 |
|---|---|---|
| `[]` → `[0]` | 2 | 第6章 6.6 節 |

大きさ 0 のブロックは存在しないので、`push` で 0 を直接積むことはできません。1 を積んで `not` で 0 にします。`not` は先頭が 0 なら 1、0 以外なら 0 にする命令です。

@piet appI/zero caption="0 を積んで出力する。`push 1`、`not`、`out(number)` の 3 命令"

@grid appI/zero

淡赤 `r`（1 コーデル）から赤 `R` へ移って 1 を積み、赤から淡緑 `g` へ移って `not`（色相 2 段階・明度 2 段階）、淡緑から黄 `Y` へ移って `out(number)` です。そのあと黄から濃黄 `2` の L 字形のブロックへ移る遷移（`push`）が最後の命令で、黒の囲みとあわせて終端のわなになっています（I.7 節）。

### 負の数 ― push 1, push n+1, subtract

| スタック | コスト | 参照 |
|---|---|---|
| `[]` → `[-n]` | n + 3 | 第6章 6.6 節 |

負の数も直接は積めません。`1 − (n + 1) = −n` を計算します。0 を積んで n を引く方法（`push 1, not, push n, subtract`、コスト n + 4）より 1 コーデル少なく済みます。−5 なら `push 1`、`push 6`、`subtract` です。

@piet appI/neg caption="−5 を積んで出力する（1 − 6）"

### 掛け算で大きな数を作る

| スタック | コスト | 参照 |
|---|---|---|
| `[]` → `[a×b]` | a + b + 1 | 第6章 6.6 節、第17章 17.4 節 |

100 を 100 コーデルのブロックで積むのは大変です。`push a, push b, multiply` なら a + b + 1 コーデルで済みます。さらに、同じ数を掛けるなら `duplicate` で複製して `multiply` する（平方）と、b のぶんのブロックが要りません。

```pasm
push 2
push 5
multiply      ; [10]
duplicate     ; [10 10]
multiply      ; [100]
```

@piet appI/hundred caption="100 を 2 × 5 = 10 の平方として作る（14×3 コーデル）"

どの分解がいちばん安いかは、本書のアセンブラが動的計画法で求めています（第17章 17.4 節）。手で描くときの目安は、「2 つの近い数の積」「平方」「平方に小さい数を足す」です。

### 文字コードを積む

| スタック | コスト | 参照 |
|---|---|---|
| `[]` → `[65]` | 12 | 第7章 7.2 節 |

文字を出力するには、その文字コードを積んで `out(char)` を実行します。英大文字は 65〜90、英小文字は 97〜122 なので、64（8 の平方）や 100（10 の平方）を土台にすると短くなります。`A`（65）は 8 × 8 + 1 です。

```pasm
push 8
duplicate
multiply      ; [64]
push 1
add           ; [65]
out_char      ; A
```

@piet appI/char_a caption="`A`（65 ＝ 8 × 8 ＋ 1）を出力する"

## I.2 スタックを操作する

Piet の命令でスタックの並びを変えられるのは `duplicate`・`pop`・`roll` の 3 つだけです。ほかの操作は、すべて `roll` の組み合わせで作ります（第11章）。

### duplicate と pop

| 名前 | スタック | コスト | 参照 |
|---|---|---|---|
| `duplicate` | `[a]` → `[a a]` | 1 | 第11章 11.1 節 |
| `pop` | `[a]` → `[]` | 1 | 第6章 6.3 節 |

`duplicate` は先頭を複製し、`pop` は先頭を捨てます。計算に使うと値が消えてしまうので、あとでもう一度使う値は先に `duplicate` しておくのが基本です。

### swap ― 上の 2 つを入れ替える

| スタック | コスト | 参照 |
|---|---|---|
| `[a b]` → `[b a]` | 4 | 第11章 11.3 節 |

`push 2, push 1, roll` です。`roll` は「深さ 2 の範囲で 1 回転がす」と読みます。先頭の b が 1 つ下に潜り、a が先頭に出てきます。

@piet appI/swap caption="1 と 2 を積んで入れ替え、上から順に出力する。出力は 12"

@grid appI/swap

`[1 2]` を入れ替えると `[2 1]` になり、先頭の 1、次の 2 の順に出力されるので `12` と表示されます。入れ替えなければ `21` です。

### over ― 2 番目を複製する

| スタック | コスト | 参照 |
|---|---|---|
| `[a b]` → `[a b a]` | 10 | 第11章 11.3 節 |

2 番目の値を先頭に複製します。後述の `pick 1` と同じで、`push 2, push 1, roll, duplicate, push 3, push 1, roll` に展開されます。いったん `swap` して a を先頭に出し、`duplicate` してから、複製の片方を深さ 3 の位置へ戻す、という手順です。

@piet appI/over caption="`[3 5]` に over を適用して `[3 5 3]` にし、3 回出力する。出力は 353"

### rot と -rot ― 上の 3 つを回す

| 名前 | スタック | コスト | 参照 |
|---|---|---|---|
| `rot` | `[a b c]` → `[b c a]` | 6 | 第11章 11.3 節 |
| `-rot` | `[a b c]` → `[c a b]` | 5 | 第11章 11.3 節 |

`rot` は 3 番目を先頭に引き出し（`push 3, push 2, roll`）、`-rot` は先頭を 3 番目に沈めます（`push 3, push 1, roll`）。「深さ 3 で 2 回転がす」は「逆向きに 1 回転がす」と同じなので、`rot` を `push 3, push 1, push 2, subtract, roll` と書く必要はありません。

@piet appI/rot caption="`[1 2 3]` に rot を適用して `[2 3 1]` にし、3 回出力する。出力は 132"

### pick n と bury n ― 任意の深さ

| 名前 | スタック | コスト | 参照 |
|---|---|---|---|
| `pick n` | 深さ n の値を先頭に複製 | 3n + 7 | 第11章 11.3 節 |
| `bury n` | 先頭を深さ n へ沈める | n + 3 | 第11章 11.3 節 |

深さは先頭を 0 と数えます。`pick 0` は `duplicate`、`pick 1` は `over` です。`pick n` は「深さ n + 1 の範囲を n 回転がして目的の値を先頭に出し、`duplicate` して、片方を元の深さに戻す」という 3 段階の手順です。`bury n` は `push n+1, push 1, roll` だけで済みます。

スタックの決まった深さに置いた値を「変数」として扱うときは、読むのが `pick`、書くのが「`bury` してから古い値を捨てる」になります（第11章 11.4 節、第18章）。深さは値を積むたびに変わるので、プログラムの各行に `[n acc]` のようなスタックの形をコメントで書いておくのが安全です。

### nip と 2dup

| 名前 | スタック | 命令列 | コスト |
|---|---|---|---|
| `nip`（2 番目を捨てる） | `[a b]` → `[b]` | `swap, pop` | 5 |
| `2dup`（上の 2 つを複製） | `[a b]` → `[a b a b]` | `over, over` | 20 |

`2dup` は、比較で値を消費する前に 2 つとも残しておきたいときに使います。コストが大きいので、比較の結果だけあれば足りる場面では使わないように、スタックの形を工夫するとよいでしょう。

## I.3 算術と比較

Piet の比較命令は `greater`（2 番目 > 先頭 なら 1）だけです。真偽値は 1 と 0 で表し、ほかの比較は `greater`・`not`・`subtract` の組み合わせで作ります（第9章 9.1 節）。

### 等しい・等しくない

| 名前 | スタック | 命令列 | コスト |
|---|---|---|---|
| a = b | `[a b]` → `[1 か 0]` | `subtract, not` | 2 |
| a ≠ b | `[a b]` → `[1 か 0]` | `subtract, not, not` | 3 |

差が 0 なら等しい、という考え方です。`not` を 2 回重ねると、0 以外の値を 1 にそろえる「真偽値への正規化」になります。`pointer` で分岐するときは値が 0 か 1 であることが大切なので、この正規化はよく使います（第9章 9.3 節）。

@piet appI/eq caption="2 つの数を読み、等しければ 1、等しくなければ 0 を出力する（入力 4 と 4）"

### 大小の比較

| 名前 | 命令列 | コスト | 考え方 |
|---|---|---|---|
| a > b | `greater` | 1 | そのまま |
| a ≤ b | `greater, not` | 2 | a > b の否定 |
| a ≥ b | `push 1, subtract, greater` | 3 | 整数なら a > b − 1 |
| a < b | `swap, greater` | 5 | b > a |

いずれも `[a b]` → `[1 か 0]` です。a ≥ b を `swap, greater, not`（6 コーデル）と書くより、`push 1, subtract, greater` のほうが短く済みます。整数だけを扱う Piet ならではの近道です。

@piet appI/ge caption="2 つの数 a、b を読み、a ≥ b なら 1 を出力する（入力 5 と 5）"

### かつ・または・でない（真偽値の演算）

| 名前 | スタック | 命令列 | コスト |
|---|---|---|---|
| p かつ q | `[p q]` → `[p∧q]` | `multiply` | 1 |
| p または q | `[p q]` → `[p∨q]` | `add, not, not` | 3 |
| p でない | `[p]` → `[¬p]` | `not` | 1 |
| p と q が異なる（排他的論理和） | `[p q]` → `[p⊕q]` | `subtract, not, not` | 3 |

p と q が 0 か 1 のとき、積は「かつ」、和を正規化したものは「または」になります。`add` の結果は 2 になりうるので、`pointer` に渡す前には `not, not` で 0 か 1 にそろえます。条件を組み合わせると、分岐の回数を減らせます。

### 範囲に入っているか ― lo ≤ x ≤ hi

| スタック | コスト（lo = 3、hi = 8 の例） |
|---|---|
| `[x]` → `[1 か 0]` | 27 |

`(x > lo − 1)` と `(hi + 1 > x)` を作って掛け合わせます。文字が英大文字かどうか（65〜90）を調べるときなどに使います（第13章 13.3 節）。

```pasm
duplicate     ; [x x]
push 3
push 1
subtract      ; [x x 2]
greater       ; [x g1]     g1 = (x > 2)
swap          ; [g1 x]
push 8
push 1
add           ; [g1 x 9]
swap          ; [g1 9 x]
greater       ; [g1 g2]    g2 = (9 > x)
multiply      ; [g1∧g2]
```

@piet appI/inrange caption="数を読み、3 以上 8 以下なら 1、そうでなければ 0 を出力する（入力 5）"

### 商と余りを同時に求める

| スタック | コスト |
|---|---|
| `[a b]` → `[a b a÷b]` → … → `[a mod b]` | 21（2dup ＋ divide） |

`divide` と `mod` はどちらも 2 つの値を消費するので、両方が欲しいときは先に `2dup` で複製します。10 で割った商と余りを繰り返し求めれば、数を 1 桁ずつに分解できます。負の数の割り算は、仕様（切り捨てか床関数かは書かれていない）と npiet（0 方向への切り捨て）とで結果が変わることがあるので、正の数で使うのが安全です（付録C）。

@piet appI/divmod caption="2 つの数を読み、商、空白、余りを出力する（入力 17 と 5、出力 3 2）"

### 偶奇 ― push 2, mod

| スタック | コスト | 参照 |
|---|---|---|
| `[x]` → `[x mod 2]` | 3 | 第6章 6.4 節 |

奇数なら 1、偶数なら 0 になります。「偶数なら 1」が欲しいときは、続けて `not` を実行します。仕様では `mod` の結果は除数と同じ符号（ここでは 0 か 1）ですが、npiet では負の数の `mod` が負になります（付録C）。負の数の偶奇を調べるときは、先に絶対値にしておくと処理系に左右されません。

@piet appI/odd caption="数を読み、2 で割った余りを出力する（入力 7）"

### 絶対値 ― 分岐を使わない書き方

| スタック | コスト |
|---|---|
| `[x]` → `[|x|]` | 10 |

x が正なら 1、そうでなければ −1 を作って x に掛けます。x = 0 のときは何を掛けても 0 なので、符号の作り方が雑でも結果は正しくなります。

```pasm
duplicate     ; [x x]
push 1
not           ; [x x 0]
greater       ; [x p]     p = (x > 0)
push 2
multiply
push 1
subtract      ; [x s]     s = 2p − 1（1 か −1）
multiply      ; [|x|]
```

@piet appI/abs caption="数を読み、絶対値を出力する（入力 −7）"

### 符号 ― (x > 0) − (0 > x)

| スタック | コスト |
|---|---|
| `[x]` → `[1, 0, −1 のどれか]` | 16 |

```pasm
duplicate
push 1
not
greater       ; [x p]     p = (x > 0)
swap          ; [p x]
push 1
not
swap          ; [p 0 x]
greater       ; [p n]     n = (0 > x)
subtract      ; [p − n]
```

### 大きいほう・小さいほう

最大値は、分岐を使うのがいちばん短く書けます。

```pasm
              ; [a b]
over
over          ; [a b a b]   （2dup）
greater       ; [a b g]     g = (a > b)
jz takeb
pop           ; [a]         a のほうが大きい
jmp done
takeb:
swap
pop           ; [b]
done:
```

分岐を使わずに `b + (a − b) × g` を計算する書き方もありますが、`pick` を何度も使うので 50 コーデル以上かかります。最小値は `greater` の向きを入れ替えて作ります（第9章 9.5 節）。

## I.4 分岐する

Piet には条件ジャンプがありません。DP（方向ポインタ）や CC（コーデルチューザ）を値によって変えることで、流れを分けます（第9章）。

### pointer で 2 方向に分ける

| スタック | コスト | 参照 |
|---|---|---|
| `[c]` → `[]`（c は 0 か 1） | 1 | 第9章 9.3 節 |

`pointer` は先頭の値の回数だけ DP を時計回りに回します。c = 0 なら右のまま、c = 1 なら下へ曲がります。c が 0 と 1 以外の値を取りうるときは、先に `not, not` で正規化します。上へ曲げたいときは `push 3, multiply` で 0 か 3 にしてから `pointer` を実行します（3 回の時計回りは反時計回り 1 回と同じです）。本書のアセンブラはこの形で条件分岐を作っています（第17章 17.9 節）。

@piet appI/branch caption="数を読み、偶数なら E、奇数なら O を出力する（入力 7）"

### switch で 2 方向に分ける

| スタック | コスト | 参照 |
|---|---|---|
| `[c]` → `[]` | 1 | 第9章 9.4 節 |

`switch` は CC を切り替えます。CC は「辺のどちら端から出るか」を決めるので、出口の辺が 2 コーデル以上ある形のブロックで使うと、値によって出口が変わります。`pointer` と違って進む向きは変わらないため、平行な 2 本の道に分けたいときに向いています。なお npiet は負の値の `switch` で CC を切り替えないので、値は 0 以上にしておきます（付録C）。

### 合流する

分かれた 2 本の道は、白の通路で同じ色ブロックへ導けば合流します。白を通って色ブロックに入っても命令は実行されないので、どちらの道から来ても、合流したブロックから先の命令は同じになります（第9章 9.5 節）。合流した直後の DP と CC が道によって違うことがあるので、合流点のブロックは 1 コーデルにしておくと、CC の違いに左右されずに済みます。

## I.5 繰り返す

ループは、流れが時計回りに一周して元の色ブロックに戻る形で作ります（第10章 10.1 節）。

### n 回繰り返す ― カウンタを減らしながら

| スタック | 参照 |
|---|---|
| `[n]` → `[]` | 第10章 10.2 節 |

```pasm
  inn            ; [n]
loop:
  dup            ; [n n]
  jz done        ; [n]
  push 42
  outc           ; * を出力
  push 1
  sub            ; [n-1]
  jmp loop
done:
  pop
```

先頭でカウンタを `duplicate` して 0 かどうか調べ、0 でなければ本体を実行してカウンタを 1 減らします。入力が 0 のときは本体を一度も実行しません。

@piet appI/repeat caption="数 n を読み、`*` を n 個出力する（入力 5、pasm で生成）"

### 番兵まで繰り返す ― 文字列の出力

| スタック | 参照 |
|---|---|
| `[0 c_k … c_1]` → `[]` | 第13章 13.1 節 |

文字列を出力するときは、先に「終わりの印」の 0（番兵）を積み、文字を**逆順**に積んでおきます。あとは「先頭を複製して 0 なら終わり、そうでなければ出力」を繰り返します。文字ごとに `push` と `out(char)` を並べるより、文字列が長くなるほど短く描けます。

```pasm
  push 0         ; 番兵
  push 10        ; 改行
  push 105       ; i
  push 72        ; H
loop:
  dup
  jz done
  outc
  jmp loop
done:
  pop
```

@piet appI/strloop caption="番兵 0 と逆順の文字を積み、0 が出るまで出力する。出力は Hi と改行"

### 入力の終わりまで繰り返す

| 参照 |
|---|
| 第10章 10.4 節、第13章 13.2 節 |

`in(char)` は、入力が終わっていると何もしません（無視されます）。そこで、読む前に番兵の 0 を積んでおきます。読めれば `[0 c]`、読めなければ `[0]` が残るので、先頭が 0 かどうかで入力の終わりを見分けられます。

```pasm
loop:
  push 0         ; 読めなかったときに残る番兵
  inc            ; [0 c] または [0]
  dup
  jz done        ; 先頭が 0 なら入力の終わり
  outc           ; [0]
  pop            ; []
  jmp loop
done:
  pop
```

@piet appI/cat caption="入力を最後まで 1 文字ずつ写す（入力 Piet と art の 2 行）"

この方法では、入力に文字コード 0 の文字が含まれていると、そこで止まってしまいます。0 も通したいときは、番兵を −1 にして「−1 と等しいか」で調べます（付録D の第13章の解答）。

## I.6 出力する

### 数を出力して改行する

| スタック | コスト | 参照 |
|---|---|---|
| `[x]` → `[]` | 12 | 第7章 7.5 節 |

`out(number)` は改行を出力しないので、続けて `push 10, out(char)` を実行します。10 のブロックが大きく感じられるときは、`push 2, push 5, multiply`（8 コーデル）でも作れます。

@piet appI/numnl caption="6 × 7 を計算し、42 と改行を出力する"

### 1 桁の数を文字として出力する ― 48 を足して out(char)

| スタック | コスト |
|---|---|
| `[d]` → `[]`（d は 0〜9） | 17（48 ＝ 6 × 8） |

数字の文字 `0`〜`9` の文字コードは 48〜57 です。0〜9 の値に 48 を足して `out(char)` で出力すれば、`out(number)` を使わずに数字を表示できます。数を 1 桁ずつ取り出して桁ごとに処理するとき（2 進数や 16 進数の表示、桁区切りの挿入など）に使います（第13章 13.7 節）。

@piet appI/digit caption="7 に 48 を足して文字 7 を出力する"

### 数を読む ― in(number) を続けて使う

| スタック | 参照 |
|---|---|
| `[]` → `[n]` | 第7章 7.4 節 |

`in(number)` は、前にある空白や改行を読み飛ばしてから整数を読みます。そのため、`4 4` のように空白で区切った入力も、1 行に 1 つずつの入力も、`in(number)` を続けて実行すれば順に読めます。入力が終わっているときや数でないものが来たときは、命令が無視されて何も積まれません。読んだ数の個数が分からない入力を最後まで処理したいときは、`in(char)` と同じように、先に番兵を積んでおく方法が使えます（I.5 節）。なお npiet は、`-q` オプションを付けないと入力のたびに `? ` を出力します（第2章、付録C）。

### 1 文字ずつ出す ― push と out(char) の繰り返し

短い文字列なら、文字ごとに「文字コードを積んで `out(char)`」を並べるのがいちばん素直です（第7章 7.3 節）。ループを作る手間がないぶん、2〜3 文字程度なら I.5 節の番兵ループより短く済むこともあります。どちらが短いかは、文字コードを作るコストの合計と、ループの配線にかかるコーデル数を比べて決めます（第13章 13.1 節）。

## I.7 形のテクニック

最後に、命令ではなくブロックの「形」や「置き方」に関わるイディオムです。

### 終端のわな

| 参照 |
|---|
| 第5章 5.5 節、第17章 17.7 節 |

Piet には停止命令がないので、プログラムを終わらせるには「入ったら二度と出られないブロック」を用意します。本書でよく使うのは、最後のブロックの右に置く 3 コーデルの L 字形のブロックを、黒と画像の端で囲む形です。

```text
B P T #
# T T #
. # # .
```

B が直前のブロック、P が最後の命令のブロック、T がわなのブロックです（`#` は黒、`.` は白）。T のどの辺から、どの DP・CC で出ようとしても黒か画像の端にぶつかるので、8 回の試行がすべて失敗して停止します。P から T へ移るときにも命令が 1 つ実行されるので、T の色は、その遷移が無害な `push` になるか、最後に実行したい命令そのものになるように選びます。I.1 節の 0 を出力するプログラムでは、`out(number)` を実行したあと、T（濃黄）へ入る遷移が無害な `push` になっています。

### 角を曲がる

| 参照 |
|---|
| 第5章 5.4 節、第8章 8.2 節 |

色ブロックの中で進めないとき、インタプリタは CC を切り替え、次に DP を時計回りに回して、出口を探します。これを利用すると、画像の端や黒いコーデルに沿って、命令を使わずに流れを時計回りに曲げられます。反時計回りに曲げたいときは `push 3, pointer` を使います（I.4 節）。

### 白の通路

| 参照 |
|---|
| 第8章 8.1 節 |

白い領域に入ると、インタプリタは DP の向きにまっすぐ滑り、次の色ブロックに入ります。このとき命令は実行されません。命令と命令のあいだに白を挟めば、色の並びを気にせずにブロックを離れた場所へ置けます。

@piet appI/corridor caption="2 を積んだあと白の通路を 4 マス滑り、その先で 2 を出力する"

@grid appI/corridor

1 行目の `rrR` で 2 を積み、白 `....` を滑って 2 つ目の赤 `R` に入ります。白を通ったので、このとき命令は実行されません。2 つ目の赤から濃マゼンタ `6` へ移るところで `out(number)` が実行され、2 が出力されます。

### 色だけを変える無害な命令の組

| 命令の組 | スタック | コスト |
|---|---|---|
| `push 1, multiply` | `[x]` → `[x]` | 2 |
| `push 1, pop` | `[x]` → `[x]` | 2 |
| `duplicate, pop` | `[x]` → `[x]` | 2 |

スタックを変えずに色だけを進めたいときは、打ち消し合う命令の組を挟みます。次の命令に必要な色にたどり着くための調整や、見た目の配色を整えるのに使います（第15章 15.5 節）。

## I.8 デバッグのためのイディオム

プログラムが思ったとおりに動かないとき、途中の値を確かめるための小さな言い回しです（第19章）。

### 先頭の値をのぞく

| スタック | 命令列 | コスト |
|---|---|---|
| `[x]` → `[x]` | `duplicate, out(number), push 10, out(char)` | 13 |

先頭を複製してから出力し、改行を加えます。スタックは元のままなので、プログラムのどこに挟んでも計算に影響しません。ただし色の並びは 4 段ぶん進むので、挟んだあとの色をすべて描き直すことになります。本書のアセンブラで書いたプログラムなら、ソースに 4 行足して作り直すだけで済みます（第17章）。

### 目印のブロックで止める

Piet スタジオでは、右クリックでブレークポイントを置いたブロックに実行が入ったところで止まります（第19章 19.4 節）。ループの先頭や分岐の直後のブロックに置き、止まるたびにスタックと DP・CC を確かめると、どこで想定と違う流れになったかを絞り込めます。

### トレースで遷移を数える

`npiet -t` や `piet.py run -t` のトレースは、1 ステップ（色ブロックからの 1 回の移動）ごとに 1 行を出力します（第19章 19.2 節）。ループが何周したか、どこで終端のわなに入ったかは、トレースの行を数えたり、特定の命令の行を検索したりすると確かめられます。止まらないプログラムは、npiet の `-e` や piet.py の `-e` でステップ数の上限を付けて実行します（第19章 19.6 節）。

## まとめ

- 0・負の数・大きな数は、`push` の組み合わせと計算で作る。大きな数は積や平方で作ると短い。
- スタックの並び替えは、すべて `roll` から作る。`swap`（4）、`rot`（6）、`over`（10）のコストを覚えておくと、設計の見積もりに役立つ。
- 比較は `greater`・`not`・`subtract` の組み合わせで作る。真偽値の「かつ」は積、「または」は和の正規化。分岐の前には、値を 0 か 1 に正規化する。
- 繰り返しは「先頭を複製して 0 か調べる」形が基本。文字列や入力は、番兵の 0 で終わりを見分ける。
- 形のテクニック（わな、角、白の通路、無害な命令の組）を使うと、命令の並びと画像の配置を切り離して考えられる。
- 途中の値は「`duplicate` してから出力」でのぞける。Piet スタジオのブレークポイントやトレースと組み合わせて使う。
