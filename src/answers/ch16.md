### 問題 16-1

`Program.from_image()` はすでに引数 `unknown` を持っているので、コマンドラインから渡すだけです。`main()` の `run` サブコマンドに次のように追加します。


```python
r.add_argument("-ub", action="store_true", help="規定外の色を黒とみなす")
...
prog = Program.from_image(a.file, a.cs, unknown="black" if a.ub else "white")
```

npiet の `-uu`（規定外の色をエラーにする）も欲しければ、`unknown="error"` のときに `RGB2COL.get(v)` が `None` なら例外を投げるようにします。

### 問題 16-2

`Machine` に `collections.Counter` を持たせ、`execute()` の先頭で数えます。


```python
from collections import Counter

class Machine:
    def __init__(self, ...):
        ...
        self.stats = Counter()

    def execute(self, cmd, size):
        self.stats[cmd] += 1
        ...
```

終了後に `for cmd, n in m.stats.most_common(): print(cmd, n)` で表示します。無視された命令を別に数えたいときは、`execute()` の戻り値が `"ignored"` のときに `self.stats[cmd + "（無視）"] += 1` とします。

### 問題 16-3

0 の方向へ丸める除算は、絶対値で割ってから符号を付けます。


```python
def tdiv(a, b):
    q = abs(a) // abs(b)
    return q if (a >= 0) == (b >= 0) else -q

def tmod(a, b):
    return a - b * tdiv(a, b)
```

`Machine` に `self.c_div = False` のような設定を持たせ、`divide` と `mod` の計算をこの関数に切り替えます。−7 ÷ 2 の商は、床除算では −4、0 方向への丸めでは −3 です。−7 を 3 で割った余りは、仕様（除数と同じ符号）では 2、0 方向への丸めでは −1 です。後者は npiet 1.3h の結果と一致します（[付録C](appC.html)）。

### 問題 16-4

DP が下向きのとき、進行方向（画面の下）を向いて立つと、自分の左手は画面の右側（x が大きい側）を指します。CC の「左」はこの左手の方向なので、縁の上で x が最大のコーデルを選びます。同じ考え方で、DP が上向きなら左手は画面の左側（x が最小）、DP が左向きなら左手は画面の下側（y が最大）になります。


### 問題 16-5

入力を使わないプログラムの次の状態は、現在の「位置・DP・CC・スタック」だけで決まります（出力は状態に影響しません）。したがって、ある状態が以前と完全に一致したら、それ以降はまったく同じ遷移が繰り返され、永久に停止しません。


```python
def run_detect(self, max_steps=1_000_000):
    seen = set()
    while self.steps < max_steps:
        key = (self.x, self.y, self.dp, self.cc, tuple(self.stack))
        if key in seen:
            raise RuntimeError(f"無限ループを検出（{self.steps} ステップ目）")
        seen.add(key)
        if not self.step():
            break
    return "".join(self.out)
```

この方法では、スタックが際限なく伸びていくループや、値が増え続けるループ（たとえば 1, 2, 3, … と数え続けるプログラム）は検出できません。状態が二度と同じにならないからです。一般に、任意のプログラムが停止するかどうかを判定する手続きは存在しない（停止性問題）ので、この種の検出は「見つかれば確実に無限ループ」という片側だけの道具になります。また、記録する状態が増え続けるので、長く動くプログラムではメモリを多く使います。
