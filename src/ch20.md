## 20.1 誕生と仕様の歩み

Piet は、David Morgan-Mar が設計した言語です。彼は Ook! をはじめ、いくつもの難解プログラミング言語（esoteric programming language、esolang）を作っています。名前は、幾何学的な抽象画の先駆者である画家ピート・モンドリアン（Piet Mondrian）にちなみます。仕様のページによると、作者は本当は「Mondrian」と名付けたかったのですが、その名前はすでに「ありふれた見た目の」スクリプト言語に使われていたため、ファーストネームの Piet を選んだそうです。

後のインタビューで、作者は Piet が自分の言語の中では「かなり早い時期」の作品で、おそらく Ook! の後に作ったと語っています。きっかけは Befunge（2 次元のプログラミング言語）で、「本物の画像をプログラムのコードとして使えないか」と考えたことでした。

正確な公開日は仕様のページに書かれていません。Esolangs wiki は Piet を 2001 年の言語として分類しています。Internet Archive に残る仕様のページの最も古い記録は 2002 年 4 月 10 日のもので、その時点ですでに、2002 年 1 月の MIT ミステリーハント（大規模なパズル大会）の第 2 ラウンドで Piet が使われたことに触れています。

仕様のページは、その後何度か加筆されています。Internet Archive の記録を比べると、主な変更は次のとおりです。

| 時期 | 主な変更 |
|---|---|
| 2002 年（最古の記録） | 20 色以外の色の扱い（白とみなす、または黒とみなす）、負の深さの `roll` を無視することは、この時点ですでに書かれている |
| 2008 年 1 月 25 日 | 「白ブロックの振る舞いの明確化」の節を追加。白の中で止められたときの動作と、同じ経路の再走査による停止を定める |
| 2014 年 | 「この仕様はずっと前に書いた」で始まる注記を追加。0 による除算は無視を推奨、`mod` の結果は除数と同じ符号、スタックや整数のあふれ、入力がないときの `in`、`roll` の深さの上限などを追記 |
| 2017 年 7 月 6 日 | `mod` についての注記（5、2、−1、−4 を 3 で割った余りはすべて 2、つまり床除算と同じ）と、競技やパズルでの Piet の利用についての段落を追加 |
| 2018 年 9 月 27 日 | 現在のページの最終更新日（内容は 2017 年版と同じ） |

作者自身は「権威ある」インタプリタを書いておらず、仕様についての質問には「あなたがいちばん筋が通ると思うやり方で」と答えてきた、と仕様のページに書いています。処理系ごとに細部の解釈が異なるのはこのためです（[付録C](appC.html)）。

!!! column "コラム: 作者のお気に入り"
    作者はインタビューで、驚かされた作品として Thomas Schoch の「Artistic Hello World」と、Richard Mitton の円周率のプログラムを挙げています。Mitton の作品は、円の形に塗られたブロックの面積を半径で 2 回割ることで円周率を近似するという、Piet ならではの発想のプログラムです。どちらも公式のサンプル集で見ることができます。

## 20.5 Piet から変換する道具

逆に、Piet の画像を読んで、別の言語や機械語に **変換する** コンパイラもあります。

| 名前 | 作者 | 概要 |
|---|---|---|
| repiet | Kelly Boothby | Piet をブロック単位で解析してグラフ形式の中間表現にし、最適化して Python・C++・Piet を出力する |
| PietCC | pwang00 | Rust と LLVM による処理系。制御フローグラフを作り、白ブロックを取り除き、一部の無限ループの検出や定数の畳み込みを行う |
| pietc | cobbal | C++ と LLVM（2011 年） |
| pietc | nokijp | Haskell と LLVM でネイティブの実行ファイルを作る（2019 年） |
| llvm-piet | allanlw | LLVM（2012 年） |
| Pietric | sh-mug | C++ と LLVM（2025 年） |

Piet を「コンパイル」するとは、どういうことでしょうか。Piet のプログラムの状態は「今いる色ブロック・DP・CC」の組で決まります。ブロックの数は有限なので、この組をノードとし、各ノードから次のノードへの遷移と、そのとき実行する命令を辺とするグラフ（制御フローグラフ）を作れます。`pointer` と `switch` は、スタックの値によって行き先が変わる「分岐」になります。こうして得たグラフは、普通の言語の `goto` と `switch` で書けるので、C や LLVM の中間表現に変換できる、というわけです。

## 20.6 Piet で遊ぶ

### クワインと Quine Relay

自分自身のソースコードを出力するプログラムを **クワイン**（quine）と呼びます。画像そのものがプログラムである Piet で、自分自身を出力するとはどういうことでしょうか。

遠藤侑介さんは、実行すると自分自身の GIF 画像のバイト列をそのまま出力する Piet のプログラムを作りました。2009 年 10 月 6 日に公開され、2026 年に再構成版が公開されています。npiet の `out(char)` が 1 バイトずつ出力する性質を利用した作品です。

遠藤さんはまた、非常に多くのプログラミング言語を順にたどって元のプログラムに戻る、クワインのリレー「Quine Relay」の作者でもあります。Piet もその中の 1 言語として登場し、`npiet QR.png` で実行されます。

### 俳句

Kelly Boothby は 2012 年、プログラミングのパズルとコードゴルフの Q&A サイト（Code Golf Stack Exchange）に、俳句を出力する Piet のプログラムを投稿しました。出力は「SPRING EVER RETURNS / NEVER EXACTLY THE SAME / THIS IS NOT A QUINE」で、その名のとおり厳密にはクワインではありません。

### パズルと Piet

Piet は、その見た目の不思議さから、パズルの題材としてもたびたび使われてきました。作者の一覧には、2002 年の MIT ミステリーハント、2005〜2006 年の Perplex City のパズルカード（234 番）、Guy Steele と Richard Gabriel の講演「50 in 50」、ジオキャッシングのキャッシュ、ゲームや雑誌への登場などが挙げられています。「ただのカラフルな抽象画」に見えるものが実はプログラムだった、という仕掛けは、パズルとして非常に魅力的です。

### Rosetta Code

さまざまな言語で同じ課題を解いて比べるサイト Rosetta Code には、Piet のカテゴリがあり、100 doors、99 bottles of beer、A+B、アッカーマン関数、整数の算術、2 進数表示、階乗、FizzBuzz、整数の列の 9 課題に Piet の解答が載っています。

## 20.7 Piet はチューリング完全か

Esolangs wiki は、スタックと整数が無制限であれば Piet はチューリング完全である、としています。その根拠として挙げられているのが、Piet で書かれた Brainfuck のインタプリタです。Brainfuck はチューリング完全であることが知られているので、それを Piet で解釈できれば、Piet も（無限のメモリを仮定すれば）同じ計算能力を持つことになります。

本書で学んだことからも、これは納得できます。

- `roll` は、計算で求めた任意の深さに値を出し入れできる。これは、スタックを「添字でアクセスできるメモリ」として使えることを意味する。
- `pointer` と白の配線で、条件分岐とループ（任意の制御フロー）を作れる。
- 整数は（仕様上は）いくらでも大きくできる。

実際の処理系では、整数の大きさ（npiet は C の `long`）やスタックの大きさに上限があるので、厳密な意味でのチューリング完全性は、ほかの多くの言語と同じく「理想化された」機械についての話です。

## まとめ

- Piet は David Morgan-Mar が設計し、画家モンドリアンにちなんで名付けられた。遅くとも 2002 年初めには存在し、仕様は 2008 年、2014 年、2017 年に加筆されている。
- 作者は権威ある処理系を定めておらず、処理系ごとに細部の解釈が異なる。npiet は事実上の標準として広く使われている。
- 処理系・開発環境は C、Perl、Python、Rust、Go、JavaScript など多くの言語で作られ、Piet を生成するコンパイラや、Piet を LLVM などに変換するコンパイラもある。
- クワイン、Quine Relay、俳句、パズルなど、Piet は遊び心のある作品の舞台にもなっている。
- 無制限のスタックと整数を仮定すれば、Piet はチューリング完全である。

## 練習問題

1. 公式のサンプル集から好きな作品を 1 つ選び、npiet と本書の piet.py の両方で実行して、出力を比べてください。入力が必要な作品では、どんな入力を与えればよいかをトレースから推測してみましょう。
2. 20.5 節の考え方に従って、[第19章](ch19.html)の `loop_fix`（9 から 2 ずつ減らして表示するループ）を、Python の `while` 文と `if` 文を使ったプログラムに手で「変換」してください。
3. 本書のテキスト格子と ascii-piet は、どちらも 1 コーデルを 1 文字で表しますが、文字の割り当てが違います。本書の形式を別の形式に変換するプログラムを書くとき、どんな対応表を用意すればよいか考えてください（ascii-piet の割り当ては、そのリポジトリで確かめましょう）。
4. 「チューリング完全である」ことは、実用上どんな意味を持つでしょうか。Piet でできないこと（あるいは非常に難しいこと）を 2 つ挙げ、それがチューリング完全性と矛盾しない理由を説明してください。
